# Lockdown Demo App Spec

**目标版本：v0.10.0**

**平台：Windows PC，键盘与鼠标，Unreal Engine 5.8.4**

本文定义首个可玩 Demo 的产品规则和验收要求，不是当前代码的完成声明。
开发方式见 [开发指南](DEVELOPMENT.md)，AI 协作约束见 [AGENTS](../AGENTS.md)。

## 1. 产品目标与范围

Lockdown 是一款采用 MOBA 操作和俯视斜角镜头的自由混战游戏。每位参赛者通过争夺野怪、击杀对手、升级选择和购买装备建立战斗优势，再把优势转化为对唯一占领点的控制。

**核心循环：探索与侦察 → 战斗获取经验和金币 → 选择成长、购买装备 → 判断继续发育还是争圈 → 独占圆圈获胜。**

击杀、金币和等级都是获胜手段，不是独立胜利条件。策略同时来自构筑、资源争夺、局部视野、进退时机与对占领点的控制，不以堆叠系统数量作为深度。

| 项目 | Demo 范围 |
| --- | --- |
| 对抗关系 | 所有参赛者各自为战；没有队伍或共享胜利 |
| 真人 | 最多 3 人，包含 Host 本人 |
| 对手 AI | 最多 3 个；与真人一样独立参赛，不是队友 |
| 总规模 | 最多 6 名参赛者；野怪不计入参赛人数 |
| 地图 | 一张地图，1 个占领点、5 组野怪、2 档野怪难度、1 个商店、10 个预设出生点 |
| 角色 | 所有人使用相同的基础角色，开局只有普攻；身份通过名称、头像和可辨识外观区分 |
| 成长 | 从 1 级到最高 10 级，每次升级获得一次三选一，最多选择 9 次 |
| 角色技能 | 最多 2 个主动技能槽；被动技能没有独立槽位上限；每个角色技能最高 3 级 |
| 装备 | 最多 2 件，没有额外背包；装备可提供属性、被动效果或主动技能 |
| 联机 | Host 同时作为玩家和 Listen Server；其他真人通过 IP 直连 |
| 表现目标 | 功能 Demo，可使用占位资源，但游戏状态、攻击、技能、视野、占点与 UI 必须清晰可辨 |

本文只定义这个 Demo。不设置跨局战力成长、长期世界模拟或后续版本路线图。

## 2. 对局流程与胜负

### 2.1 从菜单到结算

主菜单提供 **开始、设置、退出**。开始入口提供创建房间与通过 IP 加入房间。

房间展示参赛者名称、真人/AI 标识、Host 标识和准备状态。Host 设置 AI 数量；未使用的名额无需自动补满。所有已连接真人准备后，由 Host 开始。单人也可以创建房间进行练习，使用同一套玩法规则。

对局开始时，参赛者进入随机出生点，角色状态初始化，野怪生成，进入发育期。发育期内可以打野、战斗、升级和购物，但不能通过占领获胜。发育期结束后，占领点开放，并持续开放到本局结束。

占领成功后立即锁定唯一胜者，停止继续结算战斗、奖励、购物和占领。结果页面展示胜者和本局基本结果；Host 可以带房间返回 Lobby 开始新局，玩家也可以离开房间返回主菜单。

### 2.2 唯一胜利条件

占领点开放后，**一名有效参赛者连续独占圆圈达到规定时长，即获胜**。进入圆圈自动开始判定，无需交互键、站桩读条、钥匙、门票或其他前置任务。

有效参赛者是仍在本局、存活且不处于复活保护状态的真人或对手 AI。死亡角色、野怪、商店以及技能视觉效果不计入占领人数。

| 圆圈状态 | 计时规则 |
| --- | --- |
| 尚未开放 | 不计时，显示距离开放的进度或剩余时间 |
| 没有有效参赛者 | 无占领者，进度清零 |
| 只有一名有效参赛者 | 为该参赛者连续计时 |
| 多名有效参赛者 | 显示争夺中，所有占领进度清零 |
| 占领者离圈、死亡或离开本局 | 其进度清零；下一名独占者从头开始 |
| 连续独占达到规定时长 | 立即判定该参赛者获胜 |

圈内可以移动、普攻、释放技能和使用装备主动。**单纯受到伤害、受到控制或进行战斗不重置计时**；如果因此被击退、走出圆圈或死亡，则按离圈或死亡处理。

争夺结束后，即使仍是之前的占领者，也必须重新完成整段连续计时，不保留累计进度。复活保护者不能推进或打断占领，避免利用无敌状态争圈。

占点开始、争夺、清零与获胜必须有清楚反馈。占领点开放状态、当前占领者及进度属于全场公开信息，不受战争迷雾遮蔽。人数与边界判定以服务器上的实际位置为准，不依赖客户端画面或个人视野。

达到完成时刻时，必须仍然满足连续独占条件。同一结算时刻已发生的争夺、离圈或死亡不能被跳过；服务器只能提交一次最终结果。

没有击杀数、财富、等级或超时积分胜利；无人占领成功时，对局继续，或由 Host 主动结束而不产生胜者。

## 3. 操作与战斗

### 3.1 MOBA 操作

操作参考 Dota / League of Legends 的通用交互，不照搬其英雄、技能、美术或音效内容。

| 输入 | 行为 |
| --- | --- |
| 右键地面 | 点击寻路移动，绕开不可行走区域 |
| 右键可攻击目标 | 沿合法路径接近攻击距离并持续普攻；只能对当前可见目标发出新的目标锁定 |
| 右键商店 | 接近商店，在交互距离内打开商店页面 |
| 左键 | 选择查看目标，或确认已准备的技能目标/地面位置 |
| A + 左键 | 攻击移动 |
| S | 停止移动、追击及可中断动作 |
| Q / W | 使用对应角色主动技能 |
| 1 / 2 | 使用对应装备的主动技能；没有主动效果时显示为不可用 |
| P | 打开或关闭自身属性面板 |
| 屏幕边缘、方向键 | 平移镜头 |
| 空格 | 镜头回到自身角色 |
| 镜头跟随开关、鼠标滚轮 | 切换跟随，或在允许范围内缩放 |
| Esc | 优先取消当前选定动作或关闭最上层面板，否则打开设置/退出菜单 |

使用固定俯视斜角镜头，不要求自由旋转镜头。输入绑定允许修改并保存；镜头速度、边缘平移与跟随偏好属于本地设置。

技能可采用指向单位、指向地面、方向或自身释放等目标形式，由技能内容定义。释放前显示有效目标、范围或方向；无效输入不消耗资源，并反馈失败原因。

点击 UI 不得同时向世界发送移动、攻击或施法命令。打开面板、选择升级奖励和修改设置都不暂停联机对局，也不赋予角色无敌。

### 3.2 属性模型

角色采用 MOBA 式战斗属性。下表固定属性含义，不包含数值和计算公式。

| 属性 | 作用 |
| --- | --- |
| 物理攻击力 | 决定普攻及具有物理攻击加成的技能效果 |
| 法术强度 | 决定具有法术加成的技能效果；不默认让普攻变成魔法伤害 |
| 护甲 | 影响承受的物理伤害 |
| 魔法抗性 | 影响承受的魔法伤害 |
| 攻击速度 | 影响普攻频率 |
| 移动速度 | 影响行走与追击速度 |
| 攻击距离 | 影响普攻的有效距离，不等同于所有技能的施法距离 |
| 生命值、最大生命值 | 表示存活资源与上限 |
| 法力值、最大法力值 | 表示技能资源与上限 |
| 生命回复、法力回复 | 决定相应资源的自然恢复 |
| 暴击率 | 影响允许暴击的攻击；不是所有技能自动获得暴击能力 |
| 冷却属性 | 影响适用主动技能的再次使用时间；面板与技能图标反映真实效果 |

普攻默认造成物理伤害；技能与装备明确标记伤害类型、属性加成、法力消耗、冷却和作用方式。属性面板应能解释基础值、成长与装备/状态带来的加成，不能只显示没有实际效果的字段。

前摇、命中、伤害、控制、死亡及恢复使用一致的战斗规则。控制效果需要明确说明禁止的是移动、攻击还是施法，并在角色与 HUD 上可辨识。

战斗效果、持续时间、距离、属性上下限和换算公式不在本规格中预设。

## 4. 经验、金币与三选一成长

### 4.1 奖励与升级

击杀野怪或其他参赛者获得经验和金币。**两种奖励全部归完成最后一击的参赛者**，不设置助攻奖励、附近经验分摊或按伤害贡献结算。

技能、装备效果或持续伤害造成的击杀也归属于其实际所有者。同一次死亡只能发放一次奖励；没有参赛者拥有该次致死伤害时，不凭空指定奖励获得者。

金币用于商店购买装备；经验用于升级。不开设任务、采集、制作、银行或玩家交易等额外经济循环。

### 4.2 三选一

每次从当前等级升到下一级，获得一次选择机会。每次展示三个不同且当前可合法选择的选项，从中选择一个：

| 选项类别 | 结果 |
| --- | --- |
| 新主动技能 | 学习该技能，从 1 级开始，并装入角色主动技能槽 |
| 新被动技能 | 学习该技能，从 1 级开始，按条件自动生效 |
| 已学技能升级 | 将已有的主动或被动技能提升一级，最高 3 级 |
| 角色属性提升 | 获得本局持续生效的属性加成 |

三张卡不要求分别来自不同类别。新技能候选只包含当前未学会的技能；已学技能只能作为升级候选，满级后不再出现。每组选项都必须可兑现，属性选项可用于补足合法候选，但不得悄悄改变玩家选中的内容。

被动技能没有额外槽位上限，但仍受本局实际获得的选择机会和技能最高等级约束。装备被动不算一次角色学习，随对应装备生效或移除。

连升多级时，选择机会排队，逐次处理；前一次选择生效后再生成下一组候选，避免出现已经失效的升级选项。每组候选由服务器生成并保留，关闭页面、死亡或重复请求不能重新抽取。

选择页面可以暂时关闭，未使用的选择机会继续保留。选择本身不暂停世界，不强制替玩家自动选择，也不设置免费的重抽机制。

达到 10 级后不再升级或新增选择机会，但仍可处理本局已经获得、尚未使用的选择。

### 4.3 两个主动技能槽

角色主动技能只使用 Q/W 两个槽。空槽时可以直接学习；两个槽已满时，学习新主动必须明确选择要替换的旧技能，并确认后才消耗本次选择机会。

**被替换的主动技能及其等级会被遗忘**，不进入备用技能库、不返还已投入的选择。将来再次获得时，从 1 级重新学习。

装备主动使用 1/2，不占 Q/W。因此，角色最多同时有两个角色主动入口和两个装备主动入口；不是所有来源共用两个按钮。

升级、槽位调整或资源买卖不能成为重置尚未结束冷却的捷径。技能与装备能力要按其实际来源管理，不能因为图标换了位置就恢复可用。

## 5. 装备与商店

每名参赛者最多持有并装备两件装备，没有额外背包。**两个装备槽允许同时装备两件相同装备。** 装备可以只有属性，也可以带被动效果或一个主动入口。装备能力来自装备本身，不通过角色三选一提升等级。

允许装备两件同款，不代表同名被动可以叠加，也不代表两份主动冷却彼此独立。
这两项效果/来源规则仍需分别明确，不能从持有合法性推导。

商店是地图中的固定交互对象，本体不可攻击。**商店周围不是安全区**；浏览、买卖期间仍可能受到攻击。

商店页面显示当前金币、两个装备槽、商品价格、属性与效果说明，以及明确的购买和出售操作。必须有“金币不足”“装备槽已满”“不在范围内”等可理解的失败反馈。

购买要求角色存活、对局进行中且处于交互范围内。槽位已满时，先在商店卖出旧装备，再买入新装备，不自动销毁或替换玩家的物品。卖出会移除对应属性与能力，并按出售规则返还金币。

离开交互范围或死亡后不能继续交易；交易只在服务器确认成功后变更金币与装备。重复点击、延迟回包或重复请求不得造成重复购买、重复出售或额外金币。

装备目录必须覆盖属性加成、主动效果和被动效果，并支持有取舍的战斗构筑。不要求制作合成树、消耗品、商店刷新、稀有度抽奖或庞大装备目录。

## 6. 地图、野怪与视野

### 6.1 地图组成

地图需要清楚区分可自由行走区域与阻挡行走的地形。出生点、野怪营地、商店和占领点之间必须存在合法路径；寻路不能依赖穿墙或瞬移。

占领点要有可辨识边界和接近路线，不能通过不可行走地形从外部计入占领。障碍布局需要支持绕行、追击、撤退与视野取舍，不以巨大面积或大量装饰性地点作为目标。

10 个出生点是预先布置的合法落点。开局出生和每次复活都从这同一组点中完全随机选择，各点被抽中的机会相同，不按敌人距离、视野、危险程度或胜率筛选，也不优先沿用本人的初始点。允许再次抽到同一点。

若多个角色同时落在同一点，只进行必要的合法落地、防重叠处理，不借机重新选择“更安全”的出生点。

### 6.2 野怪

地图固定设置五组野怪，覆盖两档难度。具体分配、每组数量、能力与收益交由 Demo 内容和数值设计确定。

野怪不是对手 AI 参赛者，不购买装备、不选择成长、不能占点获胜。它们具有可识别的生命与战斗行为；受攻击后反击或追击，超出营地活动范围或失去目标后返回并重置，避免被永久拖离营地。

营地被清空后进入刷新等待，随后重新生成该组野怪。每个野怪生命的死亡与奖励独立且只结算一次；回位重置不等于死亡，不能发放奖励。

基础角色只靠普攻就必须能够开始低难度打野和首次升级。高难度营地应体现更高风险与成长价值，不能只是外观不同。

### 6.3 局部视野与战争迷雾

每位参赛者只有自己的局部视野，真人和对手 AI 遵守同样规则。地图地形、固定营地、商店和占领点位置可以公开；隐藏单位的位置、当前行为和资源状态不能持续透过迷雾更新。

离开视野的敌人不再提供实时位置，不能通过镜头平移、选择面板、小地图、寻路目标或 AI 决策绕过限制。地形的“阻挡行走”与“阻挡视线”需明确区分。

小地图展示自身位置、固定地点、视野覆盖及当前合法可见的单位。占领状态与全场击杀通知是明确的公共信息例外，但不能附带无关的隐藏位置或构筑数据。

侦察和藏匿主要来自移动、障碍与视野。Demo 不要求隐身系统、插眼道具、昼夜循环或可破坏地形。

## 7. 死亡、复活与对手 AI

### 7.1 死亡与复活

死亡后角色退出战斗和占领判定，显示死亡状态与复活等待。等待结束后，从随机出生点以完整生命值、法力值复活，清除死亡前的临时控制状态。

**死亡只损失等待时间和场上位置。等级、经验、技能、装备、金币及未处理的升级选择全部保留。** 不掉装备，不扣金币，不重新发放成长或初始奖励；已有冷却按时间继续，不因死亡自动刷新。

复活后有短暂保护，不受伤害和控制；主动攻击、施法或使用装备主动时，必须先解除保护，再执行动作。保护期间可以移动，但不能推进或干扰占领。保护状态和剩余时间必须可辨识。

### 7.2 对手 AI

对手 AI 是可独立获胜的参赛者，而不是站立靶子或只会巡逻的 NPC。至少能够自主完成：

- 找到适合当前战力的营地，打野获得经验和金币。
- 处理升级三选一，使用所选主动、被动和属性构筑。
- 前往商店购买装备，必要时出售并更换装备，使用装备主动。
- 与真人或其他 AI 战斗，根据局势追击、撤退和恢复。
- 在占点开放后争取独占，发现公开占领进度时尝试阻止对手。
- 死亡等待、随机复活并继续对局。

AI 使用同一套属性、奖励、经济、技能槽、死亡和胜利规则。它可以读取自身状态、合法视野和公共占领信息，但不得直接获取迷雾中的敌人位置、免费生成资源或绕过商店与施法条件。

Demo 只要求一种可完成核心循环的 AI，不要求机器学习、多档难度或模拟人类社交。

## 8. 游戏界面与反馈

| 界面 | 必须包含 |
| --- | --- |
| 主菜单 | 开始、设置、退出、产品版本 |
| 建房/加入 | 玩家名称、Host/加入入口、IP 与端口输入、连接中和失败反馈 |
| Lobby | 真人与 AI 名单、Host 标识、准备状态、AI 数量、开始与离开 |
| 战斗 HUD | 自身头像、名称、血量、蓝条、经验、等级、金币；Q/W；两个装备槽及 1/2 主动入口；被动效果；当前状态 |
| 占领提示 | 发育期/已开放/争夺中/独占状态，当前占领者和进度 |
| 小地图 | 固定地点、自身位置、战争迷雾及合法可见单位 |
| 三选一 | 三张候选、效果与等级说明、选择确认、主动技能替换流程、待选次数 |
| 属性面板 | 完整自身属性、当前加成与相关说明 |
| 商店页面 | 商品、说明、价格、当前金币与装备、购买/出售、失败原因 |
| 全场击杀通知 | 击杀者、被击杀参赛者及可理解的死亡原因；普通打野不刷全场击杀横幅 |
| 死亡界面 | 死亡状态、复活倒计时、保留的构筑和待选奖励 |
| 设置菜单 | 显示/画质、音量、按键和镜头设置、恢复默认；对局中还包含继续与离开 |
| 结算 | 唯一胜者、对局结束原因、返回 Lobby 或主菜单 |

技能和装备图标需要显示真实的冷却、资源不足、无效目标、未装备及受控制限制。被动与临时状态要区分；被动数量增长时可以展开或滚动，不能因 UI 格子用尽而增加隐含玩法上限。

关键状态不能只依靠颜色区分。占领、死亡、受击、技能释放与购买结果需要明确的视觉反馈，关键全场事件应有简洁音效或提示。占位素材不能妨碍辨认敌我、自身、野怪与交互对象。

## 9. 联机与数据边界

采用 Unreal Listen Server：Host 一边运行权威世界，一边作为一名普通参赛者游玩；最多另有两名真人客户端连接。对手 AI 和野怪由 Host 驱动。

IP 直连验收覆盖局域网，以及正确配置防火墙、端口映射后可到达的公网地址。**不承诺家庭网络之间免配置连接，不实现自动 NAT 穿透或中继。**

移动合法性、伤害、经验、金币、三选一候选、装备交易、随机出生、复活和胜负均由服务器裁定。客户端可以立即表现操作意图，但不能自行确认购买、奖励或胜利。

计时以服务器为准，客户端显示同步后的状态。对手 AI 与真人使用相同的权威玩法接口，视野展示不得泄露只属于服务器或其他玩家的私有数据。

对局开始后锁定参赛名单。Demo 不提供中途加入、断线重连或 Host 迁移；普通客户端断线视为离开本局，其他参赛者继续按占领规则游玩，不因人数减少自动获胜。离开连接本身不算一次击杀。

Host 离开或连接丢失导致会话结束时，客户端返回菜单并显示原因，而不是停留在失效的世界中。需要清楚区分房间已满、对局已开始、版本不兼容、地址不可达等失败。

所有战力与经济数据仅属于本局。新局重新初始化角色、选择、装备、金币、经验、冷却、野怪与占领状态；本地名称及设置可以保存。

## 10. 内容与数值设计边界

**本规格只固定会议给出的结构数量，不填写平衡数值，也不给“临时默认值”。**

| 本规格已固定 | 需要针对同一个 Demo 专门设计 |
| --- | --- |
| 人数、地图对象数量、等级上限、选择次数、技能与装备槽位、技能等级上限 | 发育期、独占、复活、保护、野怪刷新等时长 |
| 奖励归属、死亡保留、技能遗忘、商店买卖和占领打断规则 | 初始资源、经验曲线、击杀与打野收益、商品价格和出售回报 |
| 属性类别、主动/被动来源与视野规则 | 属性基值、等级成长、伤害与减伤、暴击、回复、冷却等计算 |
| 地图包含的功能地点和可通行/视野要求 | 地图尺度、圆圈大小、射程、移速、视野、野怪追击范围 |
| 三选一类别与合法性 | 具体技能与装备目录、各级效果、随机权重、叠加与触发规则 |

数值设计必须检验：基础角色可以开始发育；升级和装备确实能形成优势；高难度营地有合理风险收益；从地图各区回防有实际可能；控制、复活和保护不能让占点永久无法完成；不存在稳定的买卖套利或无限奖励循环。

最终内容只需足以展示不同战斗选择及主动、被动、升级、属性、装备之间的取舍，不因“完善目录”扩大 Demo。技能、装备和野怪的具体内容仍需针对本 Demo 选定，不能把属性或槽位框架本身当作完整可玩内容。

数值方案确定前，不把占领时长、属性或售价写死为产品事实；技术占位数据也不代表已批准的平衡方案。

## 11. Demo 完成标准

| 验收场景 | 必须达到的结果 |
| --- | --- |
| 正常启动 | 从主菜单进入 Lobby，经准备与开始进入对局；设置和退出有效 |
| 满规模联机 | 3 名真人与 3 个对手 AI 在同一局独立参赛，未占用名额不产生额外角色 |
| 地图与寻路 | 唯一占领点、五组两档野怪、唯一商店和十个合法随机出生点齐备；路径遵守地形阻挡 |
| 从零发育 | 基础角色依靠正常普攻打野获得经验与金币，完成升级选择和商店购买 |
| 成长边界 | 最高 10 级、最多 9 次三选一；每个技能不超过 3 级；连升多级和延迟选择不丢失、不重复 |
| 技能替换 | Q/W 不超过两个；满槽学习明确替换，旧技能及等级被遗忘，再次学习从 1 级开始 |
| 装备边界 | 不超过两件装备，允许两件同款，无额外背包；属性、被动、1/2 主动按明确的效果/来源规则真实生效；满槽可先卖后买 |
| 奖励与死亡 | 最后一击独占经验与金币，一次死亡只奖励一次；死亡后成长与财产保留，等待后随机复活 |

| 视野一致 | 隐藏单位不会通过画面、面板、小地图或 AI 决策泄露；公共占领与击杀信息正常传达 |
| AI 可玩 | AI 能自主发育、选奖励、购物、战斗、复活和争圈，并能通过同一条件获胜 |
| UI 完整 | 头像、名称、血蓝、经验等级、金币、技能、装备、被动、状态、商店、属性、设置、击杀通知和结算可理解且可操作 |
| 网络失败 | 超员、开局后加入、地址或版本失败有明确反馈；Host 退出不会使客户端卡在无效对局 |
| 新局隔离 | 返回 Lobby 再开局后，对局数据完全重新初始化，只保留明确允许的本地设置 |
| 正常完整对局 | 不依赖调试授予、传送或强制判胜，能完成发育、对抗、抢点、获胜和结算的闭环 |

验收时使用已批准的实际数值验证时长、边界、资源与效果，不能以“有这段代码”“有按钮”或“有动画”代替规则成立。
