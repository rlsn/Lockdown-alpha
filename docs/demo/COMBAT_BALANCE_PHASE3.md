## A. 可靠性报告

### A1. 严格重放：诊断与修复

**代码事实＋原生对局。** Phase 2 的跨进程重放 `RuleViolation` 有两个独立原因。

**原因 1：进程级 generation 计数。**

- 在多 Case 进程中，第 N 场的 `generation=N`；单 Case 重放时它是 1。它是编辑器进程内的比赛序号，与对局内容无关。
- 修复：只把**本 Case 自己的** generation 规范为 `generation=case`。其他 generation 值仍原样比较。

**原因 2：同刻独立准备事件。**

- 同一服务器时刻，双方各自的 `LD_OFFER`、`LD_CHOICE`、`LD_BUILD` 由引擎按不同顺序记录。
- `LD_OFFER` 的抽取种子是 `OfferSeed(MatchSecret, ContenderId, Ordinal)`（见 `LDDevelopmentDirector.cpp` 的 `DrawHead`），只取决于该参赛者自身的状态。
- 这些事件分属不同主体，彼此没有因果关系，且只发生在成长准备阶段。
- 修复：`canonical_events` 只对“**同一时刻、连续出现的准备事件**”按参赛者角色分组排列。
  - 同一参赛者内部保持原序。
  - 任何其他事件都会结束这一段。
  - 命中、击杀、状态、资源和跨时刻顺序**不会**被重排。

回归测试（`Scripts\TestBuildEvaluationLockdown.py`）：

| 测试 | 方向 |
|---|---|
| `test_canonical_events_accept_engine_order_of_independent_same_tick_preparation` | 正例：同刻两主体的准备事件互换，或本 Case generation 不同时，判为相等。去掉 `LD_OFFER` 后该测试会失败（已验证）。 |
| `test_canonical_events_keep_every_causal_or_cross_tick_order` | 反例：以下情况**仍判不等**：同主体内顺序互换；跨时刻互换；同刻互换中夹有战斗事件；陌生 generation。 |

### A3. C08 多根归属与 C11 预算

**原生受控，新增并通过。** 两项测试都在持有者的 S06 上装 C11，再在 C11 上装 C08。

**`Lockdown.Rules.Combat.Events.CounterMergedRootsFireOnce`**

- 两次独立的 S06 命中，各自拥有完整的 C11 30G 预算。
- 每次实际治疗的一半进入同一个 C08 储量（1500→3000），身份取**后到的根**。
- 发射窗口只产生一次反击，基数为合并后的 3000，带后到根的 EffectId。
- 发射后储量和根身份清零，不会重复发射。

**`Lockdown.Rules.Combat.Events.SkillLifestealBudgetConsumed`**

- 一次 S06 的 8% 实际掉血治疗被封顶为 30G。
- 同一动作的派生命中不再治疗，也不再为储量充能。
- C08 反击真实伤害对手，但不消耗 C11 预算、不治疗、不回填储量。

两项都已加入 `Scripts\CheckRuleReport.py` 的 `REQUIRED_TESTS`。“后到根为准”还是按份额拆分归属，仍**待用户决定**（§E3）。

## B. 战斗生态矩阵

### B1. 场景与构筑

**地图与对局形式（原生对局）。**

- 真实 `L_Demo` 的 `duel_site`，场地参数 `site=capture`。
- 场地中心是地图中央的占点 POI (0,0)（`SourceData\World\demo_world.json:5038`）。
- 双方先走到中心，约 15 s 首次交手。
- 权威身体、移动、视野与授权规则；1v1；60 FPS。

**构筑。** 两方都按批准规则获得固定主动；构件只抽取、**不安装**。

| | 主体（法师） | 对手（普攻） |
|---|---|---|
| 主动 | S01 肘击、S06 甩你一鞋、S18 板砖糊脸（L3 只有 S01、S06） | S01、S17 三连击、S03 掏蛋子（L3 只有 S01、S17） |
| 属性 | 全部点脑力：L3 9、L6 18、L10 30、L16 48 | 力道 : 身手 = 26 : 4 按点数缩放：L3 8:1、L6 16:2、L16 42:6 |
| 策略 | 下表的五种立场之一 | 生产 Engage：走入并普攻，**从不使用 D 冲刺** |

**统计方法。**

- 每个种子在两个出生侧各跑一次，取均值。
- 区间为 Student-t 95% 近似。
- 只要一个种子含无效 Case，就整组排除。
- `duel_score`：胜 +1、负 −1、互杀或超时 0。
- 没有批准的胜率或伤害目标，所以只报告差异，**不判定达标**。

**指标定义。**

| 指标 | 定义 |
|---|---|
| 距离 | 首次互有命中之后、双方都存活时的心跳平均距离 |
| `zin` | 同一时段内，处于场地中心 600 cm 内的心跳比例 |
| 技能占比 | 主体命中中，来自 Q/W/E 的比例 |
| MP | 心跳中 MP 的平均占比 |
| 控制 | 带控制的命中占比 |

**判断（设计判断，有原生依据）。** “普攻强、法师弱”的观察，在本 Harness 中主要是**接战距离问题**。法师若在近战距离内对拼，就输给普攻；若管理好距离，中后期就能赢下对决。但这份优势有三个前提，一旦不成立就会被削弱：

- 对手**从不使用 D 冲刺**，也没有冲撞。
- 场地是开阔地，没有掩体。
- 远程方愿意离开目标区域。

因此，现有证据**不支持**“普攻流全局占优”或“法师全局偏弱”。它真正指出的是三个结构问题：

- 远程方必须在场地控制与对决胜负之间二选一。
- 没有位移时防守毫无作用。
- 早期法师缺少足够的技能入口。
