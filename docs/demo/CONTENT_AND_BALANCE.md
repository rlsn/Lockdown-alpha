### 1.1 参数权威与模块接口

本文是已批准首轮内容和玩法参数的唯一值来源。世界模块维护地图坐标、路径、通道、遮挡和
查询契约，引用本文的参数 ID，不维护另一份可独立改动的数值表。
地图上的直线距离不代替合法最短路径；离线几何模型不代替 Unreal 导航和真实拥有客户端验收。

| 接口 ID | 责任边界 |
| --- | --- |
| `UNIT.MoveSpeedCmPerSec`、`UNIT.CollisionRadiusCm`、`UNIT.BasicAttackRangeCm` | 内容模块定单位与建议值，世界模块验证通道和接近几何 |
| `VISION.RadiusCm`、`SHOP.InteractRadiusCm` | 内容模块定半径；世界与视野模块验证遮挡、权限和交互可达 |
| `CAPTURE.RadiusCm`、`CAPTURE.SpraySec`、`CAPTURE.GuardSec`、`MATCH.DevelopmentSec` | 内容模块定尺度与节奏；比赛模块实现 Spec 的同刻结算和唯一胜者 |
| `LIFE.RespawnSec`、`LIFE.ProtectionSec` | 内容模块定时长；生命与权威模块维持时间、免疫、保留和重开隔离 |
| `CAMP.Low.*`、`CAMP.High.*` | 内容模块定构成、强度、收益、刷新、追击与重置；世界模块配置五个稳定营地锚点 |

所有世界距离建议统一为单层地面脚点的 XY 厘米距离。普攻距离是攻击者中心至目标中心；
商店交互距离是角色中心至固定交互锚点；两者都不再加减双方碰撞半径。
喷漆区按脚点中心在半径以内判定，边界含等号，不要求整只胶囊进入才计数。
碰撞半径单独用于通道净空、接近点生成和同点防重叠，不能在距离公式中重复计算。
这些查询语义须与世界模块的正式接口一致。

回防路径终点是可达的有效喷漆区边，不是旗杆中心；购物路径终点是可达的交互区域边界，
不是可能被阻挡的商店本体中心。商店交互半径内如果没有合法接近点，必须拒绝该布局，
不能扩大服务器接受距离、穿墙或传送以使样例通过。

### 1.2 实施验证的共同边界

离线检查只证明其列出的代数、离散时序和模型假设。下列场景仍必须通过实际运行验证，

| 验证主题 | 必须观察的结果 |
| --- | --- |

| 联机与 AI | Host、真正拥有连接的客户端和对手 AI 使用同一合法命令、视野、经济和获胜规则 |

## 2. 首轮方案与决策状态

首版采用 **1 基础角色、3 角色主动、3 角色被动、5 属性奖励、7 装备、2 野怪定义**。
三个主动刚好允许演示两个槽满后的替换；三个被动覆盖持续属性与条件回复；
五种属性卡提供不依赖技能/装备的持续增益，其中射程卡落实用户确认的普攻成长；
七件装备覆盖物攻、物防、法强/冷却、伤害回复、位移、资源与普攻群攻。
本节首轮池没有合成、消耗品、免死、反射、地表反应或额外职业。
反伤仅按 §15 的已批准扩展方向在核心 Demo 跑通后分批接入，不提前改变本池。

下列已批准内容是一个方案，不是两个可同时运行的模式。后续审查改变基础行为时，应重新计算受影响的
目录/模型并修订本报告，不把旧候选继续留在运行配置。

| 决策 | 状态 | 本报告采用的建议语义 |
| --- | --- | --- |
| CB-P01 普攻形态与成长 | **用户已确认**“所有人初始都是近战单体普通，群攻/攻击距离可以通过装备或者属性增加”；具体首轮方案于2026-11-02批准 | 初始近战单体，按本文幅度/横扫形式实现射程卡与自拍杆，不引入追踪普攻弹体 |

## 3. 单位、参数与公式

### 3.1 统一表示与失败语义

| 类型简称 | 作者表示/单位 | 原生建议与取整边界 |
| --- | --- | --- |
| P2 | 至多两位小数的资源/属性点 | 精确解析为 int64 百分之一点；当前 HP/MP 只在原有战斗状态中有一份真值 |
| R4 | 至多四位小数的无量纲比例/倍率 | 精确 basis points；概率与倍率是不同字段，倍率允许大于 1 |
| Rate | 次/秒、点/秒、cm/s，字段逐项注明 | 保留精确有理/足够精度中间结果；周期和资源提交最后才取整 |
| Sec | 非负、至多三位小数的秒 | 作者秒数必须可精确转换为整毫秒；不悄悄截去小数。派生 CD/间隔向上整毫秒 |
| Count | 等级、数量、XP、金币的整数 | bool 不是整数；运行累计 XP/金币用有界 int64，乘加预检溢出 |
| Cm | 单层脚点 XY 厘米 | 参数有限且非负；实际位置/路径由世界正式查询提供，不另建内容网格 |

所有范围、分母、精度和有限性先验证。非法输入整次拒绝，保持旧有效状态与产物，不用 Clamp
掩盖 NaN、溢出或缺少字段。#112 起表内每项属性的上下限是投影的夹取界（用户 2026-11-05 批准 R6）：
构筑投影把每项属性统一夹到 `STAT.<属性>.Min/Max`，不再因可重复属性卡、装备与进阶的极端组合拒绝整个构筑；
上下限数值不变，内容验证只检查伤害与护盾项在极值属性下不溢出 int64。AS/MS/概率的玩法夹取另外显式定义。
同一次属性变更只投影最终来源集合一次，UI 的格式化不回写结算。

### 3.3 可实施公式表

| 公式 ID | 输入 → 输出/顺序 | 范围、取整与样例 |
| --- | --- | --- |
| `FORMULA.StatProjection` | base + level + 属性卡 + 角色被动 + 装备 + 临时来源的 flat 先相加；同类 percent 相加后乘一次 | 先校验来源/族，再最终投影，不逐装备取整/封顶；相同来源集合换显示槽结果不变 |
| `FORMULA.Resistance` | 原始物理/魔法伤害 $D$ 与对应抗性点 $R$ → $D\times100/(100+R)$ | $R\in[0,200]$；R=0 不减伤，R=100 减半；不实现未被目录使用的负抗/穿透分支 |
| `FORMULA.Crit` | 仅合法普攻主击在唯一 AttackId 取一次随机值 $u\in[0,1)$；$u<p$ 时主击原始 AD 乘 2 | 服务器独立确定性随机流；重发同 AttackId 不重抽；副击、技能、吸血治疗不可暴击 |
| `FORMULA.Damage` | source 快照原始量 → 适用暴击 → 目标实时抗性 → 向下取 0.01 → 现有屏障吸收 → 实际 HP 损失 | HP 损失不超过目标剩余 HP；70 对 18 抗=59.32，140 对 18 抗=118.64；0.009 对零抗=0，不设最低 1 点伤害 |
| `FORMULA.AttackSpeed` | $0.90\times(1+0.02k+\Sigma ASBonus)$ → AS | 最后夹取到 [0.30,2.50] 次/秒；本目录实际可达 [0.90,1.422] |
| `FORMULA.MoveSpeed` | $UNIT.MoveSpeedCmPerSec\times(1+\Sigma MoveSpeedBonusRatio)$ | 最后夹取[173,675]cm/s；本目录[300,372]，不把Root动作禁止当减速属性 |
| `FORMULA.AttackRange` | 基础 `UNIT.BasicAttackRangeCm` + 永久/装备 `AttackRangeCmFlat` → `STAT.AttackRangeCm` | 无乘区；十次卡+两自拍杆=220+10×40+2×40=700cm；目标/导航接近/预览/AttackMove全用派生值 |
| `FORMULA.AttackIntervalMs` | $\lceil1000/AS\rceil$ → 相邻合法 AttackStart 的最短间隔 | AS=.90 得 1112ms；发出新 order、S 取消、换装备、死亡均不清已提交攻击端点 |
| `FORMULA.AttackWindupMs` | $\lceil1000\times UNIT.BasicAttackWindupSec\times STAT.BaseAttackSpeed/AS\rceil$ | 基础 250ms；必须小于本次攻击间隔。前摇可以取消/因失去权限失败，但不退款已提交节拍 |
| `FORMULA.CooldownMs` | $\lceil1000\times BaseCDSec\times100/(100+H)\rceil$ → 本次释放持续时间 | H 非负；6s、H=30 得 4616ms。10s 释放得到 ReadyAt=14.616s，随后卸装/升级不改这个端点 |
| `FORMULA.Regen` | rate × 同一权威时间的实际 elapsed + 亚P2积分余数 → 可提交的0.01点及新余数 | 见 `POLICY.RegenIntegration`；活体才恢复，满资源丢弃溢出。1.6/s 分1000次1ms仍回复1.60 |
| `FORMULA.ResourceMaxChange` | 以P2整数计算 $\lfloor oldCurrent\times finalNewMax/oldMax\rfloor$ | 用户要求保持比例，最终一次向下量化；40/100→150为60→30为12→150为60→100回40；零上限/活HP下溢见§10.3 |
| `FORMULA.SellGold` | $\lfloor PurchasePrice\times SHOP.SellRatio\rfloor$ | 全部固定价、无折扣；310×.65=201，不是202。整数溢出整笔拒绝 |
| `FORMULA.XPToNext` | $80+20(L-1)$，仅 $L=1..9$ | 正整数；达到十级不再调用生成机会。采用可手算线性增量，不依赖任意公式字串执行器 |

普攻节拍从通过初始合法性检查的 AttackStart 提交；技能则在成功 release 才提交
MP/CD。前摇内复查目标/来源，导航不负责扣费或退节拍。基础普攻命中前失效是一次已开始的
挥空，不是把非法最初输入当作成功攻击。最初动作输入被拒绝时不提交攻击节拍、费用或攻击效果，
但已认证进攻意图的解除保护仍按§10.2生效；不能把“失败无费用”写成“任何状态都不变化”。
前摇中的构筑/来源变更取消该暂存攻击，不能把两个修订的属性拼起来。

派生时长向上取毫秒之后，新截止时间还须从原始实际释放时刻安全建立：
`ReadyAtMs = ceil(OccurredAtSeconds × 1000) + DurationMs`，不能先floor起点而提前到期。
例如1000.8ms开始、持续1ms，截止为1002ms；1001.9ms时还不能使用。
`OccurredAtMs`若是ceil桶，只用于分桶；真正先后仍按原始OccurredAtSeconds及同刻因果顺序。
Ready比较用原始时间或安全的floor当前毫秒，不能用ceil当前桶提早开放。唯一时钟/Stamp由生命周期域维护。

### 6.1 经验与击杀

`XP.Start=0`，`XP.MaxLevel=10`、`CHOICE.MaxCount=10` 是 Spec 固定值
（`content.json` 的 `progression.xp_start / max_level / max_choices`，另有 `max_skill_rank=3`、`active_slots=2`、`equipment_slots=2`）。

| 该级到下级 XP | 80 | 100 | 120 | 140 | 160 | 180 | 200 | 220 | 240 | 不再升级 |

比赛开始时（成长 `BeginMatch`，即 Progression 提供者 Prepare，早于发育期开放）每名参赛者（真人与 AI）获得 1 号机会并固定其首张三选一；

1 号机会（开局）的三张卡按 `progression.opening_offer` 组成（#112，用户 2026-11-05 确认）：从可进卡池（`draftable`）的未学主动中
等概率不重复抽 `active_count=2` 个，再从可进卡池的未学被动中等概率抽 `passive_count=1` 个，三张位置随机；
按种类与 `draftable` 筛选，不写死列表。两组任一不足时 `BeginMatch` 明确拒绝，不借用组外卡补足。之后各次机会按 §15.6 的
卡位与权重抽取（`LDProgression::DrawOffer`）。DEV 成长夹具的预设报价是确定性覆盖，仍可为开局指定任意合法卡。
导入器要求两数之和为 3、各组数量不超过可进卡池的技能数；`reroll_levels` 严格递增且在 2–10 级之间。
升十级以后继续记录合法奖励的累计XP，但不能生成第十一次选择。
累计存储有界int64，溢出在整个奖励计划提交前明确拒绝，不静默饱和、不转金币；UI十级显示MAX而非暗示11级。
野怪奖励全部归最后一击，表中“每人平均”只能用于供给估计，不是实现经验分摊。
参赛者之间的击杀按 App Spec §4.1 的助攻规则（#112，参考 LoL）在同一笔死亡奖励中结算：击杀者拿全额 `REWARD.PlayerGold`；
另生成 $\lfloor PlayerGold \times REWARD.AssistGoldRatio\rfloor$ 的助攻金币，由 $n$ 名助攻者平分并各自向下取整；
`REWARD.PlayerXP` 由击杀者和 $n$ 名助攻者共 $n+1$ 人平分，各自向下取整，除不尽的余数不发放。
例：两名助攻者击杀 Lv1，击杀者 80 金币、33 XP，每名助攻者 20 金币、33 XP。资格窗口为 `REWARD.AssistWindowSec`。

因此下表不是玩家真实收益，也不是全员均分规则；后续成长/群攻可以加快清营，前两行不是全局供给上限。

连续三个低营合计500金币。一级每个高营比低营额外花约4.4s并承担明显更多耗血。

1440累计XP达到十级；三级以后每次所需只线性增加20，避免把九次升级选择藏在过长尾部。
但资源供给不是保证经验到账；完整多人对局时长、首购分位数、十次选择体验仍须真实玩法测试。

$T(D)=\min(D,450)/2250+\max(0,D-450)/372$；冲刺冷却9s，返场途中只用得上一次；

若 $D$ 是保守多边形模型内的路径长，它只是该模型路径的名义时间，
**不能当作真实圆胶囊最快返场的严格下界**。
无效dash段必须按真实合法路径重算。不能把3s保护强行加到返场时长，因为主动可以提前解除。

15s复活短于30s守护窗（D22，2026-11-04 用户批准；守护窗 2026-11-05 批准、2026-11-07 改为30s）：被淫的人复活后基速约15+13.6..14.3s
（约28.6..29.3s）才能回到喷漆区，双《润学指南》加一次冲刺的乐观下界为24.743011s，都略早于一次完整守护。
因此在涂鸦刚喷上时被淫的人若立即复活返场且一路无阻，理论上能赶在守护完成前回到喷漆区，但余量只有约0.7..5.3s；
被控、绕人群或晚于涂鸦刚喷上时死亡都会吃掉这段余量。守护能否被打断仍主要取决于场上其他活人围攻主人或进圈改漆，
而有人在区内时守护冻结的时间会给返场留出余量。争夺只暂停喷漆进度，不清零；主人以外有人在区内时守护冻结，冻结期间主人走出则守护清零。
2026-11-07 起守护只在主人独自在区内时计时，主人离区（例如追人、脱险）期间守护暂停，同样给返场留出余量；以上返场时长结论不变，只是“一次完整守护”指主人在区内站满的守护时长。
这不改变随机出生，也不把死亡/受击事件直接转换为胜利。

上述模型路径配一次《润学指南》强化冲刺的名义返场为9.946266..10.485118s；最短首直段2455.545cm在模型里足以容纳
这段位移，但仍不证明UE实际可执行。以上已用于校准本目录最高移动/位移、低营起步、
商店关系和15s复活/3.5s喷漆/30s守护时钟；在没有Unreal NavMesh/Cook和真人联机结果时，
不能将这个**离线设计闭合**升级为地图-经济-旗杆玩法验收通过。

开局金币已够买310/320金币商品，首购不再依赖营地奖励；按新值的营地战斗成本见§7.2。

由 `CatalogTools.encode` 确定性编码，文件内不放自身摘要；对完整文件字节求SHA-256，
将结果写入生成contract及加载身份，避免自引用哈希。
根manifest覆盖schema/稳定原生ID映射、handler/projection合同修订、全部角色/成长/技能/装备/
奖励/价格/政策的内容载荷摘要、已声明的显示定义与世界合同/载荷摘要。

ItemInstance为FGuid；静态内容定义仍是ASCII ID/原生编号。
Generation/参赛生命代次Life仍为uint32，原生身体/效果GUID等不同身份须明确映射；
现有MoveIdentity各字段和其他身份不因这条契约而粗暴全库改宽。

严格拒绝重复/未知 ID、未知/多余字段、bool 冒充整数、非有限数、非法单位、精度丢失、
负周期/非正重复间隔、不可解析引用、无处理器、错 rank 数与数值溢出。
失败不得更新任何产物或部分投影，也不得丢掉坏来源后返回“成功”的构筑。

作者 reader（`Scripts\DemoContent.py`）以 `parse_float=Decimal` 读取 JSON，在任何 float 转换前保留十进制词法，
按字段做有限性、范围及P2/R4/Sec的精确可表示检查；原始 `0.0100000000000000001` 这类超精度和 `1e309` 不会先被 float 吞掉。
随后生成只含规范定点整数、必要有界比率分子/分母、
字符串/布尔/结构的原生投影。`CatalogTools.encode`只接规范化树，不直接序列化不支持的Decimal。

输入拒绝测试（`Scripts\TestDemoContentImport.py`）包含上述超精度/指数溢出原文，而不只对已解析float做IsFinite。

### 10.2 能力身份、冷却债务与快照

| 记录 | 建议完整身份/责任 |
| --- | --- |
| 当前可用来源 `AbilitySourceKey` | 角色：match + contender + learned definition |
| 入口映射 | Q/W 只映射到上述当前来源；不是独立能力或冷却 |
| 角色冷却债务 | match + contender + learned definition；保存绝对 ReadyAt，与 Pawn、槽位和遗忘/重学解耦 |
| 通用冲刺冷却 | match + contender 唯一一条 `Innate` 轨道，开局即签发且就绪；不随构筑变化绑定/解绑，换装不改写已提交 ReadyAt |
| 已释放效果 `EffectContext` | match、施放者 contender/source life、cast/effect ID、定义/rank/handler revision、源属性快照、目标 life、伤害实际归属与 tick ordinal |
| 死亡/奖励回执 | match + victim identity + victim life 的唯一致死提交；持续效果用已冻结的实际所有者，不猜测最后一次接触或最大伤害者 |

进攻意图先经基本鉴权、当前match/life、写闸与去重，再解除当前身体保护，然后才做
source/绑定/target/距离/MP/CD等动作合法性校验。包括AttackUnit、AttackMove及所有角色主动，
即使是self守护；仅本地Armed/预览而未发送的动作不改变权威保护。
来源已知但MP/CD不足的已确认尝试不能只在客户端吞掉，否则会绕过服务器解保护规则。

所有可失败分配在release提交前完成；成功释放才消耗MP、写ReadyAt并创建效果。
动作失败不耗MP/CD，但此前获授权的意图解除保护不会撤销；这不是事务部分成交。
旧身份、伪造所有者、过期/重复请求与终局在意图副作用前拒绝。
释放前取消不收费，释放后取消不退款或撤销已提交效果。
实际阶段顺序由战斗/生命域统一接线，不能通过 Actor Tick 先后碰运气。

源属性在成功释放边界快照，目标抗性/屏障/生命/保护在每次命中实时验证。
前摇中来源构筑变化按 revision 取消，不能拼接两个等级的效果；之后升级/卖装不得改写在途伤害。
持续被动随当前来源生效/移除，不是一次已释放攻击；其触发事件一旦提交，按该条目的生命周期处理。
正常来源死亡、遗忘或卖出后，已成功释放的独立弹体/屏障/控制按原期限继续，
不依赖旧Pawn或当前槽仍存在；击杀归仍在本局的实际施放者。
目标本人的死亡仍清该目标life的临时状态，不能把自身旧盾带到复活；
这与“施放者死亡不取消其他活目标的独立效果”是不同边界。
正式离局取消未结束效果、移除身体；只撤销未来工作，不回滚先前已提交命中。
持续被动本身随绑定生效/失效，未释放动作因死亡取消；旧 target life 和终局绝不能继续受影响。

技能升级、换槽、遗忘再学、死亡都不能洗掉未到期的冷却债务。
按 CB-P05 已确认行为，来源缺席期间按服务器时间经过，不冻结、不返还、不置零。
遗忘只删除技能等级与入口，不保留备用技能库。只在新局更换时间/身份域。
冷却属性只在下一次成功释放时参与计算，不回算已提交 ReadyAt。

本局该owner+角色技能定义确无历史记录时，首次合法学习在成长Prepare/Commit中准备并发行唯一第一条冷却记录；
已有记录的重学/升级/换槽复用原记录和结束时间，learned来源不发行第二条。
新局清空。正式状态类型和提交接口由战斗/成长域共同维护。

### 10.3 最大资源、死亡与奖励原子性

按用户要求保留原HP/MP百分比，采用P2整数的单次最终投影：
`new_current = floor(old_current * final_new_max / old_max)`。
普通活体先按旧rate/旧状态结清到变更时刻的自然回复，再冻结旧current/max，
准备最终构筑的HP与MP结果，全部合法才与来源/库存/金币一起提交；不经逐件卸装中间Max。
比例投影可以提高绝对当前值，但不是额外治疗事件，不另触发吸血/治疗proc。

每一步都有 $newCurrent/newMax \le oldCurrent/oldMax$；没有伤害/回复/复活的零时间链，
回到原Max后当前值不增加。P2下可能向下少于.01点，不能声称无损等比。
40/100→Max150得到60→Max30得到12→Max150得到60→Max100回40。
同Max直接不变，满资源直接映射新Max；其余乘法checked，防止溢出。

极小正活HP缩Max若会量化成0，整个变更返回 `NumericUnderflow`，不改金币、装备、Build、
资源或CD，不因投影制造无主死亡，也不向上补到.01。反例：.01/100缩Max50若硬补.01，
再恢复Max100就变.02，形成舍入收益。MP量化至0不导致死亡，允许发生。
这种拒绝不是额外死亡惩罚；首版永久成长只增Max、死时仅改保留Build，
没有需要强制到期的临时MaxHP/MP增益。未来若增加不可拒绝的活体降Max/强制失源，
必须先补足合同，不能拒绝清理以保留过期来源。

非初始化时 `oldMax=0/current=0/newMax=0` 是合法无资源状态，保持0；
`oldMax=0/newMax>0` 的普通同比投影返回 `NumericDomain`（原因：未定义的0/0比例）。
不补默认百分比；玩家本目录MaxMP始终至少280，零Max只用于不发生该转换的无MP野怪。
开局/正常复活通过生命域的显式初始化事件设置新Max满资源，不调用上述除法当兜底。
死亡选择仅更新持久Build，不同比回写尸体HP/MP，HP为0不复活。

`POLICY.RegenIntegration` 在同一个Combat资源记录保存上次已积分时间和有界亚P2积分余数。
不逐Sample丢弃小数；rate/source变更先积分旧rate至提交时刻，再启用新rate。
同事件时刻、同rate变化轨迹，仅改变采样分段不得改变P2总恢复。
Max同比后积分余数仍是原资源点的未入账小量，不随Max放大；满资源丢弃超额及余数，
不囤积未来回复；死亡/新life清除瞬时积分余数。这不是第二份可写HP/MP或另一时钟。

奖励以 HP 从正变零的唯一致死事实为基础；参赛者受害者的助攻者名单在致死瞬间冻结进同一事实。击杀者与全部助攻者的
XP、金币和派生升级机会应先同时 Prepare（每人一条单账户 Mint，依次链式准备），
在同一可去重提交边界一起兑现（`ALDEconomyDirector::CommitDeathReward`），不能先改 Ledger 再执行可能失败的成长准备。
来源 Pawn 已死但所属参赛者仍在局内，不影响已合法释放效果的奖励归属；无合法所有者则不发奖励。
参赛者离局不是死亡，不发离开奖励。回位只是存活生命的 reset，不发奖、不创建新获奖生命。

沿用 int64 账本与 `净金币变更 = Mint - Burn` 审计。每个真实新死亡 receipt 获一次明确 Mint 权，
不是整局预存有限次数的奖励预算；出售退款与消费实例也须在同笔事务中核对。
极长局如果碰到技术整数/累计审计边界，必须明确失败并记录，不能 wrap、静默饱和或声称已正常发奖；
不以预设超大预算、NPC 钱包或刷新轮数限制冒充无限循环。

## 12. 原生消费者、命令与结果验收

### 12.1 账本与定义的依赖边界

`LDEconomy::FLedger`（`Public\Economy\LDEconomyLedger.h`）是纯值账本：只依赖 CoreMinimal，
不包含 Inventory 类型、不加载 UObject、不访问 World、不读任何目录，也没有旧 `UnitWeight` 查询边。
账本只校验账户/实例存在、所有权、修订、槽位容量、金额与整数范围；
装备定义合法性在进入账本之前由 `ALDVendorDirector` 按本局不可变 `FLDDemoContentSnapshot`
解析商品与卖价，未知定义以 `UnknownItem` 拒绝，不信任调用者传来的“已知定义”标志。
`Reconcile`、`TryCompactResolvedPrefix` 与 DEV 证据导出只重放账本自身条目，不重新加载“最新目录”；
快照保持至该局结束，新局重新建立。这是同一个账本，不是新增权威经济系统。

### 12.2 字段到实际结果的闭合

这是最小字段族映射；compiler 为**每个作者叶子字段**登记类型、单位转换、
原生成员、唯一消费函数、拒绝条件和行为用例。运行字段/表现字段/构建元数据分开；
未知字段直接拒绝。“原生消费者”列是当前代码落点（见 §9）。

持续被动与交易请求分别按 §2/10 生命周期处理，不以一个“全部清空”策略替代。

`CancelOrder` 处理空间订单。

来源/Build/资源提交沿会话与对局域的 `FLDGameplayWritePermit`，不另建写闸或时钟。

才作为动作身份。本文ActionId/AttackId是该Token在Match/Caller域的语义名，不另建一条攻击序列；
Nav连续普攻仅增加请求中的AttackCycle，仍复用Combat节拍与同一归属/去重链。

### 12.5 UI/AI可读定义与显示引用

不可变内容定义是公开知识，AI可以读取目标模式、固定价格/费用、属性与效果规则，
不能由此取得某个隐藏单位当前HP、装备实例、源CD或营地刷新实况。自身能力可用性、
每个IssuedCooldownId剩余时间和实际资源从本人授权投影读取，不从目录值猜测“已经ready”。

显示元数据统一为 `DISPLAY.<contentId>.NameKey/DescriptionKey/IconId`；
本地化namespace为 `DemoContent`，键分别为 `<contentId>.name`、`<contentId>.description`，
占位图标语义ID为 `icon_<contentId>`。这些规则适用于角色、六个角色技能、五张卡、
七件装备和两种怪物；具体中文名称用本报告目录中的名字。
基础头像另用 `DISPLAY.character_demo.PortraitIconId=portrait_character_demo`。
显示名与说明作为显示行的 `name_text`/`description_text` 进入 SourceData，经同一 Sync/check 生成载荷并计入根摘要；
运行时由已验证内容注册 `DemoContent` 字符串表，缺失条目是内容错误。说明不含数字，
等级、费用、冷却、射程与期限等数值由 typed 字段显示。
导入器（`LDDemoContentImport`）校验这些键与图标语义 ID 的规范形式；仓库当前没有对应图标资产，不宣称图标已生成。
占位图形可用自有箭头、护盾、锁链等简单轮廓与文字，不能复制外部游戏素材，也不能只靠颜色分辨。

状态显示名为：`root`「定身」、`shield`「护盾」、`camp_returning`「回位」；
现有显示键、状态身份、控制与保护语义不变。
公开状态另登记 `StatusDefinitionId=camp_returning`（“回位”）及对应
`DISPLAY.camp_returning.NameKey/DescriptionKey/IconId`。
它从当前合法可见的 `WorldView.Statuses` 读取，无层数、截止、Home坐标、仇恨或内部phase，
不是新增Buff、无敌或可攻击性开关。UI/AI不能绕过该视图自行读取Camp状态。

另登记公开状态 `respawn_protection`，稳定状态编号为 `4`，显示名「复活保护」。
本地化 namespace 为 `DemoContent`，显示键分别为
`respawn_protection.name`、`respawn_protection.description`，图标语义 ID 为
`icon_respawn_protection`；它只是既有复活保护事实的显示元数据，不新增 effect opcode，
不改变保护时长、进攻意图解除规则或任何其他内容值。

复活保护的唯一真值是核心 `Lives.ProtectedUntilMs`，本人沿 `OwnerState` 显示状态与剩余时间。
他人仅在当前合法可见时，从同一个 `Statuses` 列表获得非叠加的 `respawn_protection` cue
及 `ExpiresAtServerMs`；后者是该保护期限的只读投影，不是第二份可写计时器。
cue 不发布层数、`RespawnAt`、`Life`、`BodyIdentity` 或来源信息。
保护解除/到期或失去观察权限时撤销该 cue，不在隐藏期间更新或保留其当前倒计时；
UI 只能按同步服务器时间展示，不能因本地显示到零自行解除保护。

描述采用typed字段命名参数展示等级/伤害类型/系数/费用/基础与有效CD/射程/状态期限。
UI不能硬编码一套伤害或CD公式；最终 `STAT.MoveSpeedCmPerSec`、`STAT.AttackRangeCm`、
当前资源和来源剩余CD从同一只读投影提供。

可见对手按用户确认显示名称/等级/HP/MP/公开临时状态/装备**定义**，以及 Q/W 两个主动技能的定义与等级（#112 §10，满级显示 Lv3 标记）；
不发送私有物品实例、IssuedCooldownId、被动列表、技能 CD、其他属性贡献或金币。
永久学习被动不能伪装成“公开状态”泄露技能构筑。失视野清检查目标/锁定并停止该追击订单，
不保留地图LastSeen单位标记；地图地形/固定地点仍可见。
死亡可以自由拖动静态地图，但不增加活体观察源，也不跟随隐藏玩家。
镜头速度/缩放/边缘带由UI与操作域作为本地设置维护，不是本报告的玩法平衡参数。

终局只展示用户确认的全员名称、击杀、死亡、最终等级、唯一赢家、结束原因与用时。
这些统计只描述结果，绝不能代替喷漆与守护判胜或建立超时积分胜利。

## 14. 专家范围与审核结论

本轮实际使用三个分离上下文的AI专家角色：两份研究先独立进行，第三位审核者在整合稿之后
独立复算并定点复核修改，不以研究作者自检冒充独立QA。以下是最终结论，不是人类游玩测试。

| 实际角色 | 独立范围 | 交付/证据边界 |
| --- | --- | --- |
| `content-design-expert` 玩法/经济/数值研究 | 独立阅读Spec、公开机制参考、最小目录与成长/经济/时间模型 | 提供初版设计依据；整合按全规模供给、AP实效、精度及用户确认的PreserveRatio收敛，不把初稿结果直接当结论 |

**共用战斗原语**（实现与接口见 `docs\systems\COMBAT_AND_GROWTH.md`）：

- **命中特效**只有吸血、横扫、开盒大师叠层三种，按命中的系数触发：普攻主击 1.0，其余技能按其定义（默认 0，不触发）。
  横扫副击、附加伤害（潜水党、折叠椅第三击等独立命中）、反伤与你瞅啥 3 级脉冲都不触发命中特效。
- **增伤合并**：“自己造成的伤害 +%”（已截图、网线够长及后续同类）先相加成一个 (1+Σ) 系数；背后命中、暴击等技能自身倍率
  与之相乘；目标的暴击减伤最后相乘；都在抗性之前，最后一次向下取整。
- **技能暴击**倍率 `STAT.AbilityCritMultiplier=1.5`；只有上表列出的来源能让技能暴击，每次施放对每个目标只判定一次；
  反伤与附加伤害不暴击。
- **吸血**：普攻吸血、技能吸血与全能吸血相加后，按该次实际掉血（不含护盾吸收与溢出）回复，向下取 0.01。
- **破防**：同一身体可有多份破防记录（按来源效果区分，同一来源重复施加刷新）。固定值相加、比例相加；先减固定值再乘
  (1 − 比例和)，不低于 0。公开显示为“破防”。
- **硬控递减**：定身、眩晕、缴械、嘲讽共用一个计数；上一次硬控生效期间或结束后 2 秒内再中硬控，持续 ×60%、×30%（第三次及以后），
  最短 0.2 秒（原持续更短时取原值）；连续 2 秒没有新硬控即清零。减速与击退不递减；未生效的控制不推进计数。
- **剩余冷却缩减**只把尚未结束的冷却结束时间提前（不早于当前时刻），不改基础冷却、不影响已就绪的入口。
- **《润学指南》**对技能的加成在释放时固定；之后换装不改写已开始的冷却。

**新机制的合同**（实现与接口见 `docs\systems\COMBAT_AND_GROWTH.md`）：

- **击退**：服务器权威的强制位移，沿地面以与冲刺相同的原生位移推开，遇阻停在最远合法位置，不传送；方向为施放点

  （从无到有不算刷新，R1）；“打破”= 被伤害打空；到期、被掀桌消耗、被实锤冲塔击碎都不算打破。
  由脉冲或护盾触发的效果（精神胜利法、防窥膜）不再触发获得护盾的效果。
- **减疗减盾**：按比例降低目标受到的一次性治疗（吸血、技能回复）与护盾获得量；自然与脱战回复不受影响（R3）；
  同类来源取最强、不叠加，同一来源重复施加刷新。公开显示“重伤”。
- **持续伤害、区域**：持续伤害与区域脉冲按施放时快照的攻击力/法术强度结算，不暴击；破防叠层写入 §15.10 的同一份破防记录，
  按层计固定削减，结束全部恢复。施放者离局时其持续伤害、区域与减疗一并取消。
- **负面状态计数**：定身、减速、缴械、眩晕、嘲讽、破防（含持续伤害）六种，每种只算一次，按命中前的状态计。

- 当前限制：键盘连喷暂用天外飞瓶的弹体外观；对手 AI 在 #117 之前不会使用新主动。
