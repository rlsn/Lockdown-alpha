# Demo 首版内容与数值

本报告面向 v0.10.0 Demo 的实施准备与 PR 审查。产品约束来自
[App Spec](../APP_SPEC.md)；本文提出的目录、公式和参数均为**待 PR 审查的首版设计建议**，
不是已批准规则，也不是当前运行实现或平衡验收的完成声明。
核对源码的基线为 `fa11d09a762bccadf495191072e222dd158fc014`。

本文只维护本模块最终推荐方案、实施约束和验收边界，不保存放弃方案或研究过程记录。
实现时必须先批准影响玩法的基础行为，再由同一数据链生成并验证载荷；
不能直接把本报告中的表格视为已经生效的 SourceData。

| 所有战力与经济只属于本局 | 新局重建身份与资源；旧请求、回执、效果不能作用于新局或新生命 |

### 1.1 参数权威与模块接口

本文是内容和玩法参数的唯一建议值来源。世界模块维护地图坐标、路径、通道、遮挡和
查询契约，引用本文的参数 ID，不维护另一份可独立改动的数值表。
地图上的直线距离不代替合法最短路径；离线几何模型不代替 Unreal 导航和真实拥有客户端验收。

| 接口 ID | 责任边界 |
| --- | --- |
| `UNIT.MoveSpeedCmPerSec`、`UNIT.CollisionRadiusCm`、`UNIT.BasicAttackRangeCm` | 内容模块定单位与建议值，世界模块验证通道和接近几何 |
| `VISION.RadiusCm`、`SHOP.InteractRadiusCm` | 内容模块定半径；世界与视野模块验证遮挡、权限和交互可达 |
| `CAPTURE.RadiusCm`、`CAPTURE.HoldSec`、`MATCH.DevelopmentSec` | 内容模块定尺度与节奏；比赛模块实现 Spec 的同刻结算和唯一胜者 |
| `TIMING.DefendRouteBudgetSec` | 世界模块提供最远关键路径；内容模块复算回防，不保证每次死亡后必能救圈 |
| `LIFE.RespawnSec`、`LIFE.ProtectionSec` | 内容模块定时长；生命与权威模块维持时间、免疫、保留和重开隔离 |
| `CAMP.Low.*`、`CAMP.High.*` | 内容模块定构成、强度、收益、刷新、追击与重置；世界模块配置五个稳定营地锚点 |

所有世界距离建议统一为单层地面脚点的 XY 厘米距离。普攻距离是攻击者中心至目标中心；
商店交互距离是角色中心至固定交互锚点；两者都不再加减双方碰撞半径。
圆圈建议按脚点中心在半径以内判定，边界含等号，不要求整只胶囊进入才计数。
碰撞半径单独用于通道净空、接近点生成和同点防重叠，不能在距离公式中重复计算。
这些查询语义须与世界模块的正式接口一致。

回防路径终点是可达的有效圈边，不是圈中心；购物路径终点是可达的交互区域边界，
不是可能被阻挡的商店本体中心。商店交互半径内如果没有合法接近点，必须拒绝该布局，
不能扩大服务器接受距离、穿墙或传送以使样例通过。

| --- | --- |

## 2. 建议方案与决策状态

首版采用 **1 基础角色、3 角色主动、3 角色被动、5 属性奖励、7 装备、2 野怪定义**。
三个主动刚好允许演示两个槽满后的替换；三个被动覆盖持续属性与条件回复；
五种属性卡提供不依赖技能/装备的持续增益，其中射程卡落实用户确认的普攻成长；
七件装备覆盖物攻、物防、法强/冷却、伤害回复、位移、资源主动与普攻群攻。
没有合成、消耗品、免死、反射、地表反应或额外职业。

下列建议是一个方案，不是两个可同时运行的模式。PR 审查改变基础行为时，应重新计算受影响的
目录/模型并修订本报告，不把旧候选继续留在运行配置。

| 决策 | 状态 | 本报告采用的建议语义 |
| --- | --- | --- |
| CB-P01 普攻形态与成长 | **用户已确认**“所有人初始都是近战单体普通，群攻/攻击距离可以通过装备或者属性增加” | 初始近战单体，射程卡与余波锤提供首版可获得成长；具体幅度/余波形式仍待PR审查，不引入追踪普攻弹体 |
| CB-P02 同款两件 | **用户已确认允许** | 两件有不同实例身份；每件固定属性相加；不以旧部位/排他规则拒绝 |
| CB-P03 同名装备被动 | **用户已确认**“基础属性相加，同名被动只生效一次” | 固定属性逐实例相加，相同被动族每事件只生效一份；本池同族同值，不需要猜测多等级装备强弱 |
| CB-P04 同款装备主动 | **用户已确认**“各自独立冷却，可以连续使用两次” | 两份持久 IssuedCooldownId，各有自己的 ReadyAt；不是同款共享一个锁 |
| CB-P05 来源缺席期间的冷却 | **用户已确认**“失去来源期间继续计时，重新持有时沿用原结束时间” | 出售/遗忘不改原截止时刻；重购/重学重新关联原有债务，不冻结、不重置 |
| CB-P06 死亡时确认选卡 | **用户已确认允许** | 处理已固定候选只改保留构筑，不治疗/复活死体，不重抽 |
| CB-P07 最大资源变更 | **用户已确认保持原生命/法力百分比** | 所有普通升级/选择/换装只对最终Max同比换算一次；P2量化与下溢拒绝是本报告技术方案 |
| CB-P08 已释放效果与失源/离局 | **用户已确认** | 正常死亡/出售/遗忘不取消已成功释放的独立效果；未释放动作死亡取消；正式离局取消未结束效果并移除身体。持续被动/维持型来源失效另按绑定条件处理 |
| CB-P09 无效进攻与保护 | **用户已确认进攻意图即解除** | 基本鉴权、当前match/life、去重和写闸先行；之后即使目标/距离/MP等失败也解除，失败仍不收费 |
| CB-P10 可见敌人信息与隐藏 | **用户已确认** | 可见对手显示名称/等级/HP/MP/状态/装备，不显示技能/CD/其他属性/金币；失视野取消锁定并停止追击订单，无LastSeen地图单位标记；死亡可拖动静态地图但无额外活体视野 |
| CB-P11 野怪反击与回位 | **用户已确认** | 不先手；受合法攻击命中后同营共同反击但不共享隐藏坐标。Returning仍可伤/控/杀、不回头；到家存活成员满已定义血蓝、清临时/仇恨、技能就绪，不复活死成员、不发奖 |
| CB-P12 商店视线 | **用户已确认不额外检查LOS** | 使用合法区域、真实交互距离及存活/进行中等既定条件；不能把技能单位目标的LOS要求套给固定商店 |

双持、属性相加、同名被动一次、两份主动独立 CD、失源继续计时均已确认。
具体价格、效果和时长仍待 PR 审查，不在本轮写入 SourceData。

## 3. 单位、参数与公式

### 3.1 统一表示与失败语义

| 类型简称 | 作者表示/单位 | 原生建议与取整边界 |
| --- | --- | --- |
| P2 | 至多两位小数的资源/属性点 | 精确解析为 int64 百分之一点；当前 HP/MP 只在原有战斗状态中有一份真值 |
| R4 | 至多四位小数的无量纲比例/倍率 | 精确 basis points；概率与倍率是不同字段，倍率允许大于 1 |
| Rate | 次/秒、点/秒、cm/s，字段逐项注明 | 保留精确有理/足够精度中间结果；周期和资源提交最后才取整 |
| Sec | 非负、至多三位小数的秒 | 作者秒数必须可精确转换为整毫秒；不悄悄截去小数。派生 CD/间隔向上整毫秒 |
| Count | 等级、数量、XP、金币的整数 | bool 不是整数；运行累计 XP/金币用有界 int64，乘加预检溢出 |
| Cm | 单层脚点 XY 厘米 | 参数有限且非负；实际位置/路径由世界正式查询提供，不另建内容网格 |

所有范围、分母、精度和有限性先验证。非法输入整次拒绝，保持旧有效状态与产物，不用 Clamp
掩盖 NaN、溢出或缺少字段。表内资源/点值上限是本目录投影的拒绝界，不是允许把选中的卡片
静默夹成零收益；本池所有合法组合均在界内。AS/MS/概率的玩法夹取另外显式定义。
同一次属性变更只投影最终来源集合一次，UI 的格式化不回写结算。

### 3.2 基础角色 `character_demo`

令等级为 $L$，$k=L-1$。表中 `.Base` 与 `.PerLevel` 是作者键，`STAT.<属性>` 是派生结果。
初始只有普攻；未学技能、未持装备、无被动/属性卡、没有待选机会；血蓝按下表满值初始化。

| 稳定参数键 | 单位/类型 | Base；PerLevel | 合法结果范围 | 依赖、理由与可复算样例 |
| --- | --- | --- | --- | --- |
| `STAT.MaxHP.Base/PerLevel` | HP 点/P2 | 620；58 | 1..3000 | 与低营开荒约5.82%净损血、高营约55.85%联算；L10=1142 |
| `STAT.MaxMP.Base/PerLevel` | MP 点/P2 | 280；22 | 0..800 | 裸角色初期约4–6次主动资源；后续电池以装备取舍换续航；L10=478 |
| `STAT.AD.Base/PerLevel` | 物攻点/P2 | 54；3.2 | 0..250 | 普攻 1.0 AD；L5=66.8，L10=82.8 |
| `STAT.AP.Base/PerLevel` | 法强点/P2 | 0；0 | 0..250 | 通过属性/符文装备构筑；不让 AP 隐式强化普攻 |
| `STAT.Armor.Base/PerLevel` | 护甲点/P2 | 18；2 | 0..200 | 首版无负抗/穿透；L10=36，不是 36% 减伤 |
| `STAT.MagicResist.Base/PerLevel` | 魔抗点/P2 | 18；2 | 0..200 | 与护甲用相同点制公式；不能直接填入旧 MR 比例字段 |
| `STAT.BaseAttackSpeed` | 次/秒/Rate | 0.70 | 正数 | 约 1.429s 一个基础攻击节拍，提供清楚前摇与走位时间 |
| `STAT.AttackSpeedPerLevelRatio` | 每级加成/R4 | 0.02 | 0..1 | 与装备/被动同类相加；L10 无其他来源 AS=0.826 |
| `STAT.HPRegen.Base/PerLevel` | HP 点/秒/Rate | 1.60；0.12 | 0..12 | 基础回复始终有效，条件被动另外增加；L10=2.68/s |
| `STAT.MPRegen.Base/PerLevel` | MP 点/秒/Rate | 1.20；0.08 | 0..4 | 无自动战斗回蓝或商店满蓝；L10=1.92/s |
| `STAT.CritChance.Base` | 概率/R4 | 0 | 0..1 | 仅普攻允许暴击；由 precision 被动获得概率 |
| `STAT.CritMultiplier` | 倍率/R4 | 2.00 | 固定 | 不作为首版可堆叠属性；54 AD 暴击原始量 108 |
| `STAT.CooldownHaste.Base` | 冷却点/P2 | 0 | 0..60 | 只影响角色/装备主动的下一次释放，不影响 proc/复活/刷新/占点 |
| `UNIT.MoveSpeedCmPerSec` | cm/s/Rate | 600 | 派生 300..900 | 把 9600cm 路径换算为 16s；是设计值，不宣称由引擎默认值批准 |
| `STAT.MoveSpeedCmPerSec` | cm/s/Rate | 按来源派生 | 300..900 | `FORMULA.MoveSpeed`；初始600，两相位锚744；UI/运动读取最终值 |
| `UNIT.CollisionRadiusCm` | cm/Cm | 40 | 固定 | 最小双身体中心分离 80cm，小于建议普攻距离；世界负责净空/防重叠 |
| `UNIT.BasicAttackRangeCm` | cm/Cm | 220 | 基础值 | 给80cm碰撞分离之外的接近余量；真实射程必须读下行派生值 |
| `STAT.AttackRangeCm` | cm/Cm | 按来源派生 | 80..1000 | `FORMULA.AttackRange`；初始220，九次射程卡+两余波锤为660 |
| `UNIT.BasicAttackWindupSec` | s/Sec | 0.250 | 正数 | 按 AS 反比缩放；基础 250ms，不能把前摇与整段攻击周期混用 |
| `UNIT.BasicAttackTargetMode` | enum | Unit | 仅 Unit | 可攻击、可见、敌对参赛者或野怪；商店/自己非法 |
| `UNIT.BasicAttackDamageType` | enum | Physical | 固定 | 每次普攻原始量为 AD，无 MP 费用，无隐含顺劈 |
| `UNIT.BasicAttackADRatio` | 倍率/R4 | 1.00 | 固定 | 与物攻相乘，不读AP；暴击另按AttackId处理 |

结果包络不是可以同时获得的一套构筑：分别把九次卡全投某属性、再取最有利的两件装备，
得到保守上界 HP 2402、MP 718、AD 194.8、AP 204、护甲 120、魔抗 114、AS 1.106、
移动 744cm/s、普攻射程660cm、Haste 30、暴击率 0.20。即使这些坐标上界分别计算，也没有卡被上限吞掉。
Root 是动作禁止，不把移动速度属性改成 0 后再夹回 300。

### 3.3 可实施公式表

| 公式 ID | 输入 → 输出/顺序 | 范围、取整与样例 |
| --- | --- | --- |
| `FORMULA.StatProjection` | base + level + 属性卡 + 角色被动 + 装备 + 临时来源的 flat 先相加；同类 percent 相加后乘一次 | 先校验来源/族，再最终投影，不逐装备取整/封顶；相同来源集合换显示槽结果不变 |
| `FORMULA.Resistance` | 原始物理/魔法伤害 $D$ 与对应抗性点 $R$ → $D\times100/(100+R)$ | $R\in[0,200]$；R=0 不减伤，R=100 减半；不实现未被目录使用的负抗/穿透分支 |
| `FORMULA.Crit` | 仅合法普攻主击在唯一 AttackId 取一次随机值 $u\in[0,1)$；$u<p$ 时主击原始 AD 乘 2 | 服务器独立确定性随机流；重发同 AttackId 不重抽；副击、技能、吸血治疗不可暴击 |
| `FORMULA.Damage` | source 快照原始量 → 适用暴击 → 目标实时抗性 → 向下取 0.01 → 现有屏障吸收 → 实际 HP 损失 | HP 损失不超过目标剩余 HP；70 对 18 抗=59.32，108 对 18 抗=91.52；0.009 对零抗=0，不设最低 1 点伤害 |
| `FORMULA.AttackSpeed` | $0.70\times(1+0.02k+\Sigma ASBonus)$ → AS | 最后夹取到 [0.30,2.50] 次/秒；本目录实际可达 [0.70,1.106] |
| `FORMULA.MoveSpeed` | $UNIT.MoveSpeedCmPerSec\times(1+\Sigma MoveSpeedBonusRatio)$ | 最后夹取[300,900]cm/s；本目录[600,744]，不把Root动作禁止当减速属性 |
| `FORMULA.AttackRange` | 基础 `UNIT.BasicAttackRangeCm` + 永久/装备 `AttackRangeCmFlat` → `STAT.AttackRangeCm` | 无乘区；九次卡+两锤=220+9×40+2×40=660cm；目标/导航接近/预览/AttackMove全用派生值 |
| `FORMULA.AttackIntervalMs` | $\lceil1000/AS\rceil$ → 相邻合法 AttackStart 的最短间隔 | AS=.70 得 1429ms；发出新 order、S 取消、换装备、死亡均不清已提交攻击端点 |
| `FORMULA.AttackWindupMs` | $\lceil1000\times UNIT.BasicAttackWindupSec\times STAT.BaseAttackSpeed/AS\rceil$ | 基础 250ms；必须小于本次攻击间隔。前摇可以取消/因失去权限失败，但不退款已提交节拍 |
| `FORMULA.CooldownMs` | $\lceil1000\times BaseCDSec\times100/(100+H)\rceil$ → 本次释放持续时间 | H 非负；6s、H=30 得 4616ms。10s 释放得到 ReadyAt=14.616s，随后卸装/升级不改这个端点 |
| `FORMULA.Regen` | rate × 同一权威时间的实际 elapsed + 亚P2积分余数 → 可提交的0.01点及新余数 | 见 `POLICY.RegenIntegration`；活体才恢复，满资源丢弃溢出。1.6/s 分1000次1ms仍回复1.60 |
| `FORMULA.ResourceMaxChange` | 以P2整数计算 $\lfloor oldCurrent\times finalNewMax/oldMax\rfloor$ | 用户要求保持比例，最终一次向下量化；40/100→150为60→30为12→150为60→100回40；零上限/活HP下溢见§10.3 |
| `FORMULA.SellGold` | $\lfloor PurchasePrice\times SHOP.SellRatio\rfloor$ | 全部固定价、无折扣；310×.65=201，不是202。整数溢出整笔拒绝 |
| `FORMULA.XPToNext` | $80+20(L-1)$，仅 $L=1..9$ | 正整数；达到十级不再调用生成机会。采用可手算线性增量，不依赖任意公式字串执行器 |

普攻节拍从通过初始合法性检查的 AttackStart 提交；技能/装备主动则在成功 release 才提交
MP/CD。前摇内复查目标/来源，导航不负责扣费或退节拍。基础普攻命中前失效是一次已开始的
挥空，不是把非法最初输入当作成功攻击。最初动作输入被拒绝时不提交攻击节拍、费用或攻击效果，
但已认证进攻意图的解除保护仍按§10.2生效；不能把“失败无费用”写成“任何状态都不变化”。
前摇中的构筑/来源变更取消该暂存攻击，不能把两个修订的属性拼起来。

派生时长向上取毫秒之后，新截止时间还须从原始实际释放时刻安全建立：
`ReadyAtMs = ceil(OccurredAtSeconds × 1000) + DurationMs`，不能先floor起点而提前到期。
例如1000.8ms开始、持续1ms，截止为1002ms；1001.9ms时还不能使用。
`OccurredAtMs`若是ceil桶，只用于分桶；真正先后仍按原始OccurredAtSeconds及同刻因果顺序。
Ready比较用原始时间或安全的floor当前毫秒，不能用ceil当前桶提早开放。唯一时钟/Stamp由生命周期域维护。

不能静默传送、生成新生命或发奖掩盖问题。

旧受击/仇恨通知必须按事件身份与reset时序去重，不能让到家前的迟到通知重新启动追击。

同时要求同层合法capsule，不再分Low/High配置。40cm怪+40cm玩家的最小分离80cm再留20cm，
避免单个玩家占home时怪永远停在80cm外、进不了过小归位区而只能挨打。
世界模型核对八个home到外扩静态阻挡/边界净空501.769409..563.018848cm，
100cm归位区有至少401.769409cm静态余量。导航agent-overlap不能再加40变成140cm成功判定，
也不强行snap到被占的home中心；home坐标不随reset漂移。
两个归位区可以重叠，实体仍遵守动态防重叠；多人围堵及原生实际接近尚须运行验收。

例如一组低怪先死一只，发40XP/30金币；另一只回位只回血，奖励仍未发、原 life 不变。
之后它在t=10s死亡，整组从t=10开始40s等待，于t=50生成两个全新生命。
旧弹体/命中持有旧 target life，不能伤害这次刷新。

### 9.1 效果能力不是一个“法术”标签

原生已有 Attack/Skill/Item/Move/Dash/Service 的允许性检查，以及 Stun、Silence、

绕过 Silence；装备主动仍检查 Item/Mute。未进入首版目录的控制与效果无需作为可玩内容保留。

本目录的直接伤害、治疗/屏障与控制原语可以从 E07–E10 抽取；法强、通用暴击/冷却属性、
角色被动三级、属性卡和完整效果程序需要改造/新增。若使用伤害触发效果，应新增统一结果投影
`raw / mitigated / shield_absorbed / hp_lost`；不得把当前 Contact 当作实际掉血。
每个内容字段在导入投影与处理器中都要有消费者，未知字段、未知操作或缺少处理器应拒绝，

不是调用者各挑一个子目录摘要。`Content\Lockdown\Data\Demo\manifest.json`
由 `CatalogTools.encode` 确定性编码，文件内不放自身摘要；对完整文件字节求SHA-256，
将结果写入生成contract及加载身份，避免自引用哈希。
根manifest覆盖schema/稳定原生ID映射、handler/projection合同修订、全部角色/成长/技能/装备/
奖励/价格/政策的内容载荷摘要、已声明的显示定义与世界合同/载荷摘要。
子载荷仍分别由正式Sync生成校验，不能把子摘要当同一个CatalogDigest比较。
请求wire固定32原始字节，FString/日志展示64个小写hex字符；一局固定根身份，
不能中途热换目录而继续接受旧offer/来源。产品版本与这个根摘要是不同边界。
新窄请求/修订位宽按成长/战斗合同为uint64，已生成Offer/Option实例、IssuedCooldown、
ItemInstance为FGuid；静态内容定义仍是ASCII ID/原生编号。
Generation/参赛生命代次Life仍为uint32，原生身体/效果GUID等不同身份须明确映射；
现有MoveIdentity各字段和其他身份不因这条契约而粗暴全库改宽。

严格拒绝重复/未知 ID、未知/多余字段、bool 冒充整数、非有限数、非法单位、精度丢失、
负周期/非正重复间隔、不可解析引用、无处理器、错 rank 数与数值溢出。
失败不得更新任何产物或部分投影，也不得丢掉坏来源后返回“成功”的构筑。

`read_json`不能原样承担新精度合同：原始 `0.0100000000000000001` 若先被Python float读成.01，
之后再 `Decimal(str(value))` 已无法发现超精度；`1e309`也可能在reader阶段先变inf。
因此在任何float转换前保留十进制词法/Decimal，按字段做有限性、范围及P2/R4/Sec的精确可表示检查。
schema数值类型谓词须适配这个作者阶段；随后生成只含规范定点整数、必要有界比率分子/分母、
字符串/布尔/结构的原生投影。`CatalogTools.encode`只接规范化树，不直接序列化不支持的Decimal。
大整数不得经double取回；相应字段按显式整数wire或十进制字符串解析。
输入拒绝测试必须包含上述超精度/指数溢出原文，而不只对已解析float做IsFinite。

### 10.2 能力身份、冷却债务与快照

| 记录 | 建议完整身份/责任 |
| --- | --- |
| 当前可用来源 `AbilitySourceKey` | 角色：match + contender + learned definition；装备再含 item instance、equipment definition、ability definition |
| 入口映射 | Q/W 或 1/2 只映射到上述当前来源；不是独立能力、冷却或物理物品 |
| 角色冷却债务 | match + contender + learned definition；保存绝对 ReadyAt，与 Pawn、槽位和遗忘/重学解耦 |
| 装备冷却债务 `IssuedCooldownId` | 每个 match + contender + equipment definition 最多两份持久轨道；各自保存 ReadyAt，实例绑定到具体轨道，Family只分组 |
| 已释放效果 `EffectContext` | match、施放者 contender/source life、cast/effect ID、定义/rank/handler revision、源属性快照、可选 item instance、目标 life、伤害实际归属与 tick ordinal |
| 死亡/奖励回执 | match + victim identity + victim life 的唯一致死提交；持续效果用已冻结的实际所有者，不猜测最后一次接触或最大伤害者 |

进攻意图先经基本鉴权、当前match/life、写闸与去重，再解除当前身体保护，然后才做
source/绑定/target/距离/MP/CD等动作合法性校验。包括AttackUnit、AttackMove及所有角色/装备主动，
即使是self守护/回蓝；仅本地Armed/预览而未发送的动作不改变权威保护。
来源已知但MP/CD不足的已确认尝试不能只在客户端吞掉，否则会绕过服务器解保护规则。

所有可失败分配在release提交前完成；成功释放才消耗MP、写ReadyAt并创建效果。
动作失败不耗MP/CD，但此前获授权的意图解除保护不会撤销；这不是事务部分成交。
旧身份、伪造所有者、过期/重复请求与终局在意图副作用前拒绝。
释放前取消不收费，释放后取消不退款或撤销已提交效果。
实际阶段顺序由战斗/生命域统一接线，不能通过 Actor Tick 先后碰运气。

源属性在成功释放边界快照，目标抗性/屏障/生命/保护在每次命中实时验证。
前摇中来源构筑变化按 revision 取消，不能拼接两个等级的效果；之后升级/卖装不得改写在途伤害。
持续被动随当前来源生效/移除，不是一次已释放攻击；其触发事件一旦提交，按该条目的生命周期处理。
正常来源死亡、遗忘或卖出后，已成功释放的独立弹体/屏障/控制按原期限继续，
不依赖旧Pawn或当前槽仍存在；击杀归仍在本局的实际施放者。
目标本人的死亡仍清该目标life的临时状态，不能把自身旧盾带到复活；
这与“施放者死亡不取消其他活目标的独立效果”是不同边界。
正式离局取消未结束效果、移除身体；只撤销未来工作，不回滚先前已提交命中。
持续被动本身随绑定生效/失效，未释放动作因死亡取消；旧 target life 和终局绝不能继续受影响。

技能升级、换槽、遗忘再学、卖出重买、死亡都不能洗掉未到期的冷却债务。
按 CB-P05 已确认行为，来源缺席期间按服务器时间经过，不冻结、不返还、不置零。
遗忘只删除技能等级与入口，不保留备用技能库。
当前装备实例可以删除，债务记录却必须保留。只在新局更换时间/身份域。
冷却属性只在下一次成功释放时参与计算，不回算已提交 ReadyAt；
装备只检查当前绑定 IssuedCooldownId 的截止时刻，不能把同款另一份的CD合并过来。

本局该owner+角色技能定义确无历史记录时，首次合法学习在成长Prepare/Commit中准备并发行唯一第一条冷却记录；
已有记录的重学/升级/换槽复用原记录和结束时间，learned来源不发行第二条。
对装备定义，确无任何已签发轨道的空集合，首次合法购买在准备阶段拟建第一份IssuedCooldownId，成交才发布。
已有轨道时，先绑定仍未到期的未绑定债务，按ReadyAt降序、稳定ID打破平局；
没有这类债务才使用已到期空轨道。只有已有一份轨道绑定在真实持有的第一件装备、
且本次是合法购买第二件时，才准备第二份；不能以新实例、售出解绑或换槽冒充“无历史首次获取”。
来源绑定进入购买Prepare/Commit；创建/余额/版本校验失败不占轨道。客户端不选择一个“全新ready身份”。
同一实例不能绑定两轨，同一轨也不能绑定两实例。
售出仅解绑，不删除或缩短截止时刻；新局清空。正式状态类型和提交接口由战斗/成长域共同维护。

例如首次持A并使用后售出，重买会继承A的未到期轨道，而不是新建空白B绕过。
真正同时持A/B时可分别使用，ReadyAt分别为38.000s和38.250s；
卖出两件后再买两件，依次回绑38.250s与38.000s，仍是两份独立结束时间，
不是把两个入口一起锁到38.250s。物理槽位排序不改变这些绑定。

### 10.3 最大资源、死亡与奖励原子性

按用户要求保留原HP/MP百分比，采用P2整数的单次最终投影：
`new_current = floor(old_current * final_new_max / old_max)`。
普通活体先按旧rate/旧状态结清到变更时刻的自然回复，再冻结旧current/max，
准备最终构筑的HP与MP结果，全部合法才与来源/库存/金币一起提交；不经逐件卸装中间Max。
比例投影可以提高绝对当前值，但不是额外治疗事件，不另触发吸血/治疗proc。

每一步都有 $newCurrent/newMax \le oldCurrent/oldMax$；没有伤害/回复/复活的零时间链，
回到原Max后当前值不增加。P2下可能向下少于.01点，不能声称无损等比。
40/100→Max150得到60→Max30得到12→Max150得到60→Max100回40。
同Max直接不变，满资源直接映射新Max；其余乘法checked，防止溢出。

极小正活HP缩Max若会量化成0，整个变更返回 `NumericUnderflow`，不改金币、装备、Build、
资源或CD，不因投影制造无主死亡，也不向上补到.01。反例：.01/100缩Max50若硬补.01，
再恢复Max100就变.02，形成舍入收益。MP量化至0不导致死亡，允许发生。
这种拒绝不是额外死亡惩罚；首版永久成长只增Max、死时仅改保留Build，
没有需要强制到期的临时MaxHP/MP增益。未来若增加不可拒绝的活体降Max/强制失源，
必须先补足合同，不能拒绝清理以保留过期来源。

非初始化时 `oldMax=0/current=0/newMax=0` 是合法无资源状态，保持0；
`oldMax=0/newMax>0` 的普通同比投影返回 `NumericDomain`（原因：未定义的0/0比例）。
不补默认百分比；玩家本目录MaxMP始终至少280，零Max只用于不发生该转换的无MP野怪。
开局/正常复活通过生命域的显式初始化事件设置新Max满资源，不调用上述除法当兜底。
死亡选择仅更新持久Build，不同比回写尸体HP/MP，HP为0不复活。

`POLICY.RegenIntegration` 在同一个Combat资源记录保存上次已积分时间和有界亚P2积分余数。
不逐Sample丢弃小数；rate/source变更先积分旧rate至提交时刻，再启用新rate。
同事件时刻、同rate变化轨迹，仅改变采样分段不得改变P2总恢复。
Max同比后积分余数仍是原资源点的未入账小量，不随Max放大；满资源丢弃超额及余数，
不囤积未来回复；死亡/新life清除瞬时积分余数。这不是第二份可写HP/MP或另一时钟。

奖励以 HP 从正变零的唯一致死事实为基础。XP、金币和派生升级机会应先同时 Prepare，
在同一可去重提交边界兑现，不能先改 Ledger 再执行可能失败的 `AwardXP`。
来源 Pawn 已死但所属参赛者仍在局内，不影响已合法释放效果的奖励归属；无合法所有者则不发奖励。
参赛者离局不是死亡，不发离开奖励。回位只是存活生命的 reset，不发奖、不创建新获奖生命。

沿用 int64 账本与 `净金币变更 = Mint - Burn` 审计。每个真实新死亡 receipt 获一次明确 Mint 权，
不是整局预存有限次数的奖励预算；出售退款与消费实例也须在同笔事务中核对。
极长局如果碰到技术整数/累计审计边界，必须明确失败并记录，不能 wrap、静默饱和或声称已正常发奖；
不以预设超大预算、NPC 钱包或刷新轮数限制冒充无限循环。

## 12. 原生消费者、命令与结果验收

### 12.1 账本定义依赖的最小抽取

当前 `LDEconomyLedger.h:3` 包含 Inventory 类型，`LDEconomyLedger.cpp:61–64` 通过
`LDInventory::UnitWeight` 校验定义；后者又加载旧 Equipment/Acquisition。
必须同时拆除头文件与运行查询边，不能只把重量改成0或信任调用者传来的 `bKnownDefinition`。

拟议纯接口为不可变 `FValidatedItemDefinitions::Check(FItemDefinitionId, EItemOp)`，
返回明确的 UnknownId/RetiredId/UnsupportedOperation 等结果；由唯一 Demo 编译/导入阶段
对照 stable ID、原生 handler 与所有字段约束构造。调用者没有修改快照或任意返回 true 的回调入口。
定义 ID 与 Create/Transfer/Consume 等纯值类型抽出 Inventory/UObject 依赖，
保留已有编号；Transfer 原语不意味着开放玩家交易。

现有 `FLedger::Initialize` 接收该只读定义快照，`Commit` 在内部调用 Check 后仍执行所有
所有权/revision/实例/金额/receipt 预检。现有 `Reconcile` 的重放使用**同一份**局内内容快照，
不重新加载“最新目录”。快照保持至该局账本/审计结束，新局重新建立；Ledger 不加载 UObject、
不访问 World、不读旧 catalog。这是改造同一个账本，不是新增权威经济系统。
正式 C++ 类型/文件由成长装备经济域按这条依赖约束封口，以上名称是目标接口，不冒充现存 API。

### 12.5 UI/AI可读定义与显示引用

不可变内容定义是公开知识，AI可以读取目标模式、固定价格/费用、属性与效果规则，
不能由此取得某个隐藏单位当前HP、装备实例、源CD或营地刷新实况。自身能力可用性、
每个IssuedCooldownId剩余时间和实际资源从本人授权投影读取，不从目录值猜测“已经ready”。

显示元数据统一为 `DISPLAY.<contentId>.NameKey/DescriptionKey/IconId`；
本地化namespace为 `DemoContent`，键分别为 `<contentId>.name`、`<contentId>.description`，
占位图标语义ID为 `icon_<contentId>`。这些规则适用于角色、六个角色技能、五张卡、
七件装备和两种怪物；具体中文名称用本报告目录中的名字。
基础头像另用 `DISPLAY.character_demo.PortraitIconId=portrait_character_demo`。
这是拟新增原生资源/本地化引用，不宣称图标已生成；Bootstrap须核验解析，不静默用缺失资源。
占位图形可用自有箭头、护盾、锁链等简单轮廓与文字，不能复制外部游戏素材，也不能只靠颜色分辨。

公开状态另登记 `StatusDefinitionId=camp_returning`（“回位中”）及对应
`DISPLAY.camp_returning.NameKey/DescriptionKey/IconId`。
它从当前合法可见的 `WorldView.Statuses` 读取，无层数、截止、Home坐标、仇恨或内部phase，
不是新增Buff、无敌或可攻击性开关。UI/AI不能绕过该视图自行读取Camp状态。

描述采用typed字段命名参数展示等级/伤害类型/系数/费用/基础与有效CD/射程/状态期限。
UI不能硬编码一套伤害或CD公式；最终 `STAT.MoveSpeedCmPerSec`、`STAT.AttackRangeCm`、
当前资源和来源剩余CD从同一只读投影提供。纯属性/被动装备没有主动入口，1/2明确不可用。

可见对手按用户确认显示名称/等级/HP/MP/公开临时状态/装备**定义**；
不发送私有物品实例、IssuedCooldownId、技能列表、技能等级/CD、其他属性贡献或金币。
永久学习被动不能伪装成“公开状态”泄露技能构筑。失视野清检查目标/锁定并停止该追击订单，
不保留地图LastSeen单位标记；地图地形/固定地点仍可见。
死亡可以自由拖动静态地图，但不增加活体观察源，也不跟随隐藏玩家。
镜头速度/缩放/边缘带由UI与操作域作为本地设置维护，不是本报告的玩法平衡参数。

终局只展示用户确认的全员名称、击杀、死亡、最终等级、唯一赢家、结束原因与用时。
这些统计只描述结果，绝不能代替连续独占判胜或建立超时积分胜利。
