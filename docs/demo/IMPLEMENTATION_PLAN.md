# Demo 实施计划

本计划把 [App Spec](../APP_SPEC.md) 转成实施依赖和交付门槛，
不另设玩法规格或数值。当前判断见 [就绪评估](READINESS.md)，
共同边界见 [共享契约](SHARED_CONTRACTS.md)，现有运行命令见 [开发指南](../DEVELOPMENT.md)。

**本计划定义完整 Demo 的实施依赖，不是完成声明。** 当前已有入口/身份、内容编译和
本地设置，以及批准输入到唯一静态世界的生成/加载/几何导航检查；各切片仍须补齐其实际退出证据。
静态世界子片不代表 I2 的稀疏观察、真实运动和拥有连接全部完成。未批准的后续候选输入不得进入运行，
不能以文档齐备、局部构建或拒绝路径通过代替可玩闭环。

**2026-11-02 用户已批准现有完整首版内容与数值、现有单层布局作为唯一 Demo 地图，
以及[操作§4.2](CONTROLS_AND_TARGETING.md#42-右键普攻与-a-攻击移动)的自动选敌/续行规则。**
批准范围是首次实际实现/试玩输入，不是平衡、原生、资产或联网通过；这三项不再作为等待决策的阻塞。

2026-11-02 批准的校园换皮第一批仅更新名称、术语和文案文档，不改 ID、显示键、已批准首版数值、运行输入或资产。
校园构筑扩展在核心 Demo 对局、联机和新局隔离等门槛通过后，按低/中/高成本与真实依赖分批接入；
范围、建议值和成本清单只在[内容报告 §15](CONTENT_AND_BALANCE.md#15-后续批次校园构筑扩展已批准方向未进入运行输入)维护。

## 实施原则

- 收敛现有运行入口到唯一 Demo 流程，不以新的平行模式绕开旧入口。
- 复用现有 CharacterMovement、导航、命令/回执、战斗、事务和视野边界。
  对旧产品系统做真实删除，对必要底层能力做有依据的保留/改造/抽取。
- 每次切片同时处理生产者、消费者、序列化、生成输入、资产依赖、入口和验证。
  不保留为旧模式兜底的兼容壳，也不先删依赖再把失败断言关掉。
- 不以旧 SourceData 值代替首版设计，不以“临时默认值”填接口；
  待审数值明确标注，批准后才进入对应运行输入。
- 并行开发按接口所有者和资产负责人分工；共享头文件、核心配置和二进制地图先协调。
  使用独立工作区与 PR，已共享提交只用新提交修正或 merge 同步，不改写历史。

## 文档输入门槛

这些门槛用于设计输入及其变更的审查，不限制已经明确委派的代码实施任务；
设计审核也不替代下面的原生与真实场景验收。

| 门槛 | 通过条件 | 未通过时允许推进什么 |
| --- | --- | --- |
| D0：基础实施边界 | 已确认单 Demo 范围；知道现有复用入口、不可破坏的不变量和代码所有权 | 可实施相应基础接线、局部纯规则与读模型；不跨越尚未批准的玩法/数值边界 |
| D1：模块可实施 | 相应领域设计与实际入口对应，正式接口、参数引用、失败/生命周期语义和验收明确 | 仅已封口模块可进入后续代码任务；不得用猜测跨接尚未确定的接口 |
| D2：完整设计包齐备 | 八领域、架构闭包、共享契约、首版候选内容/公式、审批状态及§11验收齐全且一致 | 允许以完整候选进入PR审查；未批准参数不进正式运行输入，原生/资产/联机尚未执行不冒充通过，也不混作缺少文档 |
| D3：文档 PR 可交付 | 独立集成审核完成，链接/源码引用/文档范围一致；所有未解阻塞明示，协调者确认包齐备 | 才创建面向 main 的完整文档 PR；不提前开不完整 PR，不擅自合并 |

D2 本身只说明文档输入齐备；现有三项方案另外已获2026-11-02用户批准。
正式运行输入应精确落地该批准方案，C3/C4、原生接线和真实连接仍是实施验证门槛。
若最终总审发现未关闭的文档矛盾或真正缺失的设计，应修正或明确报告，不能归入“以后再验证”。

网络、交易、成长与胜负至少需要可见 Listen Host 和真实拥有客户端的证据，
满规模另覆盖三真人加三 AI；局域网与正确配置的公网直连分别记录。

明确写出通过、失败、未运行、未实现；不引用历史运行报告作为当前证据。
