# Demo 实施计划

本计划把 [App Spec](../APP_SPEC.md) 转成实施依赖和交付门槛，
不另设玩法规格或数值。当前判断见 [就绪评估](READINESS.md)，
共同边界见 [共享契约](SHARED_CONTRACTS.md)，现有运行命令见 [开发指南](../DEVELOPMENT.md)。

**当前工作仅为文档准备。** 下列代码、数据、资产和测试改动都是后续实施范围，
不是本轮已完成事项；不要据此顺带裁剪工程或运行生成器。

## 实施原则

- 收敛现有运行入口到唯一 Demo 流程，不以新的平行模式绕开旧入口。
- 复用现有 CharacterMovement、导航、命令/回执、战斗、事务和视野边界。
  对旧产品系统做真实删除，对必要底层能力做有依据的保留/改造/抽取。
- 每次切片同时处理生产者、消费者、序列化、生成输入、资产依赖、入口和验证。
  不保留为旧模式兜底的兼容壳，也不先删依赖再把失败断言关掉。
- 不以旧 SourceData 值代替首版设计，不以“临时默认值”填接口；
  待审数值明确标注，批准后才进入对应运行输入。
- 并行开发按接口所有者和资产负责人分工；共享头文件、核心配置和二进制地图先协调。
  使用独立工作区与 PR，已共享提交只用新提交修正或 merge 同步，不改写历史。

## 文档包的职责

下表约定领域交付文件名。未接入的文件只用代码文本标识，不创建空文件或指向不存在文件的链接。
领域报告提供目标实现设计，`docs/systems` 继续准确描述当前可复用组件；
未实现的目标接口不能直接改写成系统手册中的现存事实。

| 文档/领域 | 必须包含的非空内容 |
| --- | --- |
| 经审核的 Demo-only 架构裁剪说明 | 唯一运行链；可复用、改造、抽取和真实删除的精确闭包；配置/资产/数据/工具/测试联动及验证 |
| `SESSION_MATCH_LIFECYCLE.md` | 会话/房间/准入/旅行/断线、名单、对局阶段、占点同刻顺序、死亡/复活/保护、终局和新局矩阵 |
| `CONTROLS_AND_TARGETING.md` | 全部 Spec 输入、点击分派、持续攻击/攻击移动、目标模式、可见性重查、取消、UI 捕获与镜头/绑定接线 |
| `COMBAT_AND_ATTRIBUTES.md` | 属性来源与投影、公式引用、动作/命中/控制、效果归属与生命周期、伤害和死亡提交边界 |
| `PROGRESSION_EQUIPMENT_ECONOMY.md` | 奖励归属/去重、逐级选择队列、持久候选、替换/遗忘、两装备、买卖原子性、来源冷却和死亡保留 |
| `WORLD_CAMPS_AND_VISION.md` | 单图地点/合法路径、十点等概率落地、五组两难度营地、回位/刷新、观察协议、公开例外和隐私验证 |
| `OPPONENT_AI.md` | 自身/合法视野/公开圈感知；同一权威接口；打野/选择/购物/战斗/撤退/恢复/争圈/复活策略；拒绝和重试 |
| `UI_AND_SETTINGS.md` | 菜单到结算全部界面、字段权限/读模型、失败反馈、头像/名字/被动/冷却、按键与镜头、设置保存与恢复默认 |
| `CONTENT_AND_BALANCE.md` | 基础角色、技能三级、属性卡、装备、营地首版目录；公式/数值单一参数表；依据、验算、审核状态和运行输入映射 |
| [共享契约](SHARED_CONTRACTS.md) | 所有权、身份、单位/取整、来源冷却、命令/事件/读模型和全生命周期的跨文件唯一解释 |
| [就绪评估](READINESS.md) | 每项 Spec 的实际证据、缺口、开工门槛与结论；不把建议、旧代码或静态阅读升级为运行通过 |

每份领域报告必须携带共享契约 SC-09 的对接表，并区分已确认产品规则、
已核验实现、待审设计、未实现接口和未来验证。数值只由内容报告维护，
其他领域引用正式键；有分歧时收敛成一个当前方案，不保留逐轮讨论档案。

## 文档输入门槛

| 门槛 | 通过条件 | 未通过时允许推进什么 |
| --- | --- | --- |
| D0：基础实施边界 | 已确认单 Demo 范围；知道现有复用入口、不可破坏的不变量和代码所有权 | 可做基础接线设计、局部纯规则/读模型设计；本轮仍只提交文档 |
| D1：模块可实施 | 相应领域设计与实际入口对应，正式接口、参数引用、失败/生命周期语义和验收明确 | 仅已封口模块可进入后续代码任务；不得用猜测跨接尚未确定的接口 |
| D2：完整输入齐备 | 八领域、架构闭包、共享契约、首版内容/公式一致；需产品批准的设计有明确结论；§11 验收齐全 | 在此之前不宣称整体 implementation-ready，不用旧参数补完整对局 |
| D3：文档 PR 可交付 | 独立集成审核完成，链接/源码引用/文档范围一致；所有未解阻塞明示，协调者确认包齐备 | 才创建面向 main 的完整文档 PR；不提前开不完整 PR，不擅自合并 |

可提交待审内容的完整文档 PR，供用户决定首版设计；这并不自动满足 D2 的参数批准条件。
如果审核后仍存在产品选择，PR 的就绪结论必须明确哪些实施切片仍被阻塞。

## 验证设计与现有入口复用

具体场景由领域报告给出前置、动作、断言、实际参数、拥有连接和输出。
下表只说明当前入口能从哪里复用，不声称它们已经验证了目标 Demo。

| 层次 | 当前起点 | Demo 必须增加或迁移的断言 |
| --- | --- | --- |
| 文档 | 相对链接、源码/脚本符号核对、`git diff --check` | 不存在空模块/失效链接；目标/现状/建议分明；参数单点；评估结论不过度 |
| 内容/生成 | 对应 `Sync* --check`、`Test*Import.py`；现有例子为 `SyncB84Data.py`、`SyncV09Data.py` | 实际首版目录/参数可生成；非法值/不合法引用拒绝；载荷/contract 一致；禁止手改摘要 |
| 原生与资产 | `BuildEditor.ps1`、`BuildGame.ps1`、`BootstrapAssets.ps1 -Mode Validate` | 删除后没有反射/链接/Cook 悬空依赖；唯一入口和地图资产仍可加载 |
| 规则 | `RunTests.ps1` 和相关原生规则测试 | 新属性/成长/装备/胜利断言；保留身份/取消/事务不变量；更新旧测试数量与专用测试名门槛，而非仅降低要求 |
| 输入/路径/UI | `RunMovementCheck.ps1`、`RunNavigationCheck.ps1`、`RunInputCheck.ps1`、`RunHUDCheck.ps1` | A/右键/S/Esc、目标预览与重查、UI 手势唯一消费者、阻挡/失焦/死亡/迟到确认 |
| 战斗/观察/来源 | `RunCombatCheck.ps1`、`RunCombatNetworkCheck.ps1`、`RunViewNetworkCheck.ps1`、`RunLoadoutCheck.ps1` | 真客户端命中/重复拒绝、隐藏/过期、冷却换槽/遗忘/重购/死亡、控制与保护 |
| 奖励/买卖 | `RunInventoryCheck.ps1`、`RunVendorCheck.ps1`，复用有效事务规则 | 一次死亡一次金币+经验；两件容量；金币不足/离店/死亡/终局/旧报价/重复/创建失败均无部分提交 |
| 生命/胜利 | `RunResetCheck.ps1`、`RunObjectiveCheck.ps1`、`RunObjectiveNetworkCheck.ps1` 的可复用夹具 | 用 Demo 断言替换旧 Heart/deadline/死亡税：同刻争夺、保护、保留、新局拒绝；不保留旧玩法验收入口 |
| 世界/AI/完整对局 | 相关当前地图/网络夹具与新增目标场景 | 五营地两难度、十点等概率、AI 非全知完整循环、无调试授予；不能把现有世界或席位检查直接改名为通过 |
| 交付 | `VerifyCleanCheckout.ps1`、`PackageWin64.ps1`、`OpenPackaged.ps1` | 明确本地 LFS 缓存检出不证明远端下载；发布包实际运行/连接/完整对局后才认定可用 |

网络、交易、成长与胜负至少需要可见 Listen Host 和真实拥有客户端的证据，
满规模另覆盖三真人加三 AI；局域网与正确配置的公网直连分别记录。
同机脚本和 Host 全知调试只覆盖各自边界，不能替代远端拥有客户端、网络配置或公网可达性。

无须为本次纯文档变更运行昂贵 Unreal 场景。后续实现按最小覆盖命令逐步扩大，
明确写出通过、失败、未运行、未实现；不引用历史运行报告作为当前证据。
运行输出写入忽略的 `Artifacts`，不将日志和快照堆入产品文档。
只保留一个已确认可用发布构建，新交付成功前保留它，失败候选不当作可用版本。

## 集成审核与 PR 交付

领域包齐备后，由未兼任领域作者的独立集成审核者检查：

- Spec 每一要求都有对应模块、共享契约与验证；八领域覆盖架构子模块，无职责漏项。
- 状态所有者、类型映射、单位、时序、来源冷却、参数键和权限一致；
  没有 UI/AI 直写权威、重复结算或相互矛盾的死亡/新局处理。
- 内容目录能支撑三选一和不同构筑，数值有依据、取整/边界及验算；
  没有把提案或旧输入写成用户批准/平衡通过。
- Demo-only 删除方向与实际依赖闭包一致；现有系统手册保留真实组件知识，
  不被尚未实现的目标架构冒充。
- 文件/符号/脚本引用真实、导航完整，无空模块、失效链接、废弃备选方案或会话纠错档案。
- 本次提交仅限 docs 与必要入口文档；没有 Source、Config、Content、SourceData 或 Scripts 改动。

审核问题在文档中修正，确实未解决的产品阻塞明确列入就绪结论和 PR 说明。
最终 PR 面向 `main`，说明实际文档范围、设计审核状态、已做/未做的检查及限制；
不声称代码已收敛、不声称 Demo 已实现，也不在未经授权时合并。
