# Demo 共享契约

本文件集中跨领域必须一致的语义，避免各模块分别创造身份、计时、冷却、经济或读模型。
产品行为来自 [App Spec](../APP_SPEC.md)；当前接口来自
[系统手册](../DEVELOPMENT.md#按任务读取系统手册)。
就绪范围和依赖见 [评估](READINESS.md) 与 [实施计划](IMPLEMENTATION_PLAN.md)。

**这是目标接线契约，不是已实现 API 清单。** 标为“现有”的字段已经核对源码；
语义字段用于模块对接，不宣称同名 C++ 类型、RPC 或数据 schema 已存在。
正式类型/容器/函数由经审核的领域设计绑定到现有组件，不能据此再造一个通用状态系统。
首版参数数值只由内容与数值设计集中维护，本文件不设置数值默认值。
[架构审计](ARCHITECTURE.md) §4 保留这些边界的源码证据和裁剪理由；
本文件集中共同语义，领域报告提供正式签名，不维护互相独立的契约版本。

## SC-01：唯一状态所有者

这里的所有者是权威责任，不要求新增同名 Manager。领域服务提交变更，
OwnerState、GameState、UI 和 AI 消费适当投影，不能互相回写成多份可写真相。

| 状态 | 唯一权威责任 | 允许的消费者 | 对接时必须明确 |
| --- | --- | --- | --- |
| 房间成员、Host、准备、AI 数量、准入 | 服务器会话/对局域 | Lobby 公共名单、拥有者连接反馈 | 连接与参赛者身份映射；开局锁名单；离开与 Host 结束 |
| 本局身份、阶段、占领、终局 | 服务器对局域 | 明确公开的阶段、圈状态和最终结果 | 唯一时钟与一次性结果提交；不公开隐藏身体状态 |
| 参赛者成长、技能、待选机会和候选 | 服务器参赛记录中的成长域 | 自身 UI；该 AI 的自身状态 | 跨 Pawn 生命周期保留；选择原子提交；新局清空 |
| 金币、装备实例与来源绑定 | 服务器经济/装备事务域 | 自身余额/装备、合法商店报价、战斗派生属性 | 与参赛记录/账本的唯一真实存储及只读投影关系，不允许两端独立改钱 |
| 身体位置、生命、血蓝、动作、控制 | 原生运动与服务器战斗/生命域，各管其本职 | 自身预测/状态、获准观测表现 | 持久参赛者与短寿命身体分离；死亡提交只有一处 |
| 地图地点、营地生命、刷新、回位 | 服务器世界/营地域 | 静态公共地点；获准的动态观察 | 地点定义与 Actor 分离；营地回位不制造死亡或奖励 |
| 观察权限、句柄、可见集合 | 服务器视野域 | 每个拥有连接；对应 AI 的受限感知 | 不让镜头、Widget 或 AI 从其他状态表补全隐藏信息 |
| 名称、本地设置、输入捕获、镜头偏好 | 本地用户设置与输入层 | 本地 UI/镜头，名字按名单契约公布 | 不保存局内战力、金币、技能、候选或冷却 |

现有接线锚点：`ALDGameMode::StateFor/ContenderId`、
`FLDOwnerState`、`ALDGameState`、`LDEconomy::FLedger`、
`ULDNavigationComponent`、`ALDCombatDirector`、`ALDVisionDirector`。
这些组件的旧玩法字段不是全部保留名单；目标存储绑定要与最终架构裁剪清单一致。

## SC-02：身份、代次与请求

| 语义 | 现有表示或入口 | 目标必须保留的约束 |
| --- | --- | --- |
| 一局的身份 | `FLDOwnerState.Match` / 观测 `Generation` 为 `uint32`；账本 `Initialize` 接收 `FGuid Match` | 不同表示必须有明确映射和相同换局边界，不能强转后当成同一类型 |
| 参赛者 | `FLDContenderRecord.Session`、`ContenderId` | 身份独立于 Pawn、槽位、显示名字和 UI；真人/AI 都能作为伤害、奖励和胜者所有者 |
| 身体生命 | 自身 `Life`；效果也有来源/目标 life 身份 | 新生命拒绝旧身体的请求、命中、观察和确认；与参赛者持久状态不同 |
| 移动与取消 | `FLDMoveIdentity.Match/Life/Order/Epoch` | 新 order 和 Stop/epoch 拒绝迟到确认；不得重启已取消路线 |
| 施法请求 | `FLDTacticalRequest` 的 `Token`、`BuildRevision`、`InventoryRevision`、`ItemRevision`、`CatalogDigest` | 服务端重查来源、实际绑定、资源、状态和观察权限；槽位不是来源身份 |
| 交易与奖励提交 | 商店 `Request/Session/QuoteRevision`；账本 `FTransaction.Id/Cause` | 每次业务结果有稳定去重身份；重放不再次改金币、装备或奖励 |
| 状态与观察修订 | 自身/构筑/库存的 revision；观测的 generation/revision | 各领域版本含义独立；不得用一个“最新版本”代替全部合法性 |

每个目标命令必须交付：调用者由谁确定、所需 match/life、领域请求 ID、
预期版本、目标/来源身份、入参上限、接受条件、最终回执、去重范围和失效条件。
只传该命令确实需要的字段，不给所有请求机械套一个庞大公共封包。

生命周期敏感性必须逐命令说明。候选和选择机会可以跨死亡保留，
不表示死亡前的施法、购买或移动请求可以操作新身体。
若设计允许在死亡界面选择，应走当前参赛者状态的合法选择路径，而不是伪造一个存活 Pawn。

保留窗口内重复提交已接受的请求只重放其既有结果；过窗后明确拒旧并提供当前状态或合法查询，
不能因清除有界回执缓存而重新执行。领域须说明查询/重放窗口及拒旧水位，
不把无限时长对局解释成无限保存表现回包。同一请求 ID 携带不同内容不能作为新操作。
Pending 只表示等待，不是成功。拒绝必须有可理解且不泄露隐藏信息的原因。
真人身份从拥有连接解析，AI 身份从服务器分配的参赛记录解析；共用领域验证，
不要求 AI 伪造客户端 RPC 或网络连接。

## SC-03：时间、单位与同刻提交

现有接口同时存在 `double/float` 秒、`int64` 毫秒，
以及 `LDTactical::Milliseconds` 转换入口。统一语义不要求粗暴全库换单位。

| 量 | 对接要求 |
| --- | --- |
| 世界位置、半径、射程、路径长度 | 明确使用 Unreal 厘米；标出平面距离、空间距离或表面路径，不能混用 |
| 移动速度 | 明确厘米/秒；属性修正先按统一公式投影，再接原生运动 |
| 时长与绝对时间 | 参数表标明秒；运行接口逐字段标明秒/毫秒及“时长/本局截止时刻”，在边界集中转换 |
| 金币、经验、计数、等级 | 服务器有界整数；奖励、售价和阈值转换的取整点由内容公式明确 |
| 比率、概率、暴击、减伤、攻速、冷却属性 | 每项标明量纲、有效范围和表示法，不把百分数、倍率和整数百分比互换 |
| 血蓝和其他连续属性 | 由战斗契约确定计算类型、截断/封顶顺序；UI 格式化不能反向改结算 |
| 显示倒计时 | 使用同步的服务器时间与截止状态；客户端显示到零不能自行复活、刷新技能或判胜 |

公式表必须给出运算顺序、上下限、取整位置、非有限/非法输入拒绝以及可复算例子，
不能只列属性名称。与数值无关的单位和转换选择由工程封口，不需要产品逐字段决定。

**同刻硬约束：** 占领完成时必须看到同一结算时刻已发生的位置/资格变化、
到期命中和死亡，再重新判定是否仍连续独占。不能由独立 Actor Tick 先到者抢先判胜。
完成提交后的战斗、奖励、交易、选择和占领不能继续修改本局结果或战力。

连续性不能只靠最终位置快照重建。[架构审计](ARCHITECTURE.md) §4.5 明确的共同事件输入为：

| 责任 | 最低交接内容 |
| --- | --- |
| 运动/位移、生命/离开/保护提供者 | 局代次、参赛者与身体生命、事件来源、本流单调序号、服务器实际发生时间、圈内/有效资格变更 |
| 权威调度 | 区分事件实际时间与补算采样时间；固定同刻提交次序；记录每个提供者已发布到哪个时间边界 |
| 唯一占领归约器 | 等相关提供者水位就绪后消费到期边界，保留进入又离开/离开又返回的中间事件；判定后推进消费水位并释放记录，拒绝重复/旧局/旧生命事件 |

不能用已完成运动的当前姿态回填过去，也不能用被补算逻辑临时回拨的 World 时间给新事件打戳。
这不要求永久事件日志、第二套运动积分或网络回滚世界。事件产生点/时间所属由相关领域正式接线，
而不是占领 UI 猜测。先锁定结果并关闭写闸，再执行取消/清理和结果发布；
清理回调也不能产生新的玩法提交，已完成事务的只读回执重放不算再次提交。

生命周期、战斗、成长三个领域必须联合给出一个确定的批次顺序：
命令接受/释放、到期效果、死亡与奖励、复活、事务、占领重查、终局闸门、对外发布。
上述列表是需要排序的阶段，不预先声称当前代码已经按这个目标顺序执行。
特别要解释“奖励或交易与胜利同刻”落在哪侧，不能由各领域各自解释。

复用入口是 `ALDCombatDirector::Sample` 与适用的 `AdvanceAuthority`；
不能保留旧 deadline/Heart 规则作为另一套目标时钟。

## SC-04：死亡、终局、离开与新局

| 状态或操作 | 死亡/复活 | 普通客户端离开 | 终局 | 新局 |
| --- | --- | --- | --- | --- |
| 等级、经验、金币、技能、装备 | 全部保留，不重复初始化或发初始奖励 | 不再是有效参赛者；不是击杀，不发离开奖励 | 冻结为本局结果，拒绝继续变更 | 按批准的开局输入全新初始化 |
| 未用选择机会、已生成候选 | 保留原候选，不能重抽；提交资格由选择契约明确 | 清理未决请求，不把席位转给新加入者 | 不继续提交成长 | 清空旧机会、候选和回执域 |
| 来源冷却 | 按服务器时间继续；不因 Pawn 重建重置 | 旧来源不能继续提交命令 | 不继续释放动作 | 新局建立新的来源时间域 |
| 导航、追击、指向、未完成交互 | 取消适用动作，旧 life 的迟到消息无效 | 清理连接相关操作 | 清理未决动作并反馈结束 | 旧 match 无效 |
| 血蓝、临时控制、保护 | 复活满血蓝、清死亡前临时控制；保护按规则生效 | 身体不参与战斗或圈人数 | 不再复活或处理效果 | 按新局初始化，不复用旧期限 |
| 商店会话与未提交买卖 | 失效，死亡不能继续交易 | 失效 | 拒绝后续交易，不部分成交 | 重新建立会话/报价版本 |
| 占领状态 | 死亡者立即无效，保护者不推进也不打断 | 离开者无效，不自动给剩余玩家胜利 | 唯一结果提交一次 | 发育期、圈进度和结果全部重置 |
| 观察句柄、目标代理 | 更新/清除身体生命相关观察，不让旧目标复用 | 清理观察通道 | 按最终授权清理，不留下实时隐藏更新 | 全部换代 |
| 本地名称、按键、音量、画质、镜头偏好 | 保留 | 保留 | 保留 | 仅这类明确允许的本地设置可保留 |

Host 离开是会话结束，不执行普通客户端离开的继续对局路径；
客户端返回菜单并显示原因。Demo 不实现中途加入、断线重连或 Host 迁移。
遗留恢复/席位交接组件的存在不能改变这个边界。

已释放效果的取消范围、来源死亡后的存续、归属保存及消失时的表现清理，
必须在战斗与内容定义中逐类说明；“取消 UI”不等于回滚已提交效果。
任何继续存续的效果都不得伤害同 ID 的新生命或在终局后继续结算。

## SC-05：奖励、选择与装备事务

| 交接 | 生产者必须提供 | 消费者必须保证 |
| --- | --- | --- |
| 命中到死亡 | 本局、受害者身份/生命、最终致死效果及实际参赛者所有者、已提交死亡身份 | 生命域只结束一次；无合法参赛者所有者不指定奖励获得者 |
| 死亡到奖励 | 稳定死亡/奖励去重键、奖励目录引用、接收参赛者 | 经验和金币都归最后一击，不增加助攻/附近分摊；回位不是死亡 |
| 经验到选择机会 | 升级前后等级、增加的机会数及已提交奖励身份 | 等级最高十，机会最多九；满级不再增加，但已有机会继续保留 |
| 选择到构筑 | 固定候选组身份、三个不同合法选项、预期构筑版本、所选项与必要替换确认 | 效果、遗忘/装槽和机会消费一次原子提交；前一选择生效后才生成下一组 |
| 装备买卖到战斗 | 装备实例/定义、所有者、库存/构筑修订、来源绑定变化 | 同次提交更新属性/被动/主动可用性，移除来源不遗留悬空按钮 |
| 买卖到回执 | 会话/报价、请求身份、预期余额/库存/实例版本、成交结果 | 存活、进行中、实际距离与容量重查；满槽不自动替换；失败不部分改钱/物 |

正式设计须明确经验与金币是同一死亡事实下如何避免部分提交，
同时覆盖重复命中、持续伤害、同时死亡、死亡后收到奖励、死亡与选择/交易竞争。
奖励资格先看受害对象和关系：只对野怪或另一参赛者的合法击杀发奖，
自杀、离开清理、营地回位均不发奖。无主致死不能继承前一次伤害的所有者；
来源已经阵亡但仍在本局时，若存续效果确实击杀合法对象，奖励仍归实际所有者。
无奖励的死亡也记录已处理，不能稍后以新来源重试发奖。
候选生成的随机状态属于服务器；关闭页面、死亡和重发不重新抽取。

合法候选覆盖必须用实际首版目录验证：满技能等级、满 Q/W、连升多级及不同被动组合下，
仍能给出三张不同可兑现的卡。不能用三个相同属性卡、隐藏重抽或免费的自动选择补洞。
新技能候选只含未学技能，已学技能只能升级且最高三级，满级不再进入候选；
角色被动没有独立槽位上限，UI 容量不能增加隐含限制。

## SC-06：能力来源、冷却与派生属性

现有 `FLDActionRef` 已区分 Learned/Gear，并携带 Skill、Instance、Definition；
`LDV08::InvalidateSources` 和投影/版本检查是复用锚点，不是新槽位模型已完成的证明。

- 所有参赛者初始为近战单体普攻，装备或属性成长可以增加群攻效果和攻击距离；
  不固定为永久单体近战，也不因此强制投射物。内容/战斗域提供首版来源、几何和效果路径，
  仍走同一权威命中/归属/奖励链，不能由装备或 UI 独立追加一套伤害。
- 角色能力来自所学技能，装备能力来自真实装备实例。Q/W 与 1/2 是入口映射，
  不是四份独立能力状态；装备能力不消耗角色主动槽，也不通过三选一升级。
- 两个装备槽允许同时装备两件相同装备。相同定义的两件装备仍是不同实例，
  分别校验所有权和绑定；重复请求重放不能被当成第二次合法购买。
- 同款双持的基础属性加成相加，同名被动只生效一次。属性投影计入两件合法实例，
  被动不能因两件来源而重复注册或对同一触发重复生效；
  只卖出一件时，也不能误移除另一件仍提供的同名被动。
- 两份同款装备主动各自独立冷却，正常释放条件均满足时可连续使用两次。
  每份具有独立的持久来源冷却身份与显示状态，不能聚合成同款 family 的单个 `ReadyAt`。
- 来源身份必须同时解释所有权、当前绑定与持续锁定的冷却身份。
  只用槽位索引会被换槽绕过；只用新生成的装备实例 ID 会被卖出重买绕过。
- 来源冷却契约必须覆盖升级、换槽、遗忘后再学、卖出再买、死亡、重复请求和新局。
  这些路径不能凭重建对象消除尚未结束的冷却。
- 目录需要给出来源定义、适用冷却属性、叠加/互斥和触发限制。
  战斗与成长域共同定义每份装备的持久来源身份及重购回绑；
  新物品实例仍须继承其对应的未结束冷却，不能以独立冷却为由卖出重买洗掉旧期限。
- 卖出/遗忘等来源丢失期间，未结束冷却继续按服务器时间流逝，不冻结或清空；
  重新持有或重学时沿用对应持久来源的原结束时间，不重新起算或刷新。
  等待到原结束时间自然到期可以恢复可用；移除/重建来源本身不能加速到期。
  死亡期间已有冷却同样继续，只有新局才重建新的来源时间域。
- 构筑/装备变更只投影一次最终属性。最大血蓝变化时如何处理当前值、
  已释放效果使用来源快照还是实时属性，必须由战斗/内容契约明示。
  不另建 UI/AI 版公式。

动作无效不消耗资源，服务器负责最终合法性。
复活保护下的主动战斗必须在合法动作执行前解除保护；
验证、解除保护、消耗/冷却与释放的准确提交点由战斗和生命域共同固定。
无效进攻意图是否也解除保护仍须按架构 Q3 封口，不能把上句解释成已批准该行为。
装备主动是战斗命令：不依赖商店报价、购买余额、商店距离或空装备槽；
两个装备槽已满时，已有 1/2 仍可在店外和圈内按战斗规则使用，不因释放解绑。

## SC-07：目标、观察与读模型

世界模块统一定义正式的世界查询/观测签名：静态地标、可行走与视线阻挡、
出生锚点及同点合法落地、商店接近点、圈占用几何、营地成员生命、
每观察者可撤销句柄和失去视野后的拒绝。输入、AI、商店与占领域调用这些接口，
不各自扫描全局 Actor 或复制一套世界状态。核心只约束共同代次、提交顺序和公共读模型责任；
具体采用的单一路径与网格/稀疏协议接线由世界设计和架构裁剪共同封口。

| 读模型 | 允许字段来源 | 明确禁止 |
| --- | --- | --- |
| 自身 | 自身参赛/身体投影、合法回执和构筑派生结果 | Widget 改金币/HP；从对手结构补全自身未同步字段 |
| 可见单位 | 当前观察句柄、获准位置/朝向/表现和明确允许的检查字段 | 保存隐藏 Actor 指针；失去视野后持续更新状态或沿真实隐藏位置追踪 |
| 静态世界 | 地形与公开固定地点、合法地面目标 | 用不可见动态目标参与路径预览，借此暴露隐藏位置 |
| 全场公共 | 房间名单、占领开放/占领者/进度/争夺、胜者与结果、参赛者击杀通知 | 把通知附带成隐藏坐标、构筑、钱包或动态营地资源广播 |
| AI 感知 | 自身、与真人等价的合法视野、静态地图和公共占领信息 | 查询 GameMode/账本全表绕过感知，读隐藏敌人位置，直接改属性或发资源 |
| UI 状态 | 真实映射注册表、上述合法读模型及错误回执 | 遍历所有 Pawn/PlayerState 补 Tooltip；靠按钮禁用代替服务器校验 |

目标请求区分单位、地面、方向、自身；单位目标到达服务器时重新解析观察权限。
失去视野后的追击/已准备施法/选择面板/小地图必须共同失效或按明确允许的历史信息策略处理，
绝不能偷偷继续读实时隐藏位置。具体动作策略由操作、战斗和视野领域统一。

每个新增显示字段须同时声明：生产者、公开/自身/观察权限、match/life/revision、
失去权限后的清除、stale 表现和错误反馈。完整地图与网格观测格式须选定真实接线方案，
不能只修改数组上限假定协议兼容。
正常 Listen Host 的主画面、原生身体/附属表现、HUD 和目标解析也遵守同一授权，
不因持有服务器 Actor 而展示隐藏单位；原生与观察代理不能双重输出。
提示例外须同时审查产生端和发布端，不能只关旧技能而漏掉自动 Footstep/Trail 等旁路。
这些要求不承诺隔离或防作弊保护拥有权威进程的恶意 Host。

## SC-08：内容定义与参数引用

`CONTENT_AND_BALANCE.md` 是约定的领域交付文件名；正式接入后由它维护首版目录、
数值、公式、依据和审核状态。其他报告只引用它的稳定键，不复制另一份可独立修改的数值表。
下表是必须交付的参数语义，不是额外默认值，也不是已存在的 JSON 字段。

| 参数组 | 必须提供的精确信息 | 主要消费者 |
| --- | --- | --- |
| 对局/生命 | 发育时长、连续独占时长、复活延迟及适用变量、保护时长；全用明确时间单位 | 生命周期、占领、UI、AI |
| 空间/世界 | 地图尺度、圈几何参数、十点位置参数、商店范围、视野范围；可行走/视线/圈边界算法由世界模块定义并引用这些参数 | 世界、输入、战斗、视野、AI |
| 基础角色/属性 | 每项基值、等级成长、上下限、派生公式、资源回复；初始近战单体普攻射程/时序，以及装备或属性提供群攻/增程的首版路径，不强制投射物 | 战斗、成长、UI、AI |
| 伤害/概率/冷却 | 伤害类型与加成、抗性/暴击/攻速/冷却算法、叠加顺序、取整与边界例子 | 战斗、内容导入、UI |
| 经验/金币 | 初始资源、逐级经验阈值、参赛者/野怪奖励、无所有者致死处理引用 | 成长、营地、奖励、UI |
| 三选一 | 技能/属性候选 ID、抽取规则/权重、合法性条件、属性增量和实际覆盖分析 | 成长、AI、UI |
| 技能/状态 | 稳定定义 ID、主动/被动、三级效果、目标模式、射程/区域、蓝耗/冷却、来源身份、触发/叠加/控制语义 | 战斗、成长、输入、AI、UI |
| 装备/商店 | 定义 ID、价格/出售规则、属性、主动/被动、实例来源；支持两件同款，基础属性加成相加、同名被动只生效一次、两份主动独立冷却；持久身份/重购回绑与无套利验算 | 经济、装备、战斗、AI、UI |
| 营地 | 五组地点、两难度分配、每组成员定义/数量、战斗能力、追击/回位/重置、清空后刷新与奖励 | 世界、战斗、AI、UI |
| AI 决策 | 依赖的实际战力/资源/时间/距离量、营地与购物取舍、撤退和争圈阈值及其依据 | AI；不得形成第二套战斗或经济数值 |

每个条目需要稳定参数/公式键、类型与单位、范围、引用关系、依据、审核状态、
消费者和可验证的边界案例。文档中的键转入 SourceData 后要有明确生成器/载荷/contract 映射，
不能让运行时读取 docs，也不能直接修改生成哈希。

旧 `SourceData` 值只证明当前工程消费什么。产品版本、目录 schema、
原生枚举编号、RPC wire version、资产 ID 各有职责，禁止全库替换为产品版本号。

## SC-09：错误、取消与对接交付

错误至少区分：连接/版本/房间准入、旧 match/life、旧修订、无效或过期观察、
无合法路径、冷却/法力/控制限制、候选/替换无效、金币不足、装备满、商店越界、
死亡、终局与新局失效。正式错误码由相关模块定义并集中映射给 UI/AI，
不要求向客户端公开内部断言、隐藏目标身份或权威日志。

取消不能撤销已提交效果或退款，除非具体内容规则明确规定；
也不能复活旧 order、重抽候选、清理仍须保留的冷却或把 Pending 改成成功。
同一手势只能由 UI 或世界一个消费者接收，Esc/S/失焦/死亡的清理要共享输入边界。

每份领域设计交付时附下列对接信息，缺一项就不得宣称相关接口已可无歧义实施：

| 交付项 | 必须回答 |
| --- | --- |
| 状态与正式接口 | 写入者是谁，具体类型/函数在哪个现有组件上，哪些字段只是投影 |
| 命令与事件 | 参数/结果类型、身份、版本、来源、权限、提交阶段、拒绝和回执去重 |
| 生命周期矩阵 | 取消、死亡、离开、终局、新局分别保留/清理什么；已释放效果如何处理 |
| 内容引用 | 使用哪些正式目录/参数/公式键，单位和转换在哪里，是否仍是待审建议 |
| 接线与删除 | 替换哪些旧调用者/序列化/生成/资产/测试；删除后的依赖如何收口 |
| 验证 | 生产者/消费者共同的正反例、真实拥有连接条件、同刻与重放断言、未覆盖限制 |

出现跨文件矛盾时在这里与相应领域文档同时修正，不留两套解释或废弃备选方案。
