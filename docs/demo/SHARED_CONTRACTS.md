# Demo 共享契约

## 公共休息室接缝

GameMode 拥有当前 match/rest 配装窗口的真人准备集合；Controller 发送带 Generation/RestIndex/StepStartedAtMs 的准备意图，
同窗口重复准备幂等，跨窗口拒绝。AI 不阻塞准备；全真人准备只缩短到最后 `REST.SignupSec`，不能延长已开放报名。
休息、野外与 PK 继续复用唯一生命/Combat/运动/事务记录；公共可见与敌对效果准入分离，人物互见不表示能互相伤害或读取私有成长。
公共训练区的六个槽位为每位参赛者生成一个真实共享假人；休息室连接均可通过获准观察帧观察并合法攻击全部活体假人。
权威身体不直接复制，观察代理呈现同一目标的位置、生命、控制与受击；只有开放地面标线是纯展示，不设置静态假人替身。
目标保留生成时公开角色等级的无构筑底盘及独立身份，攻击来源取真实施放者；不披露所属玩家私有成长，也不把攻击者构筑投影到目标承伤状态。
OwnerState.NearbyRestService 仅是本人当前脚点的服务投影，Build 提交必须再查对应 NPC 与休息窗口，不凭 UI 打开状态授权。

本文件集中跨领域必须一致的语义，避免各模块分别创造身份、计时、冷却、奖励或读模型。
产品行为来自 [App Spec](../APP_SPEC.md)；当前接口来自
[系统手册](../DEVELOPMENT.md#按任务读取系统手册)。
验收状态见[就绪评估](READINESS.md)。

**这是跨模块语义契约，不是 API 清单。** 表中列出的类型与入口已在源码中实现；
其余语义字段用于说明模块之间的约定，具体签名以各领域报告和源码为准，不能据此再造一个通用状态系统。
核心类型和提交接口现在以 [会话与生命周期](SESSION_MATCH_LIFECYCLE.md) §4–6 为唯一正式提供者；
下列映射和领域转引必须与它一致，不建立同义的第二个核心头、时钟或驱动。
首版参数数值只由内容与数值设计集中维护，本文件不设置数值默认值。
本文件集中共同语义，领域报告提供正式签名，不维护互相独立的契约版本。

## SC-01：唯一状态所有者

这里的所有者是权威责任，不要求新增同名 Manager。领域服务提交变更，
OwnerState、GameState、UI 和 AI 消费适当投影，不能互相回写成多份可写真相。

| 状态 | 唯一权威责任 | 允许的消费者 | 对接时必须明确 |
| --- | --- | --- | --- |
| 房间成员、Host、准备、AI 数量、准入 | 服务器会话/对局域 | Lobby 公共名单、拥有者连接反馈 | 连接与参赛者身份映射；开局锁名单；离开与 Host 结束 |
| 本局身份、阶段、喷漆与守护、终局 | 服务器对局域 | 明确公开的阶段、喷漆区状态、涂鸦主人与守护进度（运行、暂停或冻结；守护只在主人独自在区内时计时）和最终结果 | 唯一时钟与一次性结果提交；不公开隐藏身体状态 |
| 本局结算记录 | 服务器参赛记录及唯一终局投影 | 终局后全部参赛者名称、击杀/死亡、最终等级、赢家、结束原因和用时 | 离局不丢结果行；不另建可写统计账本，不在局中借结果投影广播隐藏等级 |
| 参赛者成长、技能、待选机会和候选 | 服务器参赛记录中的成长域 | 自身 UI；该 AI 的自身状态 | 跨 Pawn 生命周期保留；选择原子提交；新局清空 |
| 身体位置、生命、血蓝、动作、控制 | 原生运动与服务器战斗/生命域，各管其本职 | 自身预测/状态、获准观测表现 | 持久参赛者与短寿命身体分离；死亡提交只有一处 |
| 地图地点、营地生命、刷新、回位 | 服务器世界/营地域 | 静态公共地点；获准的动态观察 | 地点定义与 Actor 分离；营地回位不制造死亡或奖励 |
| 观察权限、句柄、可见集合 | 服务器视野域 | 每个拥有连接；对应 AI 的受限感知 | 不让镜头、Widget 或 AI 从其他状态表补全隐藏信息 |
| 名称、本地设置、输入捕获、镜头偏好 | 本地用户设置与输入层 | 本地 UI/镜头，名字按名单契约公布 | 不保存局内战力、经验、技能、候选或冷却 |

现有接线锚点：`ALDGameMode::StateFor/ContenderId`、
`FLDOwnerState`、`ALDGameState`、
`ULDNavigationComponent`、`ALDCombatDirector`、`ALDVisionDirector`。
这些组件的旧玩法字段不是全部保留名单；目标存储绑定要与最终架构裁剪清单一致。

## SC-02：身份、代次与请求

| 语义 | 现有表示或入口 | 目标必须保留的约束 |
| --- | --- | --- |
| 一局的身份 | `FLDOwnerState.Match` / 观测 `Generation` 为 `uint32`；`FLDMatchContext.LedgerMatch` 为同局 `FGuid` | 不同表示必须有明确映射和相同换局边界，不能强转后当成同一类型 |
| 参赛者 | `FLDContenderRecord.Session`、`ContenderId` | 身份独立于 Pawn、槽位、显示名字和 UI；真人/AI 都能作为伤害、奖励和胜者所有者 |
| 身体生命 | 自身 `Life`；效果也有来源/目标 life 身份 | 新生命拒绝针对旧身体的命中/观察及旧生命输入/确认；持久参赛状态与已接受独立效果不等于新动作请求 |
| 移动与取消 | `FLDMoveIdentity.Match/Life/Order/Epoch` | 新 order 和 Stop/epoch 拒绝迟到确认；不得重启已取消路线 |
| 施法请求 | `FLDTacticalRequest` 的 `Token`、`BuildRevision`、`CatalogDigest` | 服务端重查来源、实际绑定、资源、状态和观察权限；槽位不是来源身份 |
| 奖励提交 | 死亡 `FLDDeathKey` 与奖励回执 | 每次业务结果有稳定去重身份；重放不再次发经验、机会或奖励 |
| 状态与观察修订 | 自身/构筑的 revision；观测的 generation/revision | 各领域版本含义独立；不得用一个“最新版本”代替全部合法性 |

目标核心映射如下，完整字段定义只在生命周期报告 §4/§6 维护：

| 跨域语义 | 正式类型/入口 | 集成约束 |
| --- | --- | --- |
| 比赛双身份 | `FLDMatchContext` / `GetMatchContext()` | Generation 为网络 `uint32`，LedgerMatch 为同局 `FGuid`，一一绑定；不得强转 |
| 主体与身体 | `FLDVictimKey` / `FLDCombatBodyRef` | Kind/EntityId/Life 标识参赛者或营地成员生命，BodyIdentity 标识实际身体；不使用 Controller/槽位替代 |
| 死亡去重 | `FLDDeathKey` | 仅 LedgerMatch + Victim；来源、效果、DeathSerial、时间和 CampGeneration 不进入可领奖主键 |
| 生命阶段与变化 | `ELDLifePhase` / `FLDLifeNotice` | 阶段与 Life 不混同；LifeRevision 为生命通知版本，不代替订单/动作版本 |
| 时间与事件 | `FLDAuthorityStep`、`FLDAuthorityBoundary` | 使用核心定义的原始秒、发生桶和消费边界，不重建另一组 timestamp/watermark 字段；CT06 的提供者封桶（正式 Fence/Sealing）尚未实现 |
| 写权限与保护意图 | `FLDGameplayWritePermit`、`FLDAggressiveIntent`、`FLDProtectionReceipt` | 核心发放当前借用作用域，最终提交再验证；禁止网络自填/跨帧保存许可 |

每个目标命令必须交付：调用者由谁确定、所需 match/life、领域请求 ID、
预期版本、目标/来源身份、入参上限、接受条件、最终回执、去重范围和失效条件。
只传该命令确实需要的字段，不给所有请求机械套一个庞大公共封包。

生命周期敏感性必须逐命令说明。候选和选择机会可以跨死亡保留，
不表示死亡前的施法或移动请求可以操作新身体。
死亡等待可加点、选择并学到空槽、学图纸、安装/拆下构件或确认构件奖励，走当前参赛者的构筑提交，不要求伪造一个存活 Pawn；
不能替换或遗忘主动，也不能办理休息服务。
身份、Match/Life、`ExpectedLifePhase`、候选/构筑版本、去重和终局闸仍须校验；
Alive 时发出的旧确认不能在同 Life 的 Dead 阶段消费，旧生命确认也不能应用到新身体。

动作请求与服务器动作身份分开：`FLDCombatRequestKey` 的 Direct 使用调用者的
`DirectSequence`，Nav 使用服务器 Navigation 绑定的 MoveIdentity/AttackCycle。
完整准入后才由 Combat 分配 authority Token；Queued 可无 Token，取消/查询不得拿
server Token 代替原 RequestKey 或本地已发出的 Direct 上界。Nav 键不能由客户端/AI伪造。
保护意图的 OriginCombat 序列对应 DirectSequence，Nav 对应原 Order/Epoch；
不会为了同一次派生普攻再生成一条全域序号。正式动作键由战斗域定义，M3/AI只消费。

跨战斗/成长/UI/AI 的标量与编码以
[成长 §3.1](PROGRESSION_AND_REWARDS.md) 和
[战斗 §3.2–3.3](COMBAT_AND_ATTRIBUTES.md) 的同一合同为准：
业务实例/Offer/Option/IssuedCooldownId 是 FGuid；对应 Build/Account/
Progression/Offer/SourceBinding/Readiness 修订为 uint64，资源 P2 与 XP 为 int64。
`FLDCatalogDigest` 在 wire 中为 32 raw SHA-256 bytes，显示才是64个小写十六进制字符；
技能 DefinitionId 使用固定64字节UTF-8缓冲，最多63字节内容、NUL终止、余字节零填充，
严格校验后再构造FName。坏编码属于前置shape拒绝，合法编码但未知/非规范的目录引用
按所属领域语义拒绝；Combat不能借此跳过已识别进攻意图的保护解除。
此规则不擅自覆盖世界ID、观察修订或现有MoveIdentity的独立类型。

Choice 查询统一使用 `FLDReceiptQuery{Generation, Family, RequestId}`，
先拒旧局/错误Family，再返回对应 `FLDChoiceReceiptQueryResult`。
LookupStatus 为 Pending 时只有 PendingInfo，Final 时只有匹配业务 Receipt；
NotFound/ReceiptExpired/InvalidContext 均不携带两者，不伪造 OriginalLife 或 Applied/Rejected。
业务历史只读结果不能覆盖新身体；Queued/查询/缓存过窗都不授权用新ID重做同一操作。
精确载荷和枚举由 [成长 §8](PROGRESSION_AND_REWARDS.md) 单点定义，不混用订单查询的 Expired 名称。

保留窗口内重复提交已接受的请求只重放其既有结果；过窗后明确拒旧并提供当前状态或合法查询，
不能因清除有界回执缓存而重新执行。领域须说明查询/重放窗口及拒旧水位，
不把无限时长对局解释成无限保存表现回包。同一请求 ID 携带不同内容不能作为新操作。
Pending 只表示等待，不是成功。拒绝必须有可理解且不泄露隐藏信息的原因。
真人身份从拥有连接解析，AI 身份从服务器分配的参赛记录解析；共用领域验证，
不要求 AI 伪造客户端 RPC 或网络连接。

## SC-03：时间、单位与同刻提交

现有接口同时存在 `double/float` 秒、`int64` 毫秒，
以及 `LDTactical::Milliseconds` 转换入口。统一语义不要求粗暴全库换单位。

| 量 | 对接要求 |
| --- | --- |
| 世界位置、半径、射程、路径长度 | 明确使用 Unreal 厘米；标出平面距离、空间距离或表面路径，不能混用 |
| 移动速度 | 明确厘米/秒；属性修正先按统一公式投影，再接原生运动 |
| 时长与绝对时间 | 参数表标明秒；运行接口逐字段标明秒/毫秒及“时长/本局截止时刻”，在边界集中转换 |
| 经验、计数、等级 | 服务器有界整数；奖励和阈值转换的取整点由内容公式明确 |
| 比率、概率、暴击、减伤、攻速、冷却属性 | 每项标明量纲、有效范围和表示法，不把百分数、倍率和整数百分比互换 |
| 血蓝和其他连续属性 | 由战斗契约确定计算类型、截断/封顶顺序；UI 格式化不能反向改结算 |
| 显示倒计时 | 使用同步的服务器时间与截止状态；客户端显示到零不能自行复活、刷新技能或判胜 |

公式表必须给出运算顺序、上下限、取整位置、非有限/非法输入拒绝以及可复算例子，
不能只列属性名称。与数值无关的单位和转换选择由工程封口，不需要产品逐字段决定。

**同刻硬约束：** 喷漆或守护完成时必须看到同一结算时刻已发生的位置/资格变化、
到期命中、控制和死亡（先处理死亡、离局和控制，再处理喷漆和守护），再重新判定是否仍满足条件。
不能由独立 Actor Tick 先到者抢先判胜。完成提交后的战斗、奖励、选择、喷漆和守护不能继续修改本局结果或战力。

连续性不能只靠最终位置快照重建。共同事件输入为：

| 责任 | 最低交接内容 |
| --- | --- |
| 运动/位移、生命/离开/保护提供者 | 局代次、参赛者与身体生命、事件来源、本流单调序号、服务器实际发生时间、圈内/有效资格变更 |
| 权威调度 | 区分事件实际时间与补算采样时间；固定同刻提交次序；记录每个提供者已发布到哪个时间边界 |
| 唯一喷漆与守护归约器 | 等相关提供者水位就绪后消费到期边界，保留中间进出、控制打断与资格变化；已合法接受的旧生命未消费前缀仍按真实生命区间处理，拒绝重复/旧局及退休后新到的旧生命事件 |

不能用已完成运动的当前姿态回填过去，也不能用被补算逻辑临时回拨的 World 时间给新事件打戳。
这不要求永久事件日志、第二套运动积分或网络回滚世界。事件产生点/时间所属由相关领域正式接线，
而不是旗杆 UI 猜测。先锁定结果并关闭写闸，再执行取消/清理和结果发布；
清理回调也不能产生新的玩法提交，已完成事务的只读回执重放不算再次提交。

唯一目标阶段序由 [生命周期 §6.4](SESSION_MATCH_LIFECYCLE.md) 定义：
Session → Motion → Actions → Effects → DeathsAndRewards → RespawnsAndWorld →
Transactions → Capture → Close → Publish。先按真实秒推进，真正同刻才使用核心已分配的
CommitOrdinal；消费者不得再按 Provider/Phase 重排已提交事实。
当前 Combat 的 `AdvanceAuthority/Sample` 改造为
`AdvanceAuthority(const FLDMatchContext&, int64 ThroughMs)` /
`SampleBoundary(const FLDAuthorityBoundary&)` 唯一驱动。
GameMode 只拥有时钟、BeginAuthorityStep、permit、生命与闸门，不另建并行调度器；
旧 deadline/Heart 和回拨 World 时间的路径不进入目标链。

可用性 NowMs 使用核心同一时域的 checked floor/已实际到达整数边界，事件以 ceil 分桶，
仍保留 OccurredAtSeconds；RecordedAtMs 是记录时刻的审计桶，不能直接复制 floor NowMs。
ThroughMs 只能取实际完整处理的整数 Boundary.AtMs，不能 ceil 小数完成点。
已有整数期限不经 double 往返再取整；第一次 CompleteBodyMotion 不是最终 Fence，
晚因果位移/复活落地仍进入同一身体 Motion 流，Sealing 后前缀闭合才 Capture。
这些精度与封闭规则以生命周期 §6.1–6.4 为准，不让显示时间或独立 Actor Tick 判胜。
已完成的权威 CurrentFloor 查询明确得到 NotGrounded 时，是确定的非占用几何事实：
发布既有 Inside=false，可完成该边界；同XY重新落地也须报告变化。
真正缺数据/查询未完成才阻挡 Fence。错误目标的 InvalidSurface/WrongSurface 不代表本人离开喷漆区，
不能用目标规划投影伪造本人接地，也不能把普通语义拒绝升级为整局故障。
RPC/服务器入口的收件不等于获得写权限。操作合同的 `SubmitOrder` 只排队，
Actions 阶段的 `ProcessAuthorityOrders` 重新校验当前 permit 才处理保护解除和订单激活；
动作/导航交接也在同一有效许可中原子提交。全域阶段序与核心类型由生命周期域唯一定义，
不能将某个消费方的转引复制成另一套核心合同。

## SC-04：死亡、终局、离开与新局

| 状态或操作 | 死亡/复活 | 普通客户端离开 | 终局 | 新局 |
| --- | --- | --- | --- | --- |
| 等级、经验、属性点、技能、图纸和构件 | 全部保留，不重复初始化或发初始奖励 | 不再有效参赛；不是击杀，不发离开奖励；保留必要本局结果记录 | 冻结为本局结果，拒绝继续变更 | 按批准的开局输入全新初始化 |
| 未用选择机会、已生成候选 | 保留原候选，可加点、选择并保存图纸或确认构件奖励；不能学习或替换，不治疗尸体、不提前复活或修改等待 | 清理未决请求，不把席位转给新加入者 | 不继续提交成长 | 清空旧机会、候选和回执域 |
| 来源冷却 | 按服务器时间继续；不因 Pawn 重建重置 | 旧来源不能继续提交命令 | 不继续释放动作 | 新局建立新的来源时间域 |
| 导航、追击、指向、未完成交互 | 取消适用动作，旧 life 的迟到消息无效 | 清理连接相关操作 | 清理未决动作并反馈结束 | 旧 match 无效 |
| 已成功释放的独立效果 | 正常死亡不取消，继续到原定结束；仍在本局的释放者保留后续击杀归属 | 立即取消未结束效果，不允许继续影响战斗 | 停止后续结算 | 旧局效果无执行权 |
| 血蓝、临时控制、保护 | 复活满血蓝、清死亡前临时控制；保护按规则生效 | 身体立即移除，不可攻击、不阻挡道路，不计喷漆区人数 | 不再复活或处理效果 | 按新局初始化，不复用旧期限 |
| 喷漆与守护状态 | 死亡者立即无效、喷漆进度清零，涂鸦主人死亡即清除涂鸦；保护者不喷漆，也不暂停别人的喷漆或冻结守护 | 离开者无效、清除其涂鸦，不自动给剩余玩家胜利 | 唯一结果提交一次 | 发育期、喷漆进度、涂鸦、守护和结果全部重置 |
| 观察句柄、目标代理 | 清除活体观察/旧单位标记；死亡镜头只看静态/公共信息，不新增活体视野 | 清理观察通道及离局身体/效果表现 | 按最终授权清理，不留下实时隐藏更新 | 全部换代 |
| 本地名称、按键、音量、画质、镜头偏好 | 保留 | 保留 | 保留 | 仅这类明确允许的本地设置可保留 |

Host 离开是会话结束，不执行普通客户端离开的继续对局路径；
客户端返回菜单并显示原因。Demo 不实现中途加入、断线重连或 Host 迁移。
遗留恢复/席位交接组件的存在不能改变这个边界。

尚未释放的动作因正常死亡取消。已成功释放的独立效果，在正常死亡或遗忘技能后
继续到原定结束，不重建期限或补发效果；需要持续持有/施法维持的光环、被动、引导在条件丢失时失效。
独立效果的存续不授予失去来源后的新释放权限，也不提供死亡侦察的视野来源。
来源生命证明原始释放出处，不应在来源正常死亡/复活后将已接受的独立效果误判为旧命令重放；
新的动作请求仍必须使用当前生命，每次效果作用也必须保持正确的受害生命绑定。
正式退出/断线立即移除身体并取消未结束独立效果，清理其待结算 tick/命中和表现；
不能用仍存活的 Actor 或迟到回调继续施加影响。已提交伤害/奖励/回执不回滚，
旧受害生命上的排队命中/持续伤害不能套到新身体，终局后不得继续结算。
离局取消按参赛者/效果身份执行，不以当前是否还有 Pawn 或原技能为前提。
效果独立性、绑定条件和合法结束条件由内容定义明确，不从“Actor 尚未销毁”推断。
身体移除与删除参赛记录不同：终局仍需列出本局全部参赛者，包括已离局者。

## SC-05：奖励、选择与构筑事务

正式设计须明确经验、等级与选择机会在同一死亡事实下如何避免部分提交，
同时覆盖重复命中、持续伤害、同时死亡、死亡后收到奖励、死亡与选择竞争。
奖励资格先看受害对象和关系：只对野怪或另一参赛者的合法击杀发奖，
自杀、离开清理、营地回位均不发奖。无主致死不能继承前一次伤害的所有者；
来源已经阵亡但仍在本局时，若存续效果确实击杀合法对象，奖励仍归实际所有者。
无奖励的死亡也记录已处理，不能稍后以新来源重试发奖。
正式输入是核心接受的 `FLDCommittedDeath`，其中不可变 RewardBasis 包含
`CreditOwnerEligibleAtDeath`、NoRewardReason、奖励定义以及适用的受害等级/构筑版本。
同一 Effects 致死集合先锁定全部基准再派奖；不在派奖/重试时重读已经变化的等级或在局资格。
离局后仅为离局前已锁事实保留 settlement-only 接收记录，不恢复身体、被动、动作或参赛资格，
也不让离局后的残留效果生成新死亡。必需奖励无法完成时走核心
`FailAuthorityBoundary`：明确未支付并关闭写闸，不伪造 NoReward/Fence/胜者，不永久 Pending。
真实终局后不能补付旧局；完整恢复/故障处理按生命周期 §5.1/§6.6，不另设奖励时钟。
候选生成的随机状态属于服务器；关闭页面、死亡和重发不重新抽取。

候选从未学且没有待学图纸的合格主动中不重复抽取；不足三个时如实给出一或两个，
没有合格主动时保留机会等待，不生成候选。NPC 购买要求至少三个合格主动，条件不满足时拒绝且不收费。
不能用重复选项、隐藏重抽或免费自动选择补洞；前一组处理完成后才生成下一组。
主动只有一级，随角色等级成长；构件的实例、安装位置和来源按工坊事务维护，不由 UI 复制。

营地只索引固定 CampId/成员与同一个核心 Victim.Life，不另外生成死亡或奖励身份。
未受攻击不主动攻击，同组受击共同反击但不共享隐藏坐标；Returning 可受伤/控制/击杀，
不因受击回头重追。实际到家且仍存活的成员满血蓝、清临时效果/仇恨、技能就绪，
不复活死成员、不增 Life、不发奖励。这一野怪重置不适用于参赛者的冷却/比例保留规则。
具体反击输入只消费 Combat 成功提交的 `FLDCombatHostileContact`，
由 `World\LDCampDirector` 幂等记录本营敌对来源，再经 `LDCampDecision` 纯决策生成反击意图；Miss/无效攻击意图不触发反击。
`PrepareCampReset/ApplyCampReset` 归 Combat，World 提供实际 HomeProof 和 ReturnEpoch；
重置键为 LedgerMatch + 完整 VictimKey + ReturnEpoch，只有新 Returning 周期才推进epoch。
纯Prepare先清局部候选临时状态，再计算最终上限并准备满资源，最后与World状态原子安装；
同键只读重放、旧状态回调按EffectId/目标生命拒旧，不能补旧Max、复生旧Root或误删新效果。

## SC-06：能力来源、冷却与派生属性

Combat 的 `FLDCombatSourceRef` 区分 Basic/Learned/Innate 来源；持久冷却轨道与构筑投影见[战斗手册](../systems/COMBAT_AND_GROWTH.md)。

- 所有参赛者初始为近战单体普攻；构筑可以增加距离、附加元素、强化普攻或扩大反应范围。
  不强制普攻群攻，也不要求基础普攻改为弹道。内容/战斗域提供来源、几何和效果路径，
  仍走同一权威命中/归属/奖励链，不能由 UI 独立追加一套伤害。
- 角色主动来自所学技能。Q/W/E 是入口映射，不是独立能力状态。
- 来源身份必须同时解释所有权、当前绑定与持续锁定的冷却身份。
  只用槽位索引会被换槽绕过。
- 来源冷却契约必须覆盖升级、换槽、遗忘后再学、死亡、重复请求和新局。
  这些路径不能凭重建对象消除尚未结束的冷却。
- 目录需要给出来源定义、适用冷却属性、叠加/互斥和触发限制。
- 遗忘等来源丢失期间，未结束冷却继续按服务器时间流逝，不冻结或清空；
  重新持有或重学时沿用对应持久来源的原结束时间，不重新起算或刷新。
  等待到原结束时间自然到期可以恢复可用；移除/重建来源本身不能加速到期。
  死亡期间已有冷却同样继续，只有新局才重建新的来源时间域。
- 遗忘技能只撤销后续释放资格和持续绑定能力，不取消已经成功释放的独立效果。
  独立效果继续到原定结束；光环/被动/引导仍要求其维持条件。不得把统一来源失效入口
  写成“所有旧效果一律取消”，也不得因独立效果仍在而恢复已经遗忘的技能。
- 构筑变更只投影一次最终属性。存活时生命/法力上限变化保持原百分比，
  使用变更前的当前值与上限，针对本次复合操作的最终新上限仅换算一次。
  死亡期选择不改尸体当前血蓝、不提前复活；正常复活按更新后的上限补满。
- 精度、取整和有效上限输入域由战斗/内容公式统一定义；不在
  逐个修饰器或客户端显示时分别换算。重复请求不重算；无回复/战斗的往返上限变化
  不得形成累计血蓝净收益。不支持的零分母或非法/非有限输入在预检明确拒绝，不补满兜底。
- 已释放效果使用来源快照还是实时属性，仍由战斗/内容契约明示。
  不另建 UI/AI 版公式，也不另走治疗/扣蓝路径实现上限投影。

进攻意图与动作执行分开：先通过调用身份、当前 Match/Life、请求去重/拒旧和终局写闸准入，
再因进攻意图解除复活保护，然后校验具体来源/版本、目标、距离、蓝量、冷却和控制等动作条件。
目标、距离、蓝量等无效也解除保护；释放前的动作校验失败不扣资源、不启动冷却，不回滚已解除的保护。
已释放后的命中失败或效果结束仍遵守原效果生命周期，不能借此退回已经提交的资源。
未通过前述技术准入的包不解除保护，更不能让旧包修改新生命。
解除保护本身须发布资格变化和自身投影，即使动作后来失败，喷漆与守护归约器也必须收到该事件；
不能把资格事件绑在“施法成功”分支上。输入/UI/AI 不应因可预判的动作无效而吞掉实际进攻意图，
回执应同时表达“保护已解除”和“动作未执行”，不能伪造施法成功。

## SC-07：目标、观察与读模型

具体采用的单一路径与网格/稀疏协议接线由世界设计和架构裁剪共同封口。
已审核的 [世界报告](WORLD_CAMPS_AND_VISION.md) 选择一个有界稀疏 `FLDWorldView`，

现有单层布局、完整首版参数及操作§4.2规则已获用户批准用于首轮实施/试玩；
静态world2生产、地图/目录保存、凸多边形碰撞和导航绑定已有实现；

hint只是期望，不能代替实际支持面/接地证明。NAME_None/未知为InvalidSurface，
错面为WrongSurface，无合法floor明确NotGrounded，不向下投影或填零兜底。

目标请求区分单位、地面、方向、自身；单位目标到达服务器时重新解析观察权限。

迟到确认或目标重新出现不能自动恢复这条旧订单。已准备的单位施法仍需重新获得合法目标。

需要区别目标死亡与单纯观察移除时，消费世界的授权终止合同：
`FLDObservedUnitTermination` 必须在实际死亡时有合法观察见证，并由服务器绑定原订单身份。

旧终止不能驱动新订单，客户端显示消息不调用导航。具体字段/序号定义由世界域维护，

其中 `camp_returning` 由Vision仅为当前可见Returning成员派生到同一Statuses，

离开Returning或隐匿即撤销。AI据此止损不代表禁止真人继续追杀。

结算统计从权威已提交事实和保留参赛记录投影；本局用时由服务器开局/结束边界确定，
终局前不发布全体隐藏等级，没有胜者时不按统计补选。

每个新增显示字段须同时声明：生产者、公开/自身/观察权限、match/life/revision、
失去权限后的清除、stale 表现和错误反馈。完整地图与网格观测格式须选定真实接线方案，
不能只修改数组上限假定协议兼容。
正常 Listen Host 的主画面、原生身体/附属表现、HUD 和目标解析也遵守同一授权，

## SC-09：错误、取消与对接交付

错误至少区分：连接/版本/房间准入、旧 match/life、旧修订、无效或过期观察、
无合法路径、冷却/法力/控制限制、候选/替换无效、
死亡、终局与新局失效。正式错误码由相关模块定义并集中映射给 UI/AI，
不要求向客户端公开内部断言、隐藏目标身份或权威日志。

取消不能撤销已提交效果或退款，除非具体内容规则明确规定；
也不能复活旧 order、重抽候选、清理仍须保留的冷却或把 Pending 改成成功。
同一手势只能由 UI 或世界一个消费者接收，Esc/S/失焦/死亡的清理要共享输入边界。
拒绝具体动作不等于进攻意图没有任何状态后果：SC-06 的保护解除要独立反馈；
鉴权、代次或终局闸拒绝则不得产生该副作用。死亡期选择的成功只表示构筑提交，
不表示复活、治疗或主动技能已经执行。
UI Root 的 `TopInputLayer` 是唯一输入层来源：Choices主页面为普通panel，子确认才是模态；
`OpenChildConfirmation` 先清冲突Armed，但保持按下手势的capture到释放。
Back按编辑/捕获→子确认/模态→未消费Armed→普通面板→Settings处理，一次Handled，
不能让Armed越过模态，也不隐式Stop订单、发RPC或消费Offer。完整本地边界见
[UI §4](UI_AND_SETTINGS.md) 与 [操作 §3](CONTROLS_AND_TARGETING.md)。

游戏窗口固定为无边框桌面分辨率，没有窗口模式、分辨率或显示试用；VSync/画质在明确 Apply 后应用。
仅已确认应用且可核验的本地值可保存，不把草稿或局内数据持久化。
完整应用与保存验证由 [UI §8](UI_AND_SETTINGS.md) 单点定义。

领域接口新增或变更时，在对应领域文档中说明下列对接信息：

| 交付项 | 必须回答 |
| --- | --- |
| 状态与正式接口 | 写入者是谁，具体类型/函数在哪个现有组件上，哪些字段只是投影 |
| 命令与事件 | 参数/结果类型、身份、版本、来源、权限、提交阶段、拒绝和回执去重 |
| 生命周期矩阵 | 取消、死亡、离开、终局、新局分别保留/清理什么；已释放效果如何处理 |
| 内容引用 | 使用哪些正式目录/参数/公式键，单位和转换在哪里，是否已批准进入运行输入 |
| 接线与删除 | 替换哪些旧调用者/序列化/生成/资产/测试；删除后的依赖如何收口 |
| 验证 | 生产者/消费者共同的正反例、真实拥有连接条件、同刻与重放断言、未覆盖限制 |
