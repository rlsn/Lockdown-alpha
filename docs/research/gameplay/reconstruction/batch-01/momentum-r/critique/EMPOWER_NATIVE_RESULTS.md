## 1. 对决：6 个样板，强化关 → 开（adapter v22 重判）

- **守、动处理器仍然没有出现在样板一方**：重判只改变判读，不改变原生中的宿主选择。这两次运行录制于 `2bf56d7f`，早于 S2 `6f09d2ba` 的构筑身份宿主打分，所以刺猬仍选普攻，冲刺仍选 Q。S2 实测“冲刺鬼影 → D、刺猬 → 守”需要在 `2d46001c` 上重跑 `b01-empower-on`（24 Case，约 4 min）才能进入这份对照。
## 2. BotMatch（7 AI，单局）

| 指标 | 值 |
| --- | --- |
| 强化 | 183 次（野外生命；休息室训练另有 54 次未计入），每人每野外分钟 2.86 次 |
| 宿主 / 处理器 | 普攻 68%、Q 32% / 拳 70%、打 30% |
| 目标（按本次强化带标记的命中） | 参赛者 79%、只打中营地 19%、没打中 2% |
| 触发前劲 | 平均 75.5 |
| 就绪时间占比 / 250 ms 内重复 | 20% / 0 |
| 单次强化最多命中 | **5**（原报告的 20 是汇总脚本缺陷，见下） |

**“单次强化最多命中 20 次”不是游戏缺陷**：强化序号每条生命从 1 重新计，而 `LD_HIT` 不带来源生命号。汇总脚本按（来源，序号）归并，把一名 AI 15 条生命里序号 1 的命中合在了一起（跨度 867 s）。复核：278 次带标记命中全部落在对应强化后 1.35 s 以内（90% 在同一时刻）。S5 已修汇总（`624a7fb9`：命中归同一来源、同一序号、时间不晚于它的最近一次强化）。修正后目标中营地占 19%，来自“视野内无敌方参赛者时野怪也算”的规则（反证 #2 的实现口径），不是缺陷。

**另一处计数缺陷（已修，需要合入）**：`prepaid` 行是先前已付费强化的兑现（例如 Q 滚远点付费，之后的强化普攻再记一行 `paid=0`），adapter 却把 applied 和 prepaid 都计为强化。结果冲刺样板的强化次数翻倍（6 → 3），宿主也被多记一个“普攻”。S2 的计划宿主检查用同一份宿主表，所以给“强化下一次普攻”的 Q 指定宿主会被误判 `EmpowerHostNotApplied`。S5 `3f3f3fe8`（adapter v20，已合入 S2 v19）改为只计 applied，汇总脚本把 prepaid 的命中归回付费的那次。

## 4. 平衡观察（只记录，B02）

1. 拳宿主频率超过 L2 预测 2–3 倍，而且 AI 有 68% 选普攻：拳会成为默认最优宿主。按宿主分别设消耗，或提高拳的消耗，需要先复测。
2. 守、动处理器在这两次运行中都几乎没有出现（录制时 AI 宿主打分对护盾技能和 D 不利）。S2 `6f09d2ba` 已改为按构筑身份打分；在原生重跑之前，“每个构筑都有自己的强化”在 AI 数据中还没有被验证。
3. 坦克（刺猬）受益最大：交战长、强化最多（每 Case 4.25 次），击杀时间 −37%，一例僵持变成胜利。
4. 劲经常 ≥ 90 且有溢出：进场劲高于门槛，“开场即强化”实际上已经发生（对应反证 #1）。
5. 19% 的强化用在营地上：独自打野时的强化不能保留，带不到 PvP。
