# MR-08（构筑融合部分）宿主印记独立反证

对象：`../build-integration/BUILD_INTEGRATION.md`（推荐 C6“宿主印记”：每人 1 枚免费印记放在 Q/W/E/本体/D，5 个处理器，载荷发出现有事件，声称 86 张牌经事件自动接入、约 1,000 种 R 形状零新内容）、`r_build_integration.py`。
方法：读脚本与源码（`LDCombatCards.cpp`）核对“自动接入”的实际路径；对照 R、劲两份反证与外部原则 E1–E14。

## 0. 结论

| # | 结论 | 判定 |
| --- | --- | --- |
| 1 | “经事件自动接入”在源码层面**不是统一成立的**：现有监听者对派生命中的处理逐张不同。拳印记把 3 拳都当第 3 段，A09 追加打击整份复制主命中（含段数），`第三拳回口气`（A01）与 `边打边想`（A02，`card_punch_think`，普攻减技能冷却）不排除追加打击，会随 A09 扇出 | 需要逐监听者审计；自动接入的 QA 成本被低估 |
| 2 | 本体印记会成为默认：自动模式按“宿主上的牌数”打分，而本体牌占 56/89；拳处理器接 29 张牌 | 预计多数玩家的 R 收敛为“3 拳”，与“构筑决定不同 R”相悖 |
| 3 | 阵地处理器内容断供（6 张、0 稀有、开局 37% 可见）：5 个处理器中的 1 个在 Batch 01 只能交付半成品 | 成立，且影响“召唤与工事”代表构筑 |
| 4 | 传说派生（`拳里带招`、`再来一遍`）与拳印记相乘是结构性乘法，不是“是否允许破格”的 PO 问题 | 应先给技术护栏，再问 PO |
| 5 | “约 1,000 种 R 形状”主要是**技能本身**的多样性；R 本身的行为是 5 个处理器 × 元素载荷，约 30 种 | 表述需改，避免高估 |
| 6 | C2 关键石否决：结论可保留，但算术与证据需修正（L16 属性点按公式 48，真人实际 81） | 理由应改为经济原则（P-3.2），不是数据 |
| 7 | 两条护栏自相矛盾：§2.2“不能刷新或返还宿主自身冷却”与 §5“撞着就刷新：刷新在链内一次” | 需统一 |

整体判断：“宿主印记”的方向（玩家在已有宿主上选位置、载荷走现有事件）与外部原则 E7、E8、E11 一致，并且比“卡牌开口”更少误触发，值得作为 R4 的构筑权方案提交。但“零新内容、自动接入”的两个核心卖点需要改写成“**零新内容 + 一次性的监听者审计 + 派生事件口径表**”。

## 1. “经事件自动接入”是否成立

### 1.1 源码中的派生路径（L1）
- A09 追加打击：`FLDCombatHit Strike=Primary; Strike.bExtraStrike=true;`（`LDCombatCards.cpp:713-716`），**整份复制主命中**，只清击退。主命中是第 3 段时，复制品也是第 3 段。
- 监听者对 `bExtraStrike` 的处理逐张不同（`LDCombatCards.cpp:1372-1430`）：

| 监听者 | 触发条件 | 是否排除追加打击 |
| --- | --- | --- |
| A01 `第三拳回口气`（第 3 段回劲） | 第 3 段 | **否** |
| A02 `card_punch_think`（每次普攻随机减一个技能冷却） | 任意普攻 | **否** |
| A03 `拳拳到肉`（第 3 段算一次全技能命中） | 第 3 段 | 是 |
| 力道关键石（第 3 段或暴击打 4% 当前生命） | 第 3 段 / 暴击 | 是 |

- 推论：拳印记“3 拳都按第 3 段”时，A01 每拳回劲，并且**每个 A09 复制品也回劲**；A02 每拳、每个复制品都减冷却。宿主印记 §2.2 的护栏（“载荷新增事件不能产劲”“冷却缩减合计一次”）只在**复制品继承 R 标记**时才生效；文档写“派生动作不继承载荷，但照常触发牌”，没有说明是否继承 R 标记。
- 这正是 A12×A09 风暴的同类结构：一个把“频率”变成“次数”的乘区（A09）与一个按次数结算的监听者相乘（E2、E10）。现在的乘数是“3 拳 × (1 + A09 次数)”，有界，但会让拳印记的收益随攻速超线性增长。
- 另外记录一个**现行规则**层面的问题（与 R 无关，交 S1 判断是否为缺陷）：A01 不排除追加打击，所以 A09 构筑在第 3 段每次都会多回劲。

### 1.2 应改成的说法与需要补的东西
1. 派生事件（追加打击、扫击、反伤、反应、区域跳伤）**继承 R 标记、不继承载荷**；R 标记命中一律不产劲、不减冷却、不刷新、不重放。
2. 一次性的**监听者审计表**：所有对 `basic_hit / combo3 / skill_hit / skill_cast / dash_contact / shield / shield_break / ground / reaction` 作出反应的牌（按 `op`，不按 `vocab`），逐张写明对 R 标记与派生命中的处理。这是首版必需工作，应计入成本。
3. 脚本的“自动接上 29/26/18/13/6 张”是按 **vocab** 映射的，而 vocab 是选牌加权标签，不是监听关系（例如 `attack_speed` 映射到拳处理器，但 R 固定为 3 拳，攻速牌只改变 3 拳打完的时间）。应改为按 `op` 统计，并标为“候选接入”，审计后再给确数。

## 2. 本体印记是否默认最优

- 牌的宿主形态：本体 56、技能 20、冲刺 13、勋章 5（`content.json`）。
- 自动模式得分 = 宿主上牌数 + (技能等级 − 1) + 勋章阶数。大多数构筑在本体上的牌多于任何一个技能宿主，所以**自动模式几乎总是选本体**。
- 拳处理器接入的牌最多（29 张，按 vocab），且第 3 段牌、力道关键石、本体勋章都在本体上。BUILD_INTEGRATION 自己的反对意见 3 已指出这一点。
- 后果：大多数玩家的 R 是同一种“3 拳”，构筑差异只体现在拳的附加效果上；技能循环、元素、阵地的 R 需要玩家**手动**改印记才会出现。PO 要求“不同构筑拥有不同的 R 行为”，默认值本身会把多数人推向同一个 R。
- 建议：自动模式按“技能等级与技能牌”而不是“全部牌数”打分，或者把本体从自动候选中排除、只能手动选择；并用 9 个代表构筑实算一次自动模式的选择结果写进报告。

## 3. 阵地内容断供

- 阵处理器只有 6 张牌、0 张稀有；电风扇、陷阱、封条不在开局池；开局三选一只有 37% 能见到阵地技能（BUILD_INTEGRATION §1.1、§6 G1）。
- 后果：5 个处理器中的 1 个在 Batch 01 只能交付“可用但空”。“召唤与工事”代表构筑的 R 演示依赖 B02 内容。
- 处理建议：PO 报告中把阵处理器标为“结构保留、内容依赖 B02”，并说明在 Batch 01 默认版本中阵地构筑的 R 是“立即武装 + 持续/范围”这一种，不会因为构筑成长而质变。

## 4. 传说派生与拳印记

- `拳里带招`（`combo_cast`：第 3 段放出一个技能）与拳印记相乘：一次 R 产生 3 次第 3 段 → 3 次免费施放。`再来一遍`（`auto_recast`）同理放大技能宿主。
- 这不是“破格爆发是否允许”的偏好问题，而是一个固定倍数（×3）。按外部原则 E10（派生事件系数）与 PoE“触发付折扣税”，建议先给技术护栏：**每次引爆中，每张派生施放牌最多触发 1 次**；在此之上，PO 再决定传说牌是否可以在 Type3/Type4 可读攻击上超预算。
- 冲刺处理器同类问题：“穿过敌人（每人算一次冲刺接触）”在 8 人混战中让接触类牌（`蹿过去抡一拳`、`冲刺接触元素`、`失控列车`）按人数线性放大，与“一次引爆 ≈ 一次 2 级技能”的预算冲突。建议接触类效果在一次引爆中按目标数递减或设上限。

## 5. “约 1,000 种 R 形状”

- 计算：技能宿主 24 × 分支路径 7 × 元素状态 6 ≈ 1,008。
- 其中 R 自己的行为只有 5 个处理器 × 元素载荷（约 6），约 30 种；其余变化来自被强化的那个技能本身。玩家感受到的是“我的技能变强了一下”，而不是“我的 R 是 1,000 种之一”。
- 可理解性：这是优点（R 不需要新教学），应如实写成“R 只有 5 种行为，具体样子由你的宿主决定”。
- QA：没有“R 牌 × R 牌”矩阵是事实，但有“处理器 × 监听者”矩阵（约 5 × 90）和 §1 的派生口径审计；不能写成“首版零成本”。

## 6. C2 关键石否决的依据

- 脚本按 `3 + 3 × (L − 1)` 计算属性点，L16 为 48，得出“18 点 = 37.5%”。EXP-01 真人 L16 实际有 **81** 点（击杀、营地、事件等额外来源），按此 18 点只占约 22%。
- “L5 冠军 0 次购物、堆 81 点”是单局单人（L5，n=1），对手是有缺陷的 AI，且商店吸引力本身属于 Batch 02/03 的问题。
- 外部也有关键石改写主动行为的先例（PoE2 Ritual Cadence 改写 Invocation，EXTERNAL_PRINCIPLES §3）。
- 结论可以保留（不让关键石决定 R 形态），但理由应写成：PO 原则 3.2（属性点同时是属性与货币）下，任何让关键石“额外解锁”新能力的设计都会进一步抬高“堆点不买牌”的收益；单局数据只作旁证，算术需修正。

## 8. 对构筑融合 Session 的修订要求（经 S0 转达）

1. §0.2、§2.2、§4：把“自动接入”改为“候选接入 + 监听者审计”；写明派生事件继承 R 标记、不继承载荷；补监听者审计表（按 `op`）。
2. §2.2：自动模式打分改为不偏向本体，或本体只能手动选择；附 9 个代表构筑的自动选择结果。
3. §4 / §5：派生施放牌每次引爆最多 1 次；冲刺接触按目标数递减；统一刷新护栏。
4. §4：“约 1,000 种形状”改为“5 种 R 行为 × 宿主技能的现有变化”。
5. §1.1、§0.5：修正属性点算术（真人 L16 实际 81 点），C2 否决理由改为经济原则。
6. §0.6 ③：删除已撤回的 17–32 引用。
