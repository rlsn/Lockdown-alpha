# R 架构研究（S3 · R Gameplay Architecture）

> Batch 01 · PO 第二道指令 §8 / §11 / §14。**研究候选，不是实施授权**；未批准：R 的行为、消耗、触发与构筑绑定。
> 已批准的前提：删除通用长按爆劲、删除通用精准闪避；冲刺保持多用途；移速 240；Q/W/E 的施放方式永远不受劲影响。
> 劲的获得与消耗由 `../momentum/`（M1–M4）决定，本文只定义 R 侧的接口；构筑融合（C1–C6）与 8 个真实构筑由 `../build-integration/` 负责，本文 §7 只做承载自检。
> 设计语言：采用 PO 已批准的 Threat Grammar（Type1 接触/锁定、Type2 预判、Type3 反应、Type4 高威胁/承诺、Type5 区域/阵地）描述 R 的反制；它是设计语言，不是运行时分类，R 可以改变一招的类别。通用预警视觉规范由 S3b 负责，本文只给 R 的可读性需求（§7.1）。
> 证据级别：L1 源码 / 数学 · L2 离线模拟 · L4 原生整局 · L5 真人。本文没有 L5 证据，“好玩”都是假设。
> 配套：`R_ARCHITECTURE_SKETCH.md`（早期草图）· `r_value_model.py` / `data_r_value.json`（L1 公平性计算）。

## 0. 摘要

> **修订注记**：经 S5 反证与构筑融合后，推荐方案已更新为“R4 引信 + 宿主印记 + 5 个处理器”。“卡牌开口”的写法与 8 个口的目录（§3.4.1、§6、§8）已由 §13 取代，公平性数字降为定性。先读 §13。

1. **R 的核心难题不是“按下去发生什么”，而是“同一份 R 对不同构筑是否公平”。**（L1）
   - 用同一名义强度比较 8 个代表构筑，只要 R 的效果是“放大已有数值”，一次 R 的价值就会随构筑结构变化。在一组任意设定的换算下，差距约 2 倍，但具体倍数和“谁受益”对换算很敏感，S5 改动换算后为 1.35–3.41 倍（**只作定性**，§13）：
     - 强化下一招偏向大技能构筑；
     - 回响偏向护盾与工事；
     - 限时全伤害状态和每次命中加成偏向攻速与冲刺。
   - 加上乘法卡牌，差距会继续放大。
   - R4 / R2 把公平性变成**可以逐口、逐原型设计的问题**；但模型里它们的 1.0 倍是常数载荷构造出来的，不是证据。还要乘上各口的引爆机会（§13.1）。
   - 外部同类做法：PoE2 的 Meta 宝石把能量门槛与技能施法时间挂钩，以“让快慢技能都可用”；RoR2 给高频攻击更低的触发系数。
2. **推荐 R4“引信”为骨架**（AI 推荐，排序见 §5）。
   - **按 R** = 给自己装上一发可见的“引信”。
   - **接下来**第一个符合条件的动作把它引爆，打出该动作专属的引爆效果。
   - **开局**只有“技能”一个触发口，所以开局的 R 就是“强化下一招”（R1），心智模型简单。
   - **构筑可以三方面改变 R**：
     - 开新触发口：普攻第三段、冲刺、元素反应、护盾、受击、放置物……
     - 改造引爆效果；
     - 增加引信发数，从“一发”长到接近 R3 的“连续引爆期”。
   - 内容随“触发口”增长（约 8 个），不随“技能 × 卡牌”组合增长。
3. **R5“回响”**（把你上一招再放一遍）是本研究最有原创性的方案，建议作为引信的一个核心形态卡进入，而不是单独成系统。理由：
   - 回响的伤害、形状、元素都来自玩家已有的技能和分支，几乎不需要新内容；
   - 但单独作为 R 时，它会把最强技能的爆发翻倍，违反可读伤害预算，并偏向护盾、工事构筑。
4. **R3“爆气状态”是 PO 如果想要“阶段性高潮”的备选**：观赏性最强。代价是构筑间价值差最大、8 人混战光环难读，而且“状态子句”要为每类卡牌单独写。
5. **R2“可构筑大招”排最后**：
   - 内容最重（每种原型要做完整大招）；
   - 由关键石决定原型会加重“关键石比买牌重要”的老问题；
   - 五种原型会让构筑趋同。
6. **对 R4 的主要反对意见**（详见 §6）：
   - 按 R 时没有即时反馈，“装上”本身不爽；
   - 多触发口时可能被不想要的动作误触发；
   - 8 人混战里引信颜色是否读得出；
   - 它在“阶段性高潮”上比 R3 弱。
7. **与劲的接口**：
   - 无论选哪种 R，**都建议在引爆时扣劲、过期或被打掉不扣**。
   - 在 M1（技能与 R 共用劲）下，缺劲的技能流几乎用不上 R，与 PO 想要的“每种构筑都有 R”冲突。R 更适合 M2 或 M3。由劲研究 Session 定。

## 3. 五个 R 架构

### 3.1 R1 上劲（强化下一招）

| 项 | 内容 |
| --- | --- |
| 开局的 R | 有。按 R 进入“上劲”状态，持续约 5 s（示意值），**下一个 Q/W/E** 变为强化版 |
| 按 R 后发生什么 | 拳头或球亮金。下一招的强化按技能类型分三类：**攻击型**更强并附带元素载荷（现行爆劲的元素表），追加约 0.15 s 金光起手；**防御型**持续时间和范围 ×1.5，零延迟；**位移型**更远或穿过敌人 |
| 随构筑成长 | 卡牌改“几次、哪些招能吃、强化后连锁什么”，例如：`再来一下别喘` 让强化后的这招不进冷却；`先垫一句` 的记号在强化时双倍 |
| 成型后 | 仍然是“强化一招”，变化有限 |
| 反制 | 看到金光就躲开或打断下一招；硬控打掉上劲状态（泄劲，不扣劲） |
| 新增成长系统 | 无 |
| 复用 | 现行爆劲的元素载荷、观察帧里的蓄力可见状态、特效 `NS_LDOverdriveBurst` |
| 扩展成本 | 低；但要把“下一招”做得有趣，24 个技能需要逐个设计强化版（S4 已指出防御、位移的爆劲几乎没有战术差异） |
| 主要风险 | 退化为伤害倍率；L1 公平性 2.0×（偏向大技能构筑：冲刺、元素最高，重击最低）；攻速流的 R 价值主要来自技能，与它的身份脱节 |
| 证据 | L1；外部：LoL Rengar 的“下一招强化”需要“每个技能都能连放两次仍然平衡”（C，转引 Riot 设计师）；Karma 的强化下一招在 Wild Rift 改到被动，以免 R 变成空按钮（A） |

### 3.2 R2 招牌大招（可构筑终极技能）

| 项 | 内容 |
| --- | --- |
| 开局的 R | 一个通用小招（例：原地震地，小范围推开 + 小护盾，冷却较长） |
| 按 R 后发生什么 | 放出当前大招 |
| 随构筑成长 | 第一次达成关键石（18 点）时，R 变成该属性的大招原型：体格 / 脸皮 / 力道 / 脑力 / 身手各一种；之后带 R 标签的卡牌改细节（范围、元素、次数），技能分支不影响 |
| 成型后 | 一个与流派吻合的独立大招，阶段高潮感最强 |
| 反制 | 大招有长前摇、语音和光效，冷却长，看到后躲 |
| 新增成长系统 | 隐性地新增了：关键石的意义从“被动效果”变成“决定大招”，等于新增一条成长线 |
| 复用 | 技能系统可直接承载（R = 第 4 个技能槽） |
| 扩展成本 | 高：6 个完整大招（通用 + 五维），每个还要分支或修饰；每加一种流派就要加一个大招 |
| 主要风险 | 关键石的权重进一步压过买牌（PO 已担心属性点与商店的冲突）；五种原型带来趋同；“先拿关键石”成为唯一正解；与 Q/W/E 的身份竞争（R 太强时 Q/W/E 只是铺垫） |
| 证据 | 外部：Battlerite 的大招吃满能量（C）；Udyr 重做时让“每种出装都有想觉醒每个姿态的时刻”（A），说明单一原型锁死会伤害灵活性 |

### 3.3 R3 爆气状态（可构筑战斗状态）

| 项 | 内容 |
| --- | --- |
| 开局的 R | 有。按 R 进入约 4 s 爆气：全身光环；基础效果小且通用（例：技能冷却流速 ×1.5，移速 +10%） |
| 按 R 后发生什么 | 4 s 内按构筑获得状态效果，直到结束或被“破气” |
| 随构筑成长 | 构筑里每张带 R 子句的卡往状态里加一条：攻速卡加攻速、元素卡让每次命中挂主元素、护盾卡让护盾翻倍、工事卡让放置物立刻生效…… |
| 成型后 | 一段“开大期”，打法明显不同 |
| 反制 | 光环可见；硬控破气（剩余时间作废）；拉开熬过 4 s |
| 新增成长系统 | 无，但每类卡都要写一条“状态子句” |
| 复用 | 限时增益、属性投影（`timed_stat_bonus`）、观察帧状态 |
| 扩展成本 | 中高：子句数量 ≈ 卡牌数量；多条子句同时生效时难以解释 |
| 主要风险 | 公平性最差（全伤害 +30% 时攻速 13.5% 对工事 5.9%，2.3×）；同一时刻多人光环在 8 人混战难读；一个窗口内爆发集中，TTK 方差大（S4 D03-D 已提醒：价格不变时也会降低平均 TTK） |
| 证据 | 外部：Battlerite Overload 是 8 s 状态，加速、加伤也加承伤（A），后来因“削弱了死亡之前的重要性”被下调（旧研究 A）；SF6 用一个计量槽做所有强化，开发者说“计量越少越好理解”（B）；S4 L2：状态在劲盈余构筑中收益最高 |

### 3.4 R4 引信（构筑决定触发对象）

| 项 | 内容 |
| --- | --- |
| 开局的 R | 有。按 R 装一发**引信**：脚下出现一个颜色环，最长约 6 s（示意值）。开局只开“技能口”，所以下一个 Q/W/E 引爆它，效果与 R1 相同 |
| 按 R 后发生什么 | 什么也不立刻发生；接下来**第一个符合任意已开触发口的动作**引爆引信，打出该触发口的载荷 |
| 随构筑成长 | ①**开口**：带 `R口` 的卡牌、技能 3 级分支开新触发口（表 3.4.1）；②**改载荷**：带 `R改` 的卡牌修饰某个口的载荷；③**加发数**：少数卡牌让引信 +1 发（上限 3 发，每发独立引爆） |
| 成型后 | 例如攻速流：R 后接下来 3 次普攻各打出“劲拳”；冲刺流：R 后下一次冲刺落地震地、再下一次冲刺也一样；工事流：R 后放下的书包立刻武装并扩大爆炸 |
| 反制 | 引信环的**颜色表示装在哪类动作上**（攻击 / 防御 / 机动 / 阵地四族），对手知道接下来要防哪类动作；硬控打掉引信（泄劲，不扣劲）；攻击类载荷追加可读起手 |
| 新增成长系统 | 无；`R口` / `R改` 是现有卡牌的附加行 |
| 复用 | 爆劲元素载荷、现有词汇（`vocab`）、观察帧状态、`bAutoRecast` 护栏 |
| 扩展成本 | 低–中：触发口约 8 个，每个一份载荷与 2–4 种修饰；新卡多数只是“开某个口”或“改某个口” |
| 主要风险 | 见 §6：按下无反馈、误触发、颜色可读性、高潮感 |
| 证据 | L1：按口定预算让公平性可以逐口设计（不等于已经公平，§13.1）；外部：PoE2 Meta 宝石能量按施法时间（C）、RoR2 触发系数（C）、Hades 同时只能持一个 Aid（C）、Warframe 每技能一个 Augment（C） |

#### 3.4.1 初始触发口目录（示意，载荷数值待定）

| 触发口 | 什么动作引爆 | 默认载荷（按“一次引爆约等于一次 2 级技能”的预算） | 现有组件中谁会开这个口（举例，由 Build Integration 定） | 颜色族 |
| --- | --- | --- | --- | --- |
| 技能口（默认） | 下一个 Q/W/E | 攻击型：伤害提高并附带元素载荷，追加约 0.15 s 金光起手；防御型：持续与范围 ×1.5，零延迟；位移型：距离 +50% 并穿过敌人 | 开局自带 | 按技能类型 |
| 连招口 | 下一次普攻第 3 段 | “劲拳”：前方小扇形冲击 + 短击退 | `第三拳回口气`、`拳拳到肉`、`千斤重锤`、`左右开弓` | 攻击 |
| 普攻口 | 接下来 3 次普攻 | 每次附加小额伤害；**总量**按预算分摊，攻速越高单次越小 | `越打越上头`、`手快有手慢无`、`熟能生巧` | 攻击 |
| 冲刺口 | 下一次冲刺 | 落地震地，小范围减速 | `撞着就刷新`、`蹿过去抡一拳`、`穿人而过`、`闷头撞到底`、`失控列车` | 机动 |
| 反应口 | 你触发的下一次元素反应 | 反应变为范围版，并在原地留对应地面状态 | `反应回本`、`一波接一波`、`炸得更响`、脑力流分支 | 攻击 |
| 护盾口 | 你获得的下一份护盾 | 护盾 ×1.5，被打破时向周围爆开 | `壳碎了也崩你`、`挨揍起硬皮`、`反应装甲`、`吃撑了` | 防御 |
| 受击口 | 你受到的下一次直接伤害（1.5 s 内） | 减伤并反震攻击者（“硬吃”） | `打我也硌手`、`铁刺猬`、`死扛` | 防御 |
| 工事口 | 你放下的下一个书包 / 风扇 / 陷阱 / 地面状态 | 立即武装、持续 ×1.5、范围 +30% | `双摊位`、`违章工事`、`挪地盘`、`地头蛇` | 阵地 |

有意不开的口：
- **击杀口**：违反 K5（奖励补刀）。
- **治疗口**：吸血构筑已有无上限的增益，再叠一层 R 会放大反制缺口。
- **劲口**（R 回劲）：违反 K4。

### 3.5 R5 回响（原创）

| 项 | 内容 |
| --- | --- |
| 开局的 R | 有。按 R：**把你刚放过的那个 Q/W/E 再放一遍**（回响版），朝当前光标方向。回响的伤害和护盾约为原版 60–70%，不扣冷却，不产生劲，不触发“施法时 / 冷却返还 / 免费重放”类卡牌 |
| 按 R 后发生什么 | 上一招的半透明“幽影”在原起手位置重放；这一招有原前摇 + 约 0.15 s 幽影起手 |
| 随构筑成长 | **技能分支自动改变回响**（回响的就是你学成的那一版）；卡牌改：回响从哪里放（冲刺起点、书包、地面状态、残影）、回响什么（上一次第三段普攻、上一次冲刺）、回响几次 |
| 成型后 | 一套完整连招被“复述”一次，或者从不同位置交叉放出 |
| 反制 | 对手刚看过原招，知道回响的形状；幽影起手可读；硬控时回响作废 |
| 新增成长系统 | 无 |
| 复用 | `card_encore` 的自动重放（`auto_recast`）与 `拳里带招` 已经是“以 X% 效果再放一次某技能”的实现，护栏完整 |
| 扩展成本 | 最低：几乎没有新内容 |
| 主要风险 | 把最强技能的爆发在 0.5 s 内变成 1.6–1.7 倍，破坏可读伤害预算；L1 公平性 2.3×（护盾、工事构筑回响价值最高，重击最低）；回响冲刺、回响护盾的规则要单独定；技能顺序成为唯一的决策 |
| 证据 | L1；现有 `auto_recast`；外部：Sylas 用别人的大招（A），其设计取决于“有什么可偷”，没有强大招的对手打起来更舒服（B）——同理，回响的价值完全取决于你的技能组 |

**原创变体（不单列）**
- **劲兑现**：R 花光全部劲，按花掉的量放出构筑决定的载荷。与 M4 状态型劲成对；它把“攒还是花”变成核心决策。但满劲兑现的爆发与“以满劲进入战斗”（PO §7 Q9）直接相关，取决于劲研究的结论。
- **组件 R**：关键石定动词（砸、冲、守、放），卡牌加修饰（Noita / PoE 式）。组合空间最大；但关键石主导、组合爆炸、玩家难以预测，等价于 R2 + R4 的复杂叠加，不推荐作为首选。

## 5. 推荐与排序（AI 意见）

| 排序 | 方案 | 理由 | 反对意见 |
| --- | --- | --- | --- |
| 1 | **R4 引信（开局等于 R1，回响作为核心形态卡）** | 同一套规则从开局的“强化下一招”一路长到成型后的“连续引爆”；构筑改变的是 R 的种类而不只是大小；按口定预算可控公平；内容按口增长；AI 友好 | 按下无即时反馈；多口误触发；8 人混战颜色可读性；高潮感不如 R3 |
| 2 | **R5 回响（独立方案）** | 内容最省、最有原创性，自动承载技能分支的身份 | 爆发翻倍；公平性差；技能顺序成为唯一决策；冲刺、护盾回响的规则要另定 |
| 3 | **R3 爆气状态** | 高潮感最强，观赏性好 | 公平性最差；子句维护成本高；混战可读性差 |
| 4 | **R1 上劲（单独）** | 最保守，可作为 R4 的第一阶段直接上线 | 成型后没有成长，很快退化为倍率 |
| 5 | **R2 招牌大招** | 可读性和高潮感好 | 内容最重；关键石主导；构筑趋同 |

**为什么 R4 适合 Lockdown**
- **符合“简单操作、复杂构筑”**：按键永远只是 R，构筑决定按了以后“装到哪里”。玩家不需要学新按键，只需要理解“我的引信装在哪类动作上”。
- **与现有卡牌词汇天然对齐**：`basic_hit`、`combo3`、`dash`、`reaction`、`shield`、`ground`、`damaged` 已经是卡牌的分类，触发口就是它们的动作版本。
- **能承载 PO 列出的 R1–R4 全部意图**：
  - R1：只开技能口；
  - R4：多口；
  - R3：多发引信接近状态；
  - R5 回响：作为技能口的一种形态卡。
- **分阶段上线**：本批次先上 R1（只有技能口），B02 再逐步开口。

## 6. 对 R4 的逆向反证

| 质疑 | 分析 | 处理 |
| --- | --- | --- |
| “按 R 什么都没发生，不爽” | 成立。Karma 的强化在 Wild Rift 被移到被动，就是为了避免“空按钮”（A） | 按 R 时给即时反馈：角色起势动作 + 音效 + 引信环；可选给引信一个小的即时效果（例：0.5 s 内移速 +10%）。这个即时效果必须很小，否则变成第二个冲刺 |
| “我想用冲刺口进场，结果逃跑时冲刺把它用掉了” | 成立。“第一个符合的动作引爆”在多口时会误触发 | 规则：同一时刻只**开放一个口**——默认技能口，其余口由卡牌**替换**而不是叠加（K8）。少数“万能”卡允许双口；引信发数上限 3 |
| “8 人混战里看不清别人的引信颜色” | 部分成立。8 种口太多 | 只用 4 个颜色族（攻击 / 防御 / 机动 / 阵地）；装载与引爆各有一个音效；视野外不显示 |
| “开局的 R 就是爆劲换皮” | 开局确实等于现行爆劲的单技能强化，但输入从“长按”改为“先按 R”，Q/W/E 不再变 | 这是有意的平滑迁移：现行的元素载荷与 Y11 等卡牌可以先迁移到技能口 |
| “预算平均会让所有 R 一样无聊” | 预算平均的是**价值**，不是**种类**：攻速流的 R 是三拳，工事流的 R 是加固书包 | 预算按口设计；预算只作诊断，B02 的稀有卡牌可以在 Type3 / Type4 可读攻击上超出 |
| “R4 比 R3 弱在高潮感” | 成立。单发引信是“一下”，不是“一段” | 引信 +1 发的卡牌就是通往“连续引爆期”的路径；如果 PO 更看重高潮，可以选 R3 或在 R4 上限定一张传说卡开启“爆气”形态 |
| “触发口会产生递归” | 冲刺口 + `撞着就刷新`（冲刺立即刷新）可以连续冲刺；但引信一次只有一发，引爆后必须再按 R 并付劲 | K4：引爆动作带 `R` 标记，不再装填、不产劲；引信发数上限 3；R 本身有约 1 s 内置冷却 |

**淘汰的方向**

| 方向 | 原因 |
| --- | --- |
| R 由已装卡牌的词汇**自动推导**触发口（纯涌现） | 玩家无法预测引信会装在哪；换一张卡 R 就变，违反可读性；PoE / Noita 式的完全涌现适合单机，不适合 8 人 FFA 的对手视角 |
| R 自带击杀刷新或回劲 | 违反 K4 / K5 |
| R 的效果按劲当前值连续缩放（劲越多越强） | 让“攒满再用”成为唯一正解，并使 R 的强度对对手不可读（无法从画面判断它攒了多少）；只在“劲兑现”变体中以档位形式出现 |

## 7. 规则边界（PO §11，按推荐的 R4 写成一套内部一致的规则）

数值都是示意值，等方向批准后再研究。

| 问题 | 规则 | 理由 |
| --- | --- | --- |
| 是否需要劲门槛 | 需要：劲 ≥ 引信价格才能按 R（价格由劲 Session 定） | 劲是 R 的唯一入口（不加第二资源） |
| 何时扣费 | **引爆时扣**；过期或被打掉不扣；引爆瞬间劲已低于价格时引信哑火（无效果、不扣费、提示“劲不够”） | 按 R 不再是赌博；与 PoE2 Cast on Crit“满能量才触发”同理 |
| 独立冷却 | 引爆后约 1 s 内置冷却；被打掉后 3 s | 防连按刷载荷；被打掉的惩罚是时间，不是劲 |
| 劲不足时的反馈 | R 槽显示还差多少（数字或刻度），按下播放拒绝音效 | 零滚动 UI 原则 |
| 控制状态下 | 眩晕、击退、嘲讽时不能按 R；定身、沉默、缴械可以按（R 不是技能） | 硬控是反制 R 的主要手段，其余控制不额外惩罚 |
| 主动取消 | 再按一次 R 卸下引信（不扣费，进入 1 s 内置冷却） | 解决误触发担忧的一半 |
| 持续 | 一发引信最多约 6 s，未引爆则消失 | 防“永远上膛”的威慑；也防止开战前很久就装好 |
| 次数 | 默认 1 发；卡牌最多加到 3 发，每发独立引爆；**一次按 R 只付一次价**，引爆第一发时扣（见 §12） | 通往“连续引爆期”；劲上限 100，按发分别付费会让多发卡在劲-B 下买不起 |
| 死亡、阶段切换、休息室 | 死亡和阶段切换清空且不扣费；休息室可用，对训练假人练习（休息室满劲） | 可学习性 |
| 对手能否看到 | 能：装上时有起势动作、音效与颜色环（4 个颜色族）；引爆的攻击类载荷追加可读起手 | K2；Overwatch 大招语音（A） |
| R 能否被打断 | 硬控打掉已装好的引信（“泄劲”），不扣劲，对攻击方显示“泄劲” | 给控制构筑一个对 R 的专属回答 |
| 不同构筑的反制方式 | 攻击族：引爆的那一下按 Type4 处理——躲开、冲刺或硬控打断；普攻口的“劲拳”仍是 Type1（锁定），反制靠控距与换目标，所以它的单次载荷必须小；防御族：别打它，或用削盾（馊）、等它过期；机动族：盯住落点（落地震地为 Type3）；阵地族：Type5，远离或拆除放置物 | 反制种类随口而变，是构筑身份的一部分 |
| 多个改造叠加 | 每个口**只有一个形态卡**（K8，装备时拒绝第二张），修饰卡可叠加（数值相加，不相乘） | 防止乘法爆炸和规则冲突 |
| 冲突形态 | 装备规则在工坊里拒绝，并说明原因 | 运行时没有冲突 |
| 换牌、洗点 | 下次装填时生效；已装上的引信沿用快照 | 现行“前摇中的构筑变更取消该次攻击”的口径 |
| 递归与无限 | 引爆动作带 `R` 标记，不再装填引信，不产生劲，不触发 `auto_recast`、冷却返还、`takedown_reset` 等；单次引爆最多一条链 | K4，复用现有护栏 |

### 7.1 R 的可读性需求（交 S3b 的分级预警规范）

| 编号 | 需求 | 对应类别 |
| --- | --- | --- |
| RV1 | 引信装载：起势动作 + 专属音效 + 脚下颜色环，视野内所有人可见；视野外不提示 | — |
| RV2 | 颜色只用 4 个族（攻击 / 防御 / 机动 / 阵地），与元素色和席位色可区分 | — |
| RV3 | 引爆后的攻击载荷使用最高一级的预警（Type4）：追加约 0.15 s 起手，范围在起手时显示，与普通同招在形状上可区分（例如加边框或金色描边） | Type4 |
| RV4 | 引爆载荷如果把一招从 Type1/2 变成范围或延迟效果，按变化后的类别显示预警 | Type1/2 → Type3/5 |
| RV5 | 被硬控打掉（泄劲）有明确的反馈：对被打者和打的人都显示 | — |
| RV6 | 多发引信显示剩余发数（1–3 个点），零滚动、图标化 | — |

S3b 的攻击承诺研究如果定义了“收招”，R 引爆的 Type4 攻击应沿用同一规则，不单独定。

**与劲架构的接口**（对齐 `../momentum/` 的 M1–M4，由该 Session 定）：

劲账本（`../momentum/MOMENTUM_LEDGER.md` §3）中对 R 最关键的三条事实：
- 几乎每场新遭遇都从约 50 劲开始（打野存下的劲被脱战回落吃掉）。
- 真人按键被冷却拒绝的次数是被劲拒绝的 14 倍。
- 删除爆劲后，原生花费中有 5–20% 失去出口。

对 R 的含义：
- **R 的价格如果高于 50，R 就不能用来开战**。按 S5 的统计要等 2.4–3.1 s 才越过 60，而 TTK 中位只有 4.8–5.9 s。
- 所以要么价格 ≤ 进入遭遇时的典型劲量，要么劲 Session 调整回落目标。这是 R 的“开战 / 收尾”身份分界，属于 PO 级的选择。
- R 天然接上被释放的那份支出，不需要另造出口。

| 劲架构 | R4 的适配 | 风险 |
| --- | --- | --- |
| M1 共享消耗 | 可用。劲研究 L2 显示理性留劲时 R 主要落到支出低的构筑（护盾 95%、冲刺 34%、高频技能 45%）；高频施法构筑成型后的劲压力是风险，**原生没有证据**（原先引用的“平均劲 17–32”是持续施法上限工况，已被 S4 撤回）。扣费顺序见 §13.4 | 与“每种构筑都有 R”有张力 |
| M2 战斗积累（技能只看冷却，劲只给 R） | 最干净：R 频率 ≈ 交战时长的函数，可预期，对手能读“他快攒满了” | 劲收入的 40% 是交战被动，R 会变成计时器；需要提高“行为收入”的占比 |
| M3 混合 | 可用；需要明确哪类技能耗劲 | 规则复杂度上升 |
| M4 状态型 | R4 的载荷可以按引爆时的劲档位分级（低 / 中 / 高三档，不连续缩放） | 档位与颜色环叠加，需控制可读性 |

## 12. 与劲研究对齐（`../momentum/MOMENTUM_RESEARCH.md`）

劲研究推荐**劲-B「战斗热度」**：普通技能只看冷却，劲只喂 R 与构筑，脱战回落到低于 R 价格的基线。次选**劲-C「急速税」**：只有被急速加快的那部分施放付劲，进场约 50。
下面只写 R 侧的定位与规则调整；价格数值仍是示意值。

### 12.1 R 的定位随劲架构而变

| | 劲-B 战斗热度（首选） | 劲-C 急速税（次选） |
| --- | --- | --- |
| 进场劲 / R 价格（示意） | 低于价格（0–30）/ 50 | 约 50 / 50 |
| R 什么时候能按 | 交战中挣出来：元素 2.5 s – 冲刺 5.1 s（约 2 倍差距，L2） | 无急速构筑开场即可；高频技能流只有 45%（饱和 12%）的短交战能用到 |
| R 的身份 | **中盘 R**：交战展开后的转折点 | **开战 R**：第一下就可以是引爆 |
| 能否在迷雾里预装引信伏击 | 不能（脱战时劲低于价格） | 能（≥价格即可装，引信 6 s）；靠引信环在进入视野时可见来反制 |
| 对手的可读信号 | 对手的劲条：“他快满了” | 对手的引信环；劲条几乎总是可用 |

### 12.2 R4 引信在两种劲架构下的调整

- **劲-B**：
  - 扣费时机仍建议“引爆时扣”。由于装填前就必须劲 ≥ 价格，“按了没引爆”的情况只来自过期、被打掉或哑火，都不扣费。
  - **多发引信只付一次价**（§7 已改）。
  - **元素流的双重优势**：它拿 R 最快（反应回劲），反应口又是它的引爆口。反应口的载荷预算应低于其他口；或者由劲研究的“反应回劲单独封顶”解决。两者选一，不要叠加削弱。
  - **劲-E（挨打涨劲）下**：受击口和护盾口会出现“挨打 → 有 R → 再硬吃一下”的双重收益。这两个口的预算按“更常可用”下调。
  - **急速流**：去掉技能劲耗后施法次数可增加到 1.8 倍（L2）。技能口会被更频繁地自然引爆，但每次 R 仍只付一次价，所以 R 本身不放大急速问题。急速约束归 B02。
- **劲-C**：
  - R 是开战武器，**技能口的引爆载荷就是第一下的伏击伤害**。攻击类载荷必须走 Type4 可读起手（RV3），否则就是不可读的先手爆发。
  - 高急速技能流很少拿到 R。需要靠 `R价` 卡（例如由 `气短` 改来）补，否则它们没有 R 身份，与 PO 的“每种构筑都有 R”冲突。

### 12.3 R5 回响在两种劲架构下的调整

- 回响需要“这场交战里已经放过一招”，所以**在任何劲架构下回响都天然是中盘行为**：开战按 R 没有可回响的招，或只能回响很久之前的一招。建议规则：只回响 5 s 内放过的技能。
- 这让 R5 在劲-C 下也不会成为伏击武器，是它相对 R4 的一个优点。
- **劲-B 下**：去掉技能劲耗后，急速流的回响相对价值下降（它本来就常放技能）。重击、工事这类慢节奏构筑的回响价值相对上升，部分抵消 §3.6 中 R5 的公平性偏差。

### 12.4 组合建议（AI 意见）

| 组合 | 评价 |
| --- | --- |
| **R4 引信 + 劲-B** | **首选**。R 在交战中挣出、2 倍以内的可用时间差、按口定预算，两边都在压同一个公平问题。代价：R 不能用来开战；“他快满了”的计时器感由行为收入的占比缓解 |
| R4 + 劲-C | 可行。R 成为开战武器，需要严格的 Type4 可读起手和 `R价` 卡照顾急速流 |
| R5 回响 + 劲-B | 可行。回响的中盘属性与劲-B 一致，慢节奏构筑的回响价值相对上升；爆发翻倍的问题仍在 |
| R3 爆气 + 劲-D 档位 | 不推荐。两者都会把强势期集中给高收入流派（劲研究 §4 结论 6），叠加后差距最大 |
| 任何 R + 劲-A 共享钱包 | 不推荐（劲研究 §4 结论 1） |

**新增的 PO 级问题**：无，已并入 §11 的问题 3（R 用来开战还是收尾）。其答案与劲架构的选择是同一个决定的两面：选劲-B 就等于选“中盘 R”。

| 刷新 / 返还宿主冷却（`dash_contact_reset`、`takedown_reset`、`blast_reload` 对宿主自身） | 不计入 | 不计入 |
| `momentum`（产劲、偷劲、回劲） | 不计入 | 不计入 |
| 免费重放（`auto_recast`、`combo_cast`） | 照常产生派生施放，但派生不消耗引信、不继承载荷 | 不计入 |
| `kill`（击杀触发） | 计入击杀本身的牌效果，**不**触发任何与 R 相关的返还 | 不计入 |
| R 装填 | 不可能（R 标记的动作不能装填） | 不可能 |

### 13.4 各处理器的引爆机会（S5 要求 1 的补充，L1）

假设玩家在宿主冷却周期的任意时刻按 R，宿主一就绪就使用，引信在 6 s 内引爆的概率 ≈ min(1, 6 / 宿主冷却)：

| 处理器 | 宿主冷却 | 6 s 内引爆概率 |
| --- | --- | --- |
| 拳（本体） | 普攻 ≈ 1 s | ≈100% |
| 攻 / 守 / 阵（技能宿主） | 4.2–8.4 s | 71–100%（阵 78–100%；最长冷却的守类技能 71%） |
| 动（D） | 9 s（身手关键石 5.4 s） | 67%（100%） |

含义：
- 等预算不等于等价值。D 宿主的引信有约 1/3 等不到冲刺就绪。
- 结合 §13.2 的“过期也进冷却”，D 宿主的有效 R 频率最低。
- 构筑融合提出“冲刺印记让 D 立即就绪一次”来补偿；但这触及 M-07（不改变冲刺基础定位），属于 PO 问题。另一个补偿方式是给动处理器略高的载荷。
- 这些都是 L1 粗估，需要原型遥测（`LD_R` 的引爆 / 过期比例）。

### 13.5 外部证据改写（S5 要求 5）

**Wild Rift Karma：开局的 R 为什么不是空按钮。**

S5 的读法是对的：Riot 把“只强化下一招”从 R 键挪到被动，理由是 R 槽变成了空按钮，还有 Wild Rift 对局更短、移动端操作等因素。R4 开局就是这个形态。我的回答分三层：
1. **在 Karma 身上，强化占用的是唯一的大招槽**：玩家拿“强化”换掉了一个本可以是高潮技能的位置。Lockdown 的 R 不替换任何东西，是全员新增的第 5 个动作；与之比较的不是“一个更好的大招”，而是“没有 R”。
2. **宿主印记让开局 R 有一个立即可用的对象**：新手的默认印记在投入最深的宿主上。若是本体，按 R 后下一次普攻（约 1 s 内）就引爆三记重拳，按下到见效的距离与一个普通技能相当。只有印记在冷却中的技能上时，R 才会“等待”，这时 R 按钮显示宿主冷却。
3. **剩余风险不能靠论证消除**：“按 R 再按一个键”是否仍让人觉得空，只能靠原型验证。若原型显示空按钮感，后备方案是用同样 5 个处理器做 R3 式的短状态（“3 s 内宿主动作都按处理器结算一次”），不需要换系统。

**Battlerite Royale：FFA 中删除 EX 并取消 R 的能量消耗（A）。**

这是最接近 FFA 的一手先例，方向与“R 以劲为门”相反，应当作为对照组讨论：
- **Royale 删 EX 的原因**：EX 多是防御动作，在 Royale 里“没起作用”，由消耗品补位。R 去掉能量消耗后只看冷却。
- **它的前提 Lockdown 不具备**：Royale 有局内消耗品和装备稀有度承担构筑表达；Lockdown 的构筑表达在卡牌与宿主上，没有消耗品层。
- **对照组：“R 只看冷却、不用劲”**：
  - 优点：最简单，FFA 先例支持，也没有 §13.2 的扣费细节。
  - 代价：劲在劲-B 下就失去唯一职责。劲研究的结论是“劲需要一个新职责，R 是最自然的出口”，所以选这个对照组等于同时决定劲的去留（删除或另找职责）。
  - 这是一个 PO 级取舍，已并入 §11 问题 3（R 用来开战还是收尾 / 与劲的关系）。建议在决策单里作为 R 的价格选项之一出现：**劲价 / 冷却 / 两者**。

### 13.6 修订后的推荐（替代 §5 第 1 行的表述）

**R4 引信 + 宿主印记 + 5 个处理器 + §13.2 规则 + §13.3 口径**，配劲-B。

- 我认为它仍是最适合 Lockdown 的方向，但它的两个卖点都还没有证据：“构筑间公平”只是**可设计**，“开局就有意义”只是**有理由相信**。
- 提交 PO 时应如实标注；原型优先验证三件事：空按钮感、8 人同屏可读性、各处理器的引爆 / 过期比例。
