## A. 正式规则（已批准，直接实施）

### A1 地面落点预警从前摇开始下发（C-12）

**规则**：已学技能的施法动作处于前摇（`Body.Action` 已设、尚未释放）时，如果它的目标形式是 `GroundPoint`，并且当前形态含 `ground_impact`，服务器就把**它将要砸下的真实范围**作为观察事实发布，从前摇第一帧到结算。释放后由已有的地面效果接管，同一个观察键连续存在，画面上不出现“消失再出现”。

**受影响技能**（按当前内容；以“当前形态含 `ground_impact`”判定，不写技能名单）：

| 技能 / 形态 | 前摇 | 落地延迟 | 预警总时长（现 → 新） | 半径 / 内圈 |
| --- | --- | --- | --- | --- |
| S18 板砖糊脸（基础及 2A） | 0.25 | 0.55 | 0.55 → **0.80** | 200 / 80 |
| S18 2B 精准砖 | 0.25 | 0.55 | 0.55 → 0.80 | 120 / 120 |
| S08 2B 一锅端（`ground_impact delay=0`） | 0.25 | 0 | 0 → **0.25**（C2 原型另加延迟） | 240 / 240（3B2 内圈 80） |
| S18 2A 二砖、S08 3B1 再炸（`echo_impact`） | — | — | 不变：回声在首砸后才产生，已有现行预警 | — |

不包括：S19 陷阱（`contact_trap`，放置后常显）、S08 基础区域（`zone`，首跳是 T1，C-12 未覆盖）、N2/N4/N6 放置物。

**服务器改动点**

| # | 位置 | 改动 |
| --- | --- | --- |

| A1-4 | 打断 / 取消（`AbandonAction` → `FinishAction`） | 动作清空即不再发布，同一次采样内移除；不需要额外代码，但测试要覆盖 |

### A2 “你被锁定”只给目标本人（C-12）

**规则**：已学技能以**单位**为目标（`TargetDef.Mode == Unit`）且处于前摇时，只告诉被锁定的那个参赛者“你正被锁定”，并给出剩余时间。为了**不泄露迷雾**，只有在施法者本身已经出现在这位目标的当前观察帧中（单位句柄已授权）时才下发；施法者不可见时不提示。

- 受影响技能（按当前内容）：S01 滚远点（220，含 2A 拉 / 2B 踹）、S10 电你个哆嗦（650；3B2 900）。
- 不包括：普攻（锁定必中，太频繁）、野怪技能、S10 释放后的弹射（已经命中，不是“锁定”）。
- 迷雾选择说明：单位技能在准入与释放时都检查施法者到目标的视线（`ReleaseAbility` 的 `ClearSight`），但视野半径随高差在 75–125% 之间变化，所以“施法者看得到我、我看不到他”是可能的。本规格选**保守方案**（施法者不可见就不提示），完全满足“只用已授权信息”。如果 PO 希望在这种情况下也提示（只提示“被锁定”，不给方向），那是一项新的信息授权，需要单独批准。

## B. 需要 PO 批准数值的规则

### B1 可读起手（C-09：只给 T4 与长距离分支）

**机制（数值批准后实施）**
1. 内容：分支补丁目前只支持 `target / set / scale / add / remove / cooldown`（`Scripts/DemoContent.py` `_apply_patch`），**没有改前摇的补丁**；运行时已经按分支读前摇（`ActiveOf` 中 `Variant->WindupMs`）。需要在 `DemoContent.py` 与 `content.schema.json` 加一个 `windup` 补丁，然后走 Sync `--check`。不新增运行时字段。
2. 表现：可读起手要让对手**看得出这是重的版本**。在 `FLDObservedUnitView` 增加一个公开位“承诺起手”（内容标记，例如分支 `commit_tell: true`），客户端据此把通用 `CastAim` 换成方向线（V1）；对应 VI-1。没有这一位，加长的前摇只是延迟，不是“可读”。
3. 基础版技能、普攻、防御技能、基础冲刺**不变**（C-09）。

**推荐值**

| 技能 / 分支 | 现前摇 | 推荐 | 可选范围 | 依据（L1） |
| --- | --- | --- | --- | --- |

### B2 T4 未生效被打断 → 部分冷却（C-11）

**规则**
- 适用对象：带 T4 标记的技能形态，即 B1 表中获得可读起手的分支（S03 2A、S13 2B、S02 2B）。S17 2B 不适用：它的“重拳”是普攻，被打断时沿用现行规则（退还节拍）。将来 R 引爆的 T4 攻击沿用本规则。
- **“尚未生效”的判定点 = 释放时刻**：`Body.Action` 仍处于前摇、`ReleaseAbility` 尚未执行。现行代码里，劲耗与冷却都在 `ReleaseAbility` 中结算，未释放的动作被放弃时什么都不付，因此这个判定点与现有记账一致。释放之后（冲刺已经冲出、落点已经放下）被控，不追加任何惩罚。
- 触发原因：只看 `ELDCombatReject::ControlBlocked`（眩晕、击退、沉默、嘲讽打断前摇）。**主动取消**（移动、冲刺、S 键、换目标）保持免费——骗招本身是对手可以学习的读招内容；同时可以避免误触惩罚。
- 结算：`Track.ReadyAtMs = Now + 比例 × 该形态的冷却`。“该形态的冷却”是按当前急速计算的值，与释放时相同的公式。**不扣劲、不返劲、不给打断者任何奖励**（C-06、C-11）。
- HUD：技能格显示部分冷却；打断者看到对方技能进入冷却（已有冷却可见性规则不变）。

**改动点**：`AbandonAction`（或 `CommitControl` 中调用 `AbandonAction(…, ControlBlocked)` 之前）对符合条件的动作计算并写入 `Track.ReadyAtMs`；内容形态上增加只读标记（例如 `interrupt_cooldown_ratio`，只出现在 T4 形态上）。测试：`Lockdown.Rules.Combat.InterruptedCommitPartialCooldown`（控制打断 → 部分冷却，劲不变）、`Lockdown.Rules.Combat.CancelledCommitStaysFree`（主动取消 → 不进冷却）、`Lockdown.Rules.Combat.ReleasedCommitNoExtraCost`（释放后被控 → 不变）。

**推荐比例：50%**（可选 30–70%）
- 依据（L1 与设计判断）：上述分支的冷却是 6–6.3 s（未计急速），50% 相当于对手用一次控制换来约 3 s 的空窗，相当于半个技能循环——能感觉到，但比“白放一次”（100%，E3，挫败感高、控制流过强）轻。
- 30% 约 1.9 s，接近一次普攻节奏加一次走位，打断的意义偏弱；70% 接近完整冷却。
- 没有 L2 或原生证据；人能否在 0.30 s 的起手里命中打断，需要 L5。按 C-14，覆盖的分支进 B02，所以本比例在 B02 原型中验证；B01 只实现机制和标记。

## C. 隔离原型（Feature Flag，不进默认规则）

**开关约定**：沿用仓库现有的命令行开关形式（`FParse::Param(FCommandLine::Get(), TEXT("LD…"))`，如 `LDDevGrowthFixture`、`LDBuildEvaluation`）。
- **只在服务器读取一次**，在比赛开始时写入一行 `LD_PROTO flags=… params=…` 日志（BuildEvaluation / SummarizePlaytestLog 可以据此把样本分组）。
- 关闭时行为与正式规则完全一致：只增加分支，不修改正式路径。
- 原型参数只来自命令行，**不写入 `SourceData`**，不进内容哈希，因此不会出现“临时默认值”。
- 打包版默认不带开关；需要真人测试时，由 S0 用带参数的启动方式分发。

### C1 “急眼了”（C-10）

**开关**：`-LDProtoAgency`；参数 `-LDProtoAgencyCut=Immediate|NextControl`，以及下列数值参数（可省略时取下表“原型起点”）。

| 参数 | 原型起点 | 扫描范围 | 含义 |
| --- | --- | --- | --- |
| `Window` | 4.0 s | 3–5 s | 滑动窗口 |
| `Threshold` | 2.0 s（加权） | 1.6–2.6 s | 窗口内操作权损失累计达到即触发 |
| 权重 | 眩晕 / 击退位移 1.0；嘲讽 0.8；定身 0.5；沉默、缴械 0.2；减速 0 | 固定，原型中只观察 | 见 CONTROL_AND_PLAYER_AGENCY §6 |
| `Guard` | 1.0 s | 0.8–1.2 s | 急眼期：新的硬控不生效；击退照常位移但不锁输入 |
| `Cooldown` | 6 s | 5–8 s | 两次急眼的最短间隔 |
| 翻滚 | 同一链中第 3 次起的击退：照常位移，飞行中保留输入 | 第 3 / 第 4 次起 | “同一链” = 距上一次击退结束 < 2 s（与硬控递减窗口相同） |

**两种变体（必须二选一后才能审批正式规则）**

| 变体 | 触发时对正在生效的控制 | 预期 | 风险 |
| --- | --- | --- | --- |
| **V-Cut（立即截断）** | 当前所有眩晕、定身、嘲讽、沉默、缴械立即结束；正在进行的击退位移照完（物理不变），但从此刻起保留输入 | 与 L2 模型一致：最坏协同场景首次可逃 3.26 → 1.08 s | 控制方会觉得“我的控制被吃掉了”，需要清楚的表现 |
| **V-Next（从下一次起免疫）** | 当前控制照常结束；从触发起到 `Guard` 结束，新的硬控不生效 | 更温和；首次可逃取决于当前那段控制还剩多少（模型未覆盖，原型测） | 墙边长眩晕（0.8–0.9 s）期间触发时帮助有限 |

**实现位置**：受控者状态里加一个滑动计量与急眼截止时间。计量是纯函数，放在 `LDCombatControlRules`（与 `DiminishHardControl` 同处），方便规则测试；在 `CommitControl` 中先判断急眼期，再走递减；击退分支在“翻滚”条件下设置“保留输入”。表现：受控者身上一个明显的“急眼”状态（表情或动作即可，不加按键），HUD 计量为可选。日志：`LD_PROTO_AGENCY trigger t= victim= meter= cut=`。

**原型要回答的问题**
1. 正常的 2–3 段控制连招（单人控制流、开阔地击退流）是否**完全不会**触发急眼？
2. 墙边、多人、高急速时，受控者第一次能真正行动的时间缩短多少？
3. 两种变体哪种更可理解、控制方的挫败感更低？
4. 翻滚（保留输入的击退）是否让物理连招更好笑，而不是更难懂？
5. 真实对局中急眼的触发频率是多少？

**通过 / 失败判据**（原型结论，不是正式规则的数值目标）

| 判据 | 通过 | 失败 |
| --- | --- | --- |
| 单人标准连招触发率（探针脚本：扒裤子 → 冰可乐 → 滚远点；开阔地击退乒乓） | 0 次 | 任一次触发 |
| 三人围攻首轮控制保留（只量前三段控制时长） | ≥ 85% | < 75% |
| 墙边 + 3 人 + 急速 100 的首次可逃时刻（探针脚本） | ≤ 1.5 s | > 2.0 s |
| 7 AI 整局（Clean Baseline 构建）每条命的触发次数 | 中位 0，P90 ≤ 1 | 中位 ≥ 1（说明阈值太低，正常交战也在触发） |
| 真人（L5，至少 3 人 × 2 局，每种变体各一局） | 多数人能说出“刚才为什么挣脱了”；没有人把翻滚当成 Bug | 多数人看不懂，或认为控制失效 |

**需要的验证**：一个服务器端探针（复用 `LDDemoCombatProbe` 的风格，脚本化 3 名攻击者），用于测前两条与第三条，Host-only 即可；一次渲染运行看急眼与翻滚的表现（V-Cut、V-Next 各一段）；一次 7 AI 整局（无画面）统计触发频率；L5 真人局。机器预算由 S0 排（共用机器规则）。

### C2 S08 2B 一锅端：前摇显示落点 + 落地延迟（C-14）

- A1 上线后，2B 已经有 0.25 s 的前摇预警（正式规则）。本原型只增加**落地延迟**。
- **开关**：`-LDProtoPotDelay=<秒>`。服务器在加载内容快照后，只覆盖 `active_quick_meeting` 2B 形态（含 3B1、3B2）`ground_impact.delay`；不改基础版、2A，也不改其他技能。日志写明覆盖值。
- **原型起点 0.45 s**，扫描 0.35 / 0.45 / 0.55。起点与板砖同档：可读总时长 0.70 s，中位站位走出约 120 cm 只需约 0.5 s。
- 3B1“锅再炸”从首砸时刻起算，原型不改它的延迟。

**原型要回答的问题**
1. 延迟后，2B 是否还值得选（对站定、被定身、读条的目标仍然命中）？
2. 普通玩家看到锅圈时，能不能走出去？
3. 2B 是否因此形成了“控制 → 砸锅”的配合构筑？

**通过 / 失败判据**

| 判据 | 通过 | 失败 |
| --- | --- | --- |
| 对**被定身 / 眩晕**目标的命中（探针：先定身再施放） | 与现行（延迟 0）相同 | 下降（说明延迟太长，超过了控制时长） |
| 对**正在移动的 AI**的命中率（7 AI 整局或对决，构筑固定 2B） | 明显低于现行，且不为 0 | 与现行相同（预警无效），或接近 0（没人选） |
| 真人：被砸的一方能否说出“我没走出锅圈” | 多数能 | 多数人说“看不到”或“来不及” |

**需要的验证**：渲染运行，三档延迟各一段（与 A1 的渲染运行合并）；X1 循环构筑镜像加入 2B 变体（S5 清单）；L5 真人。

### C3 S18（说明）

按 C-12，S18 的前摇预警是**正式规则**（A1），落地延迟保持 0.55 s，不做原型。C-14 中“S18 进 B01 隔离原型”在这里落实为：A1 上线后，与 C2 共用同一次渲染运行与真人局，观察“普通玩家是否开始躲板砖”。不提出 0.40 s 延迟方案（L2 没有依据，见增补“反证后修订” #4）。
