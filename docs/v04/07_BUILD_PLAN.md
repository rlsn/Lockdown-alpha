# v0.4 implementation plan

## B40 Audit the Unreal baseline

Read the revision 4 master plan and this package, inspect the real v0.3 repository and run its prerequisite checks. Record engine version, completed and missing scaffold behavior, remaining parity gaps and source tuning. Preserve working native systems and keep necessary prerequisite repair separate from new scope.

Done when an actual build and ledger exist or the exact external blockers are recorded. Do not substitute the v0.3 documents for implementation evidence.

## B41 Add the character data and level state

Create the three class starts, six attributes, five-level thresholds, point currencies, derived values and private retained build state. Add class selection and Ready lobby, roster lock, new-generation reset and profile declaration.

Done when equal starting totals, deterministic point awards, HP and speed scaling, death retention and private replication pass. No fixed primary attribute or automatic per-class growth remains in the active profile.

Depends on B40.

## B42 Make one skill execution path

Wrap retained basic combat as the basic action, migrate dash to Step and assassination to Ambush, and add the remaining catalog actions. Add rank state, persistent cooldowns and unified slot validation. Remove old hotkey and context bypasses.

Done when a learned but unequipped skill fails through every ordinary entry point, combat and utility share four slots, and native movement and counterplay still work under delay.

Depends on B41.

## B43 Implement preparation books and branching

Add point allocation and rank spending, station commit, book purchase and reading, four-slot UI and level-four subclass choice. Keep books as real inventory instances and preserve knowledge independently.

Done when a Rogue can learn Spark, more than four known skills require an equip choice, failed commits spend nothing and death or swapping never clears cooldowns. Demonstrate two different builds from the same start.

Depends on B42.

## B44 Add world checks and the bounded roll

Implement the four Charter alternatives, source-specific scores, wallet capability, Pickpocket eligibility, one-draw receipt and stable retry windows. Add normal feedback without exact private difficulty leakage.

Done when deterministic alternatives work with suitable equipped builds, theft can succeed and fail through authority, duplicate and cancelled requests do not reroll, and NPC versus human identity is not exposed by target validation.

Depends on B43.

## B45 Build the connected progression region

Author one city, two towns, public and covered routes, preparation stations, book market, eight residents, trained NPC, real paid jobs, first visits, sentinel and real watchtower sabotage. Validate navigation, geometric sight and public-source invalidation.

Done when noncombat and combat XP are real and bounded, each class has a usable starting path to a Charter Witness, and the same rules load a second test topology without fixed district indices.

Depends on B44.

## B46 Close the peaceful acquisition loop

Implement actual Seal fabrication from four credits, 100 gold and Witness. Remove the normal seeded Seal. Retain the item theft/drop/pickup lifecycle and real Heart interruption. Mark full conquest, remote acquisition and other routes accurately deferred.

Done when a zero-kill contender wins under normal acquisition rules with the central gate still protected, and another contender can obtain an earned dropped Seal. No developer grant counts toward this demonstration.

Depends on B45.

## B47 Verify and deliver

Run helper, transaction, map, native network, privacy, packaging and reset checks. Test real costs and profiles. Measure progression and downtime with humans where available. Run the long technical soak separately and report overrides.

Done when the completed feature ledger and report distinguish actual passes, failures, fixtures, deferred ports and human validation still pending. Source-only work remains unverified if the engine cannot compile or run.

Depends on B46.

## Review boundary

v0.4 is a class-and-progression step, not permission to build the complete long-session RPG. Before expanding, review mixed loadout decisions, cross-class acquisition, combat scaling, peaceful completion, privacy and whether the region creates useful travel choices. Then prioritize remaining parity, robust resume and long-session pacing before a large world or new roster.
