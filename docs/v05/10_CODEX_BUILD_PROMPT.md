# v0.5 development request

Implement the UI/control sprint in this package on top of the delivered v0.4 Unreal project. Read master plan revision 5, this package, source decisions, the JSON companion, wireframes and ledger template. This is an implementation request, not a request for another plan or a static mockup.

The user reports v0.4 delivered. Inspect the actual revision, engine pin, current assets and evidence before changing it. Record actual deviations from historical specifications, preserve agreed tuning and working gameplay, and repair only necessary prerequisites. Do not assume the implementation is missing, upgrade Unreal or mandate a new ability/UI framework.

Replace default WASD movement with validated right-click native navigation and explicit camera controls. Left-click inspects. Right-click a neutral visible unit approaches its observed position without attacking or automatically following. A then click explicitly attacks. Q/W/E/R address the four equipped skills, 1–4 quick items and F contextual holds. Remove old normal-profile shortcuts and left-click attack. Implement mapping-driven labels, rebinding, conflict checks and input priority. A UI click must never issue a world command.

Prove native path following, prediction/corrections, order supersession, cancellation epochs, ramps, sprint, Step, focus loss and respawn on two independent clients before building the full UI. Keep one native movement authority and the retained geometry/timing. Do not teleport, introduce a second integrator or assume an AI SimpleMove helper gives correct remote player movement.

Build one coherent HUD: lower minimap and selected-subject inspector plus anchored own status/skill/item commands. Selection never changes the controlled subject. Other HP, build, rank, wallet and bag remain Unknown and are absent from unauthorized payloads. Clear selected dynamic data on sight loss. A tower or ward permits observation, not remote interaction. No decorative MP bar or new mana system is part of the proposed baseline.

Implement a real 24-slot carried bag with unique nonstacking instances and four quick references, replacing the separate four-book cap. Keep a one-Seal limit and actual finite supplies. Reordering preserves instance identity; consumption/transfer/drop clears references atomically. Books execute actual reading/learning, wards execute actual finite placement and Seal is not quick-usable. Provide click/button alternatives to drag and explicit safe drop confirmation. Preserve and document the actual death policy; adopt the proposed charge policy only as recorded.

Implement actual Guild catalog purchases and consensual peer exchange. Use invitations, eligibility/timeouts, at most six offered items per side, versioned edits, physical item reservations, both Ready and separate final Confirms. Gold remains stealable, not escrow-protected. Wallet changes invalidate approval. Final commit rechecks net capacity, final Seal count, balances, life, range, sight and exact offer, then transfers everything once or nothing. No partner full-bag/wallet/build leaks, unsolicited out-of-game messages, trade XP or craft-budget reset.

Keep current classes, attributes, shared skill slots, growth costs, cooldown identity, fog, NPC rules, reward budgets and earned Heart outcome. The normal profile remains short integration, not proof of full 60–90 minute pacing. Full conquest, new spells, equipment stats, stacks, full markets, squads and procedural/four-city expansion stay deferred.

Follow B50–B58 and U01–U56. Use shared native widgets, clear pending/blocked/result states, mapping-driven prompts, panel focus, text scaling and reflow at declared resolutions. Use wireframes as hierarchy references, then verify actual native screenshots. Focus loss, death and terminal state stop navigation, targeting, held work and trade; focus regain never replays them. Menus do not pause multiplayer.

Deliver real source/assets, deterministic bootstrap and launch steps, cooked Win64 game where toolchain permits, synchronized actual data, completed baseline/feature ledger and report, test logs, native screenshots, normal-rule demo and remaining work. Inspect restricted client data as well as visual output. Record real user tasks without invented participants. If tools or humans block required evidence, complete feasible work and mark the exact checks incomplete. Keep synced sources read-only.
