# Platform and migration

Unreal remains chosen, with native desktop, a3D world and controlled top-down view. Browser/io accessibility inspired the concept but is not the current runtime requirement. Keep the actual pinned engine and working source/assets. Do not mandate a GAS/UI-framework migration or reinterpret old web behavior as current release evidence.

Native movement/path following, ownership, life identity, restricted observation, input/UI and atomic transactions are foundations. Character stats, effects, MP, gear, item families and route state extend those foundations rather than creating parallel authorities. Walking/dash/push use validated native movement/collision; explicit teleport abilities validate endpoints separately.

The v0.7 audit records actual v0.6 commit/status, engine/toolchain, inherited class/economic skill/check formulas, supplies and test evidence. Required missing dependencies are completed honestly. Preserve compatible delivered features and normalize explicit changes at a clean match boundary. No live-match save conversion or production accounts/reconnect redesign required. Local preference migration cannot overwrite remapped keys silently.

Versioned JSON in the package is source design input, not Unreal assets or compile proof. Implement real saved definitions/assets through the installed engine, synchronize checksums and document adopted changes. A dedicated server target depends on actual compatible toolchain; report unsupported targets rather than claiming packaged verification. Production hosting, matchmaking and public deployment remain later work.

Prior prototypes/specs remain references. Real independently controlled native clients and server-side payload checks establish authority/privacy; listen-server alone and static UI pictures do not. Specifications and Python model checks remain separate from engine results.
