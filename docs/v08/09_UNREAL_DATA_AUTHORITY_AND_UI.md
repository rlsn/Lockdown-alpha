## Data model and import

All active JSON files use schema_version8, distances cm, time integer ms, rates per second, damage fixed-point hundredths with final receipt rounding down. Item Gold/stock/count uses checked integers; no floating-point currency. IDs stable snake_case except case-sensitive legacy material IDs Fiber/Ore/Crystal/Toolkit/Core. Requirements_any is OR of AND objects; [{}] means no gate. Missing numeric fields may not be invented from names. A JSON null active is genuinely nonactivatable. Book wrappers are generated per learned ability with weight1, Rank1 acquisition and drop policy; legacy wrappers remain distinct. No book wrapper for gear active.

Ability row retains v0.7 fields and adds domain, element, activation_kind, origin, reaction_eligible, acquisition. Effects define ordered ops. Direct hit marker must be explicit: frost tags on a surface/VFX do not qualify. Area_cm is radius except line where it is preview half-width mirrored in op; cones use explicit angle_deg. Unit, ground, line, cone, self_area, self_or_ground, observed_construct, owned_marker, two-unit/two-point and terrain-anchor requests are distinct tagged variants. self_or_ground for Thawing Touch uses either self feet or ground point and affects only cells, never a self unit status. Self_area excludes source from hostile damage/control but includes self for aid/barrier ops. Spell-block flag controls unit packets, not global immunity.

Retained rank mapping remains: damage→one designated amount/total_damage, barrier→pool, duration_ms→primary lifetime, cooldown_ms→cooldown, radius_cm→preview/emitter, anchor_hp→emitter HP, stun_ms→primary stun. New element_hit.damage maps only its amount; not Burning or surface DPS. conductive_bounce.damage maps each base amount60, not wet_bonus20. guard_aura_pulse.barrier maps amount100, no radius/lifetime. shatter_burst.damage maps80 raw burst, one per victim; no surface tick. Rank potency only for whitelisted potency_fields; +1 effective rank within3. New abilities' cooldown ranks reduce1000/2000 ms and no other field unless explicitly listed. Generic item active has no learned rank. Every modifier ID resolves to a precise modifier_contracts entry; retained scalar passives use07 glossary plus inherited v0.7 semantics.

Canonical tuning: data/*.json; generated06/07 tables mirror exact values. Normative rules in prose settle meaning. If prose/data/imported assets diverge, block release and reconcile. Use schemas/catalog.schema.json for structural checks, tools/check_spec.py for IDs/references/graphs/rules and reference boundary tests. These validate specification models only. Asset import must record payload hashes and prove actual server behavior separately.

## Authoritative records

ActionRequest = matchId, contenderId, lifeId, sequenceId, loadoutRevision, inventoryRevision, sourceKind[learned|gear|accessory|basic|world], sourceDefinitionId, optionalSourceInstanceId, targetVariant. Source category is derived server-side, never trusted to relabel an item as Silence-immune/Mute-immune. Old life/revision/sequence rejects; duplicate accepted sequence returns same result with no spend.

Loadout = six ActionRefs and eleven physical binding refs. ActionRef is Learned(abilityId) or Gear(instanceId, activeDefId); must be unique and source-equipped. Accessories are physical refs with optional own action, never independent inventory copies. Reserve/loadout commit uses inventory revision. Item instance stores definition, quality, owner/location, binding, cooldownReadyAt, procReadyAt, lineage, revision, reservation. Source unbinding invalidates dependent action atomically. No equipped-input craft/trade. A consumable has one identity consumed exactly once and binding cleared in that transaction.

Unit status has effectId, sourceCastId, sourceOwnerId, sourceLifeId, targetLifeId, start/end, magnitude, dispelCategory. Wet–FrostReadyAt is contender state, not a status instance; persist through death/rejoin. Field record adds budgetOwnerId to04 fields, separating resource sponsor from damage attribution. Before projectile commit reserve worst-case footprint cells and transition tokens, including pending reservations in owner64/match256 caps. At impact materialize actual cells and release unused tokens. Reflection keeps original budgetOwnerId for this paid reservation while changing effect attribution to reflector; no second budget spend or free capacity failure. Empty/blocked/missed field reservation releases once. Reflected field record remains charged to original budget owner until expiry. This prevents a paid reflection from exceeding capacity or silently losing its field.

If new fields overlap existing cells, reference-count allocations by budget owner and distinct cell; consume reservation only for genuinely added owner-cell records. A source replacement reassigns old allocation; never credit capacity twice. Creation/expiry/death cleanup is revisioned/idempotent. Environment simulation never edits inventory count except the original consumable action transaction.

Receipt = request/cast/transactionId, acceptedServerTime, originalSourceLife, resolvedVictimLife, spend/cooldown changes, damage components, status attempts/applied/suppressed, reaction lock endpoint, field revisions, attribution and authorized feedback. Internal audit can retain hidden details; client receipt is filtered. Do not expose exact hidden target HP, equipment, class, wallet or human-vs-NPC identity through hit reactions, trace counters, sounds or debug payloads.

## Tick ordering and deterministic conflict

For each scheduled100 ms environment boundary, expire due state first and advance native movement/contact crossings. Refresh Wet from existing contacts. Resolve due direct packets in server acceptance sequence; each packet's unit effects/reactions atomic. Then process surface commands by server sequence with one transition/cell; then derive contact Wet/slow/hazard ticks for newly written cells; apply combat/deaths; institutions/access; claim completions; deadline. Frost targeting a newly created Rain cell in the same batch sees it only if that Wet contact already existed before direct-packet phase; direct Water Jet before Frost applies unit Wet immediately and can combo that batch. UI tutorials should teach sequences with distinct visible impacts rather than rely on same-tick arrival. Never reorder at client timestamp.

If two fields compete for same cell use this order, not hash iteration. Exact lifetime end is expired before a later cast at that instant. Due direct CC at a claim completion timestamp takes precedence and cancels if applied. Direct damage alone cannot cancel surviving claim. Drain stalled server events in scheduled-time order; no catch-up loop that resets cooldowns/extends fields. All status/contact callbacks deduplicate with cast/life/tick IDs.

## Sight/UI

Native bottom bar shows six shared actions with a source badge for item-sourced action; four accessory cells show their active hotkey or passive icon. Equipment panel has seven body slots, separate four accessory bindings and24-instance bag. Source gear/removal warns which bar action will disappear. Own inspection shows primary-cap excess, exact active disabled reason, field mask, lifetime, costs and item cooldown. Inspecting another unit uses existing authorized Unknown/private view model; selection does not copy own detailed UI permissions onto target.

Wet/Frozen/Burning/Electrified/Steam have distinct world cues and own debuff labels. Wet icon says: direct Frost may briefly stun; Frozen ground only slows. Reaction lock may be shown to affected owner, never leaked as hidden enemy state. Casting Frost preview highlights only already visible water and static explored substrate, not unseen unit Wet. Ground casts do not enumerate hidden victims. Steam fog affects minimap/target handles as well as rendering. Spectator/debug full-grid replication is never sent to ordinary clients. Server unit-targeting rechecks geometry at release; local cached handle alone is insufficient.

## Mitigation and modifiers

New conditional damage reductions (Storm Crown/Insulated Leggings/Thermal Coat/Guardian Shield) are part of the same per-kind maximum60% total reduction with armor/MR. Example base MR15% plus conditional25% gives1−(1−.15)*(1−.25)=36.25%, capped60; it is not a new post-cap immunity layer. Storm/Insulation are strongest25%, never both. New movement bonuses sum capped20%; equipment negative movement sums independently; strongest slow<=60%; final speed clamped20..120% base. Sight total bonus<=50 cm, gear cast range strongest<=50 cm, no range bonus on Heart/service/gate pair distance or detectors. Aura modifiers are strongest per named family and require aid consent/geometry; no informal friendly filter.
